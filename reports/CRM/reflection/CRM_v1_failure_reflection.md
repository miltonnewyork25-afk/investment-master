# CRM v1.0 失败反思

> 2026-03-18 | 生态科技 Worktree | 全Phase在单日内完成(Phase -0.5 → Phase 4 v2.0)

## 一、结论先行：为什么失败

**根因不是质量差——密度指标实际上是35份报告中最好的之一(DM 2.40/千字, 因果11.68/万字)。根因是P1/P2的叙事方向被P3/P4彻底推翻，报告内部自相矛盾，无法组装成连贯文档。**

| | P1/P2 (未重写) | P3/P4 v2.0 (重写后) |
|--|---------------|-------------------|
| 核心叙事 | "CRM被标签系统性低估" | "市场的隐含假设可能接近正确" |
| 公允价值 | $227-235 | $176 |
| 期望回报 | +30-34% | +0.6% |
| 评级 | 关注(偏积极) | 中性关注 |
| CQ方向 | 5/5偏正面 | 2/5正面+1负面+2中性 |

这意味着Phase 5组装要么保留P1/P2(估值矛盾)，要么重写P1/P2(等于重做60%报告)。两条路都走不通。

## 二、五个失败因素

### F-1: 结论先行偏差 (致命)

P1从第一段就预设了"标签误读→低估"的叙事框架，CI-01"标签税"建立在"市场错了"的假设上。但P3红队发现市场隐含增速6.5-8.5%，而有机增速确实只有~7%——**市场其实是对的**。

如果P1一开始就用中性视角("市场定价了什么？这个定价合理吗？")，而不是bullish视角("市场错在哪里？")，P3的红队不会产出如此颠覆性的结论。

**教训**: Reverse DCF应该在P1 Ch1就完成并设定基调，而不是留到P2再做。先理解市场在赌什么，再判断市场对不对。

### F-2: 单日Rush (严重)

10个commit全部在2026-03-18完成。Tier 3设计为多会话(通常5-10个session)，原因是：
- 每个Phase之间需要"冷却期"让分析师(和AI)退一步审视方向
- 单日rush导致P1的bullish动量一路传导到P2，没有机会纠偏
- P3红队虽然有效(从$235打到$176)，但打击过猛——因为P1/P2偏得太远

**教训**: 即使AI可以单日产出166K字符，也不应该这样做。每个Phase之间至少间隔一个session，给出修正窗口。

### F-3: v1.0 → v2.0重写浪费 (中等)

- P3 v1.0仅19.3K(目标50K的39%)→铁律6"禁止骨架扩写"触发→必须v2.0重写
- P4 v1.0基于浅层P3→数字不可靠→也必须v2.0重写
- **浪费**: v1.0 P3(19.3K) + v1.0 P4(10.6K) = ~30K字符被丢弃
- **根因**: P3 v1.0就不应该被提交——19.3K不可能达到Phase 3的最低标准

**教训**: Phase完成后自检(铁律6的自审)必须严格执行。19.3K的P3不应通过任何门控。

### F-4: Checkpoint未更新 (轻微但致命后果)

checkpoint.yaml仍然记录v1.0数据($223/+27%/关注)。如果不同session基于checkpoint恢复，会拿到完全错误的基准。这是一个流程bug。

### F-5: ADBE经验迟到 (中等)

AIAS v2.0是专门为CRM准备的(ADBE实战修复后)，但ADBE对标直到P3 v2.0才首次出现。如果P0就做ADBE对标(两家增速几乎相同：12% vs 12%，PE接近：13x vs 15x)，P1就不会写出"标签系统性低估"的论点——因为ADBE的PE也低，但没人说ADBE被低估。

## 四、v2.0重做方案

### 方案A: 从P4结论反推(推荐)

1. **起点**: P4的结论($176/+0.6%/中性关注)是正确的→以此为锚
2. **P1重写**: 从"市场为什么恐惧CRM"改为"市场对CRM的定价隐含了什么假设？这些假设合理吗？"→中性视角
3. **P2重写**: 从$235估值改为用P4的校准参数(有机增速~7%/WACC 10%/AF溢价$22B)直接建模→DCF/SOTP从一开始就用正确参数
4. **P3简化**: P3 v2.0的红队发现已经回流到P4→新报告P3只需要验证少量残余偏差，不需要重做整个RT-1~RT-7
5. **P4简化**: 校准幅度会很小(因为P1/P2已经用了正确参数)

**优势**: 叙事一致(从P1到P4都基于同一组假设)，P3/P4轻量化(偏差小→校准少)
**风险**: 可能变成"先有结论再找证据"——需要P1真正中性评估，不是反向论证$176

### 方案B: 保留P1数据重写叙事

1. P1保留所有DM锚点和数据表，但重写连接文本(从bullish改为neutral)
2. P2完全重做(基于P4参数)
3. P3/P4直接用v2.0内容微调
4. **优势**: P1的111个DM锚点不浪费
5. **风险**: "缝合"痕迹可能明显

### 推荐: 方案A

因为P4的分析质量最高(离散度首次<30%，5方法独立校准)，且结论"中性关注/+0.6%"有充分支撑。从可信结论反推叙事，比从偏差叙事正向推导更诚实。

### v2.0关键纪律

1. **P0阶段就做Reverse DCF** — 先翻译"$175隐含了什么"，再决定叙事方向
2. **P0阶段就做ADBE对标** — 两家增速/PE几乎相同，这是最重要的外部锚点
3. **禁止单日rush** — 最少3个session (P0-P1 / P2-P3 / P4-P5)
4. **P1叙事门控** — P1完成后检查：叙事是否比Reverse DCF暗示的更偏向一方？如果是→修正
5. **checkpoint实时更新** — 每次估值结论变化都更新checkpoint.yaml
