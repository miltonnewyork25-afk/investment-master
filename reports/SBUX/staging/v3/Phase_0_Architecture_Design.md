## 三大缺失模块补强设计

### M2: 门店吞吐工程学 (新增Ch3子模块)
```yaml
核心字段:
  peak_orders_per_15min: 高峰吞吐量 [重新调研]
  avg_queue_time: 平均等待时间 [实地/财报]
  labor_productivity: 人效指标 [交易/小时/员工]
  mobile_order_penetration: MOP渗透率 [~30%]

一致性检验:
  吞吐改善 = 等待时间↓ + 人效↑ + 交易量↑
  改造投入 → 产能提升 → 销售增长 (闭环验证)

KS门控:
  条件: 改造投入连续2季未改善吞吐且等待时间不降
  动作: 下调OPM修复路径预期，产能约束假设成立
```

### M3: 定价力实证分析 (新增Ch5子模块)
```yaml
核心字段:
  menu_price_index: 菜单价格指数 [2020=100]
  promo_intensity: 促销强度 [折扣深度×频次]
  transaction_elasticity: 实际弹性系数 [重新计算]
  premium_vs_competitors: vs QSR溢价率

一致性检验:
  同店增长 = 交易量变化 + 客单价变化 (CSSPD验证)
  价格敏感性 vs 品牌忠诚度 (弹性区间测试)

KS门控:
  条件: 提价+交易量连续2季负+促销被迫加码
  动作: 定价力透支警告，下调长期margin上限
```

### M6: 会员增量贡献引擎 (升级Ch4)
```yaml
核心字段:
  active_90d_penetration: 90天活跃渗透率 [新增]
  member_frequency_premium: 会员频次vs非会员 [倍数]
  incremental_margin: 增量利润贡献 [vs获客成本]
  stored_value_utilization: 储值卡使用效率

一致性检验:
  会员增长 → 频次提升 → 销售增长 (传导验证)
  浮存金增长 vs 会员活跃度 (金融属性验证)

KS门控:
  条件: 活跃度或频次连续2季下滑+获客成本上升
  动作: 身份B估值权重降至下限区间
```
