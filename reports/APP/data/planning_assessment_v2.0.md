### 缺陷 #2: Agent Prompt缺乏操作细节 (致命, 预期+7分)

**问题**: Planning仅定义了Agent身份(identity/quality_bar), 但未给出per-Phase的具体prompt模板。RDDT的CQ置信度29.6%(历史最低)的根因就是"Agent prompt不够详细"。

**修复**: 每个Agent×Phase需要一个**Execution Prompt Template**, 包含:

```
## Agent {A/B/C} — Phase {N} Prompt 模板

### 任务目标
{一句话描述这个Agent在这个Phase要完成什么}

### 必须回答的问题
1. {具体问题1, 对应CQ编号}
2. {具体问题2}
...

### 必须使用的数据源
- MCP: {哪些工具}
- WebSearch: {哪些搜索词}
- 文献: {literature_map中哪些来源}

### 产出规格
- 字符: ≥{N}K
- DM锚点: ≥{N}个, 分类: {DM-XXX}
- Mermaid: ≥{N}个, 类型: {具体图表}
- 章节: 对应Chapter {N}

### 质量检查
- So What测试: 每个段落必须回答"这对投资论文意味着什么?"
- 特异性测试: 替换APP为Unity, 如果仍成立→太空泛→删除
- v13.0合同: 最低{N}K字符, 不达标→重跑
```

**预期效果**: GOOGL/PLTR的CQ置信度(~50%)来自于Agent知道自己要做什么。此修复直接影响CQ置信度从预期~30%提升到~50%。

### 缺陷 #3: 非共识洞察(CI)零预设 (重大, 预期+6分)

**问题**: CG12要求CI≥5, 但Planning中没有任何CI候选方向。进入执行后, Agent不知道要找什么。

**修复**: 预设5-7个CI假设方向:

| CI# | 假设 | 共识观点 | 非共识理由 | 需要的证据 |
|-----|------|---------|-----------|-----------|
| CI-1 | **APP的护城河不在AXON而在MAX** — AI可被追赶, 但中介层垄断不可复制 | 市场认为AXON AI是核心 | MAX 60%份额+SDK锁定+数据独占比任何AI模型更持久 | MAX替代品迁移率数据 |
| CI-2 | **电商扩展将因单位经济学而非技术而失败** — 30天LTV breakeven在大规模广告主中不可持续 | 市场认为技术是关键 | 电商复购周期远长于游戏, CAC回收期延长 | Wayfair/Dr. Squatch实际ROAS数据 |
| CI-3 | **SEC调查是买入信号而非卖出信号** — Google放宽fingerprinting=追溯合法化 | 市场恐慌SEC | 2025-02 Google政策变更使APP的数据实践从"违规"变为"合规" | Google政策原文+SEC调查范围 |
| CI-4 | **APP的DPO 360天是制度性优势, 不是风险** — 类似保险浮存金(Buffett), 是免费资本 | 分析师忽略现金流结构 | $1.5B+免息占用=ROIC超100%的关键驱动 | DPO趋势+开发者议价力分析 |
| CI-5 | **MAX-AXON捆绑将引发反垄断行动** — 类比Google AdX+AdSense双边控制 | 市场未定价监管风险 | EU DMA先例+DOJ对Google广告诉讼 | EU DMA合规要求+APP商业实践 |

### 缺陷 #4: 估值框架未操作化 (重大, 预期+6分)

**问题**: 仅说"Discovery System B型"但未定义:
- 哪些情景? 边界在哪?
- 用哪些方法? 每个方法的输入/输出?
- 方法离散度怎么计算?
- 条件估值范围怎么呈现?

**修复**: 定义3+1情景 + 5方法清单

**情景定义**:
| 情景 | 描述 | 概率权重 | 关键假设 |
|------|------|:------:|---------|
| S1 Bear | SEC处罚+电商失败+增速<20% | 20% | AXON数据源被限制, 电商客户流失>30% |
| S2 Base | 游戏稳增+电商缓慢扩展 | 45% | 游戏20-30% YoY, 电商$1-2B/yr by 2028 |
| S3 Bull | 电商爆发+CTV突破 | 25% | 电商$3B+ by 2027, CTV成为第三引擎 |
| S4 Moonshot | 成为全渠道广告OS | 10% | BofA $860论文成立, TAM $300B+ |

**5方法清单**:
1. **Reverse DCF** — 价格隐含增长率(核心, AI最强)
2. **可比公司** — APP vs META/TTD/GOOGL广告业务倍数
3. **SoTP** — 游戏广告Core + 电商Option + CTV Option
4. **DCF** — 3情景加权
5. **TAM Ceiling** — 即使成功的上限在哪?

**方法离散度**: 5方法最高/最低 = 预期3-8x (B型特征)

## 五、风险-收益权衡

### 框架复杂度悖论

**核心矛盾**: GOOGL用最简框架(9 Agent)产出最佳报告(453K), 而APP Planning用24 Agent + 3原创框架 — 复杂度是GOOGL的3倍。

**诚实评估**:
| 因素 | 支持高复杂度 | 支持低复杂度 |
|------|------------|------------|
| CQ数量 | APP有10个CQ(>GOOGL 6) | 10个太多, 不如8个深做 |
| 争议密度 | APP有4做空+SEC+Meta+增速减速 | 争议多≠需要更多Agent |
| 数据可用性 | AXON黑箱=数据有限 | 数据少→Agent多也没用 |
| Session数 | 6 session=更多context | 每session context有限=浅广 |

**建议**: 从24 Agent精简至**16-18 Agent**(含4 Supplement), 把省下的Agent配额转化为每个Agent更深的prompt。

| | v2.0 | 建议v3.0 | 理由 |
|--|:----:|:--------:|------|
| Phase 1 Agent | 3 | 3 | 保持 |
| Phase 2 Agent | 3 | 3 | 保持 |
| Phase 3+3.5 Agent | 3 | 3 | 保持 |
| Phase 4 Agent | 3 | 2 | RT-1~7可由1个Agent完成, 做空检验合并 |
| Phase 5 Agent | 3 | 2 | KS/TS/CQ可由2个Agent完成 |
| Session 6 Supplement | 4 | 4 | 保持(补强薄弱CQ) |
| **总计** | **24** | **21** | 少3个Agent, 每个Agent深度+20% |

### 500K是否现实?

| 因素 | 有利 | 不利 |
|------|------|------|
| 历史最高 | LRCX 470K | APP数据(AXON黑箱)不如LRCX(硬数据密集) |
| 可能性宽度 | PW=7→4-6分基准200K, 7-10分350K | 350K×1.5(Supplement)=525K合理 |
| Supplement | 4个×30K=120K | 需要Phase 5后发现薄弱CQ才能精准 |
| 电商/CTV | 大量外部文献可引用 | 一手数据有限 |

**诚实预期**: 主报告380-430K + 4 Supplement 100-120K = **480-550K**

## 八、结论

**当前Planning v2.0评分: 52/100 (良好低端)**

**修复至v3.0后预期评分: 84/100 (卓越)**

**一句话总结**: **APP的数据弹药是最充足的, 但缺少精确瞄准镜(章节蓝图+Agent prompt+情景定义)。装上瞄准镜后, 这是最有可能超越GOOGL的报告。**
