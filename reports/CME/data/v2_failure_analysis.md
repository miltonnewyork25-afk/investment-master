# CME v2.0 失败分析 + 系统修复方案
> 2026-03-18 | 失败类型: 体量严重不足(66K/300K = 22%)

## 失败数据

| Phase | 目标 | 实际 | 达成率 | 应阻断? |
|-------|------|------|--------|---------|
| Phase 1 | ≥80K | 32.7K | **41%** | ✅ 应在此阻断 |
| Phase 2 | ≥70K | 12.2K | **17%** | ✅ |
| Phase 3 | ≥50K | 9.2K | **18%** | ✅ |
| Phase 4 | ~15K | 5.3K | 35% | — |
| 合计 | ≥300K | 66K | **22%** | ✅ |

## 根因: 密度指标掩盖体量缺失

AI在每个Phase完成时报告:
- "DM密度4.7/千字(门控0.8 ✅, 超5.8倍)"
- "因果密度35.7/万字(目标5.0 ✅, 超7倍)"

这些数字让AI和用户都误以为质量过关。但**密度高+体量低=覆盖不足**:
- 27章平均2.4K/章 → 每章仅能覆盖1-2个论点
- v1.0: 182K/16章 = 11.4K/章 → 每章覆盖5-8个论点+数据+推理+反面
- v2.0目标: 300K/27章 = 11.1K/章 → 与v1.0持平但更多章节

**22%达成率意味着75%的分析维度被跳过** — 投资者基于此报告做决策将面临严重的信息不完整风险。

## 系统Bug: 执行循环缺少体量硬门控

```
当前执行循环:
  写Chapter → 检查DM密度 → 检查因果密度 → ✅ 通过 → 下一章
                                                    ↑ 没有检查字符数!

应该的执行循环:
  写Chapter → 检查字符数 vs 目标 → 未达80%? → ❌ BLOCK, 扩写到达标
                                   → 达标? → 检查密度 → 下一章
```

## 修复方案: 3层防御

### 修复1: 逐章字符硬门控 (最关键)

在chapter_plan中为每章定义min_chars。每章写完后:
```
if actual_chars < min_chars * 0.8:
    BLOCK — "Ch{N}字符{actual}K < 目标{min}K的80%, 禁止进入下一章"
```

### 修复2: Phase完成前累计校验

phase_complete.sh应增加:
```
phase_target=$(从checkpoint读取)
phase_actual=$(wc -m staging文件)
if phase_actual < phase_target * 0.7:
    BLOCK — "Phase {N} 字符{actual}K < 目标{target}K的70%, 禁止进入下一Phase"
```

### 修复3: 密度指标不能单独作为通过条件

修改AI执行规则:
```
旧规则: DM密度≥0.8 AND 因果密度≥5.0 → PASS
新规则: DM密度≥0.8 AND 因果密度≥5.0 AND 字符≥目标80% → PASS
        任一不满足 → BLOCK
```

## 对当前v2.0报告的处置

**66K报告不可发布**。两个选项:
1. **废弃重做**: 新会话从Phase 1开始, 每章强制≥8K, 每Phase校验字符
2. **保留骨架+逐章扩写**: 风险是铁律#6(骨架扩写), 但骨架质量(285 DM/因果链完整)高于v1.0骨架

建议选项1(废弃重做), 因为:
- 骨架扩写的历史教训: ADBE v1.0骨架70K→扩写271K=碎片化+30%填充→真实4.0非自评4.55
- 重做可以利用当前骨架作为outline(不是扩写, 是以outline为指导重写)
- 每章8-10K的连续写作比"2K+6K补丁"的一致性更好
