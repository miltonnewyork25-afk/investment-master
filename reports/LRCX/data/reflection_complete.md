## 六、教训提取 (Phase R6)

### 6a. 三个标准问题

**Top Technique: 温水煮青蛙24月量化路径**
- 描述: 将"周期性风险"从模糊概念转化为6个时间节点×4个维度的可追踪矩阵, 配有检测信号
- 可复用条件: 任何高P/E周期性公司面临均值回归风险时 (如半导体、SaaS成长股)
- 适用公司: 所有P/E>30x的周期性行业公司

**Top Lesson: 多Agent组装需要数值锚定协议**
- 根因(5 Whys):
  1. Ch25(-11.3%)和Ch29(-29.5%)不一致 → Why?
  2. P5_A和P5_C是独立Agent, 各自做了情景计算 → Why?
  3. Agent间没有共享"权威值注册表" → Why?
  4. 当前框架假设Phase内Agent产出互补而非互替 → Why?
  5. **根因: 框架缺少"跨Agent数值冲突检测"机制**
- 防止方案: Phase 5启动时建立"权威值表"(评级/期望回报/CQ), Agent A仅引用不计算, Agent C负责权威计算, Agent B无估值输出
- 机制: preflight_gate添加"跨Agent数值锚"检查项

**Top Mistake: Phase 5应禁止Agent A独立计算期望回报**
- 具体改变: P5_A(综合评级)应引用P5_C(估值闭环)的结果, 而非自行建模
- 预期提升: 消除Ch25 vs Ch29冲突, 减少组装修复40+处→0
- 性质: **系统性** — 任何多Agent Phase 5都会面临同样问题

### 6b. 递归深化三问

1. **深度问**: CSBG估值可再深一层。三方法给出$30-126B的巨大跨度, 关键争议在Reliant口径(80-84% vs 60-67%真实续约率)。如果获取LRCX Investor Day的CSBG segment详细数据, 可以将跨度收窄到$40-60B。
2. **方法问**: 缺少了**客户调研法** — 直接估算台积电/三星/Intel对LRCX服务的年度支出, 自下而上验证CSBG总量。这在半导体设备行业是可行的(客户集中度高, 3-5个客户占CSBG 60%+)。
3. **反思问**: 如果从零开始, 会将Phase 1精简50%(已有6份半导体报告的知识库可引用), 把节省的token投入CSBG独立深度分析(单独Phase 2.5)。CSBG是LRCX估值争议的核心——花30%篇幅在"常识性"的刻蚀市场背景上, 不如花在$30B vs $90B的争议解决上。
