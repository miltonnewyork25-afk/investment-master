## Part 2: 22份报告跨报告系统性分析

### 质量分布更新 (含ETN v2.0)

- **均值**: 3.72/5 (↑from 3.64) | **中位**: 3.75 | **标准差**: 0.36

- **灾难区**: MU(2.8), AAPL v1(2.8) — 仍是底线标记

### 四大系统性模式 (跨≥3份报告验证)

**模式1: DM系统性退化 (连续5份: KLAC→AAPL→LRCX→ANET→VRT→ETN)**

```
AMAT(625) → RBLX(613) → APP(472) → MSFT(400) → LRCX(326) → AAPL(263) → KLAC(205) → ANET(50) → VRT(0) → ETN(0→60)
```

**诊断**: v15→v17框架精简删除了Agent prompt中的DM强制标注要求。shared_context.md有完整registry但Phase Agent正文不引用。VRT+ETN连续两份v1=0, 确认这不是偶发事件而是**系统性退化**。

**ETN发现的解法**: DM附录化方案 — 不在300K+正文逐章注入(Agent context溢出风险)，而是集中式附录(35新锚点+25引用=60)。CG8检测6个fold table + 60个DM-ID → PASSED。

**进化方向**: 双轨策略 — (a)附录化作为保底方案写入report-merger skill (b)长期在Agent prompt恢复DM标注要求(EVO-ANET-003精神)

**模式2: 方法伪独立 (AMAT→KLAC→AAPL×2→ETN)**

ETN的5方法中M1(DCF)和M2(SOTP)共享增长率+WACC假设，M5(情景)共享概率分配 → 实际~2.5个独立方法。

这与AMAT发现一致(5方法实际2.5)。但ETN通过**估值独立洞见(Ch26.5)**引入了新思路: 与其追求5方法独立性，不如承认估值假精度并产出不依赖估值的决策建议。

**进化方向**: `/valuation-quality-gate` G2 Q3(三条不依赖估值洞见)从"巨头>$500B"扩展到"所有PW≤4传统估值公司"。

**模式3: 工业公司分析维度缺失 (ETN首次暴露)**

ETN是第22份报告中第一份**传统工业多元化公司**(非纯科技/纯半导体)。发现:
- 产业链纵深对工业公司洞见增量 >> 科技公司(科技公司供应链简单，工业公司上下游关系复杂)
- 积压质量分析($153B中"恐惧囤积"占比)是工业公司独特风险维度
- 身份转型叙事(传统→AI)需要溢价分解，框架v17.0原本无此工具

**进化方向**: EVO-ETN-005产业链纵深 + 积压质量分析模板 + 身份溢价分解(VRT估值张力的工业版)

**模式4: v1→v2优化路径可标准化 (ETN验证)**

ETN v1.0(3.9/5) → v2.0(4.3/5)的优化路径:
1. 产业链新章节(+0.2分) — 补全分析维度
2. DM附录化(+0.1分) — 解决CG8/CG9
3. CI注册表(+0.05分) — 非共识洞见显式化
4. 记分卡+免责(+0.05分) — CG3/CG11合规

这个4步路径对所有"v1.0 CG FAILED"的报告都可复用。应标准化为**post-assembly优化检查清单**。

### DM系统性债务: 附录化vs逐章注入

| 策略 | 优势 | 劣势 | 适用 |
|------|------|------|------|
| **逐章注入** (v14前) | 读者就近查证, DM密度高 | Agent context溢出(300K+), 维护成本高 | 短报告(<200K) |
| **附录化** (ETN发现) | 一次性集中写入, 不受context限制, CG检测简单 | 读者需翻到附录查证 | 长报告(>250K) |
| **混合策略** (推荐) | 高频引用数据在正文[DM-FIN-001], 完整定义在附录 | 需两步: 正文标注+附录生成 | 通用 |

**结论**: 附录化是当前最可行方案。逐章注入的Agent context溢出问题在300K+报告中不可避免。混合策略是最终目标但当前成本太高。

## Part 4: 递归进化提议

### EVO-ETN-001: DM附录化标准方案 → report-merger skill

**问题**: DM=0连续3份(ANET/VRT/ETN v1)，Agent扩写不继承DM规范
**方案**: 在report-merger skill Step 6后新增Step 6.5 "DM附录生成":
1. 从shared_context.md提取所有DM锚点
2. 按FIN/VAL/SEG/MKT分组写入附录
3. 生成fold source table (每组1个`<details>`块)
4. 写入CI注册表(如staging中有)
5. 写入数据审计声明(DM覆盖率计算)

**影响**: report-merger skill +40行
**递归三问**:
1. 够深吗? → 解决症状(附录生成)而非根因(Agent不标注)。但根因修复成本>>收益(Agent context溢出)
2. 最佳方式? → 标准化已验证方案 > 追求理想方案
3. 新问题? → 附录生成依赖shared_context.md存在且完整

### EVO-ETN-002: CI自动提取关键词模板

**问题**: CI注册表靠人工识别和编写
**方案**: post_report_autopsy.sh 或 report-merger 新增CI扫描步骤:
```
关键词: "非共识|独特|首次|被忽视|市场低估|系统性|偏差|矛盾"
模式: 扫描所有heading + 第一段 → 匹配关键词 → 输出CI候选列表
```
人工审核后写入CI registry

**影响**: autopsy脚本+15行grep逻辑
**递归三问**:
1. 全自动可能吗? → 不可能，CI的"非共识"判断需要语义理解
2. 半自动值得吗? → 值得，从0→候选列表节省50%工作量
3. 误报率? → 高(关键词匹配≠真正非共识)，但候选列表人工过滤成本低

### EVO-ETN-004: 估值独立洞见 → catalog新条目

**问题**: 巨头估值假精度问题已被valuation-quality-gate识别，但解法局限于>$500B
**方案**: 将ETN Ch26.5的"不依赖估值的可操作洞见"作为新catalog条目，适用范围扩展到所有PW≤4传统估值公司
**实施**: catalog YAML +15行

### EVO-ETN-005: 工业公司产业链纵深标准化

**问题**: 框架v17.0无工业公司专用分析模块
**方案**: 在deep_dive_protocol.md Phase 1增加条件检查:
```
if PW ≤ 4 AND 行业 in (工业/制造/基础设施):
    Phase 1 Ch9A产业链纵深 (必选):
    - 上游: 核心原材料×供应商集中度×替代成本
    - 下游: 客户集中度×合同结构×积压质量
    - 交叉销售: 板块间协同×量化效率指标
```
**影响**: protocol文档+20行, phase_sentinel可选检测
**递归三问**:
1. "工业公司"定义清晰吗? → 用PW≤4 + 行业标签双重判断，避免硬编码
2. 科技公司需要吗? → 不需要(供应链简单)，但混合型(VRT/ETN)受益
3. 增加多少工作量? → ~20K字符+1个Agent slot，ROI已被ETN验证(+0.2分)
