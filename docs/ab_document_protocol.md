# A/B 文档分离协议 v1.0

> **目的**: 将深度报告拆分为对外(A)和对内(B)两层, 实现品质分析与投资策略的合规分离
> **生效日期**: 2026-03-14 | **触发**: MSCI报告后的策略成熟度评估

---

## 一、文档定义

### 文档A: 深度研究报告 (对外发布)

**回答的问题**: 这家公司的商业模式有多好? 护城河在变深还是变浅?

| 维度 | 包含 | 不包含 |
|------|------|--------|
| 公司画像 | ✅ 行业定位/商业模式/竞争格局 | |
| 护城河分析 | ✅ C1-C6评分/趋势仪表盘/半衰期 | |
| 财务X光 | ✅ 5-10年趋势/利润结构/资本效率 | |
| 风险全景 | ✅ 风险拓扑/竞争威胁/监管 | |
| 品质评分 | ✅ A-Score/CQI/品质评分卡 | |
| 红队审查 | ✅ 承重墙/空头钢人/偏差审计 | |
| AI能力边界 | ✅ 深潜域/诚实域声明 | |
| **估值** | ⚠️ Reverse DCF("市场在赌什么") | ❌ 综合公允价值/目标价/期望回报 |
| **评级** | ❌ | ❌ 关注/审慎关注等评级 |
| **交易策略** | ❌ | ❌ 仓位建议/PE区间/入场纪律 |
| **Kill Switch** | ⚠️ 追踪信号(观察什么) | ❌ 触发动作(做什么) |

**关键原则**:
- Reverse DCF保留 — 它回答"市场在赌什么"(分析), 不是"应该值多少"(建议)
- 追踪信号保留 — 它告诉读者"关注什么变化", 不是"变化后怎么操作"
- 品质评分保留 — CQI是商业模式评估工具, 不是买卖信号

### 文档B: 入场纪律卡 (仅内部)

**回答的问题**: 这家公司现在该买吗? 在什么价格? 用什么仓位?

| 模块 | 内容 | 数据来源 |
|------|------|---------|
| **估值快照** | 公允价值/安全边际价/高估触发价 | 报告A Ch12-17 |
| **入场纪律** | PE三档/仓位结构/当前判断 | 报告A Ch34 |
| **等待期收益** | 股息+回购+增速/最坏年化/vs国债 | Moat Data Card v2.0 |
| **组合角色** | CQI/E-Score/Beta/回撤/相关性 | Moat Data Card v2.0 |
| **Kill Switch速查** | 12个KS/距离/紧迫度/协同 | 报告A Ch31 |
| **催化剂日历** | 验证事件时间表 | 报告A Ch37 |
| **温水煮青蛙防御** | 4道防线/年度审计规则 | 报告A Ch34 |
| **隐含赌注清单** | 赌注/置信度/验证方法 | 报告A Ch16 |
| **Moat Data Card** | 机器可读YAML(含v3.1新字段) | 自动生成 |

## 二、文件命名与存放

```
reports/{TICKER}/
├── {TICKER}_Complete_v{X}.md              ← 文档A (对外)
├── {TICKER}_Strategy_Card_INTERNAL.md     ← 文档B (仅内部)
└── data/
    ├── moat_datacard.yaml                 ← 机器可读数据
    ├── checkpoint.yaml
    └── cq_evolution.md
```

**命名规则**:
- 文档A: `{TICKER}_Complete_v{X}.md` (不变)
- 文档B: `{TICKER}_Strategy_Card_INTERNAL.md` (固定后缀`_INTERNAL`)
- `_INTERNAL`后缀 = 不可对外发布的标记

## 三、文档A的改造 (现有报告)

### 对现有Complete报告的处理

**已完成报告(35份)**: 不回溯修改。它们本身不含买卖建议(已有"报告不含"声明), 合规风险已低。

**新报告(MSCI起)**: 在研究契约(Protocol Header)中明确声明:

```markdown
| **报告包含** | 商业模式分析+护城河评估+风险全景+品质评分+Reverse DCF(市场隐含假设) |
| **报告不含** | 目标价+买卖建议+仓位建议+评级+入场时机+投资组合配置 |
```

### 需要从文档A中移除/调整的内容

| 章节 | 当前状态 | 调整方案 |
|------|---------|---------|
| 报告头部评级 | `评级: 关注(偏中性)` | 移除评级, 改为`品质定位: CQI 66/100, 前15%` |
| 报告头部期望回报 | `期望回报: +13.1%` | 移除 |
| Ch16 综合估值 | 公允价值$675/$606 | 保留Reverse DCF, 移除综合加权和期望回报 |
| Ch29.4 评级 | 评级决策树 | 移除评级, 保留核心论文矛盾(多头/空头) |
| Ch31 Kill Switch | 12个KS+动作 | 保留触发条件, 移除"动作"和"评级影响"列 |
| Ch34 交易策略 | 完整仓位建议 | 整章移至文档B |
| Ch37 事件日历 | 含"动作触发"列 | 保留事件和影响, 移除"动作"列 |

## 四、文档B的生成时机

### 自动生成

文档B在以下时机生成:
1. **Phase 5 Complete组装完成后** — 从Complete报告中提取数据, 生成Strategy Card
2. **不需要额外分析** — 所有数据已存在于Complete报告和Moat Data Card中

### 生成流程

```
Phase 5 Complete组装 → quality_gate_complete.sh → PASS
    ↓
从报告提取: Ch12-17估值 + Ch29评级 + Ch31 KS + Ch34策略
    ↓
从Moat Data Card提取: E-Score + Drawdown + Beta + Liquidity
    ↓
计算补充: 等待期收益 + 最坏年化 + vs基准
    ↓
生成: {TICKER}_Strategy_Card_INTERNAL.md
    ↓
从Complete报告中清理: 移除评级/目标价/仓位建议 → 对外版
```

## 六、跨公司汇总 (未来)

当积累≥8张Strategy Card后, 生成:

```
knowledge/strategy/
├── portfolio_universe.yaml       ← 所有策略卡的机器可读汇总
├── correlation_matrix.md         ← 跨公司相关性
├── entry_signals_dashboard.md    ← 当前哪些公司在安全边际价以下
└── annual_review_{YEAR}.md      ← 年度策略回顾
```

**组合构建的前提条件**:
1. ≥8张Strategy Card (不同行业)
2. ≥1年的Kill Switch追踪记录
3. 回测验证: 用CQI backtest数据检验入场纪律的历史表现
