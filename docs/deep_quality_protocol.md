# 深层质量协议 v1.0

> **诞生背景**: RBLX v1.2 SBC数据错误($2.65B→$1.13B)暴露了表面质量门控的盲区。
> 17项CG全部PASS的报告可能包含严重数据错误 — 因为CG只检测**过程合规**(锚点密度、字符数、Agent引用)，不检测**内容正确性**。

---

## 质量三层模型

| 层 | 检测什么 | 工具 | RBLX教训 |
|---|---------|------|---------|
| **L1 过程合规** | 锚点/字符/结构 | CG1-CG17 | 全部PASS但SBC错2.35× |
| **L2 数据硬约束** | 关键数字内部一致+外部可验证 | CG18 + 人工 | APIC $1.22B 即刻否决 $2.65B SBC |
| **L3 逻辑连贯** | 叙事逻辑与数据匹配 | 人工审读 | "23.1%为同业最高" 实际低于SNAP(35%) |

**核心洞察**: L1是自动化的(脚本可检)，L2部分自动化(约束检查)，L3只能靠人工审读。

## L2 数据硬约束 — 可脚本化规则

### 规则1: APIC硬约束 (SBC上限)

**原理**: 资产负债表的APIC(额外实收资本)变动 ≈ 当期SBC + 期权行权。SBC不可能大于APIC增量。

**检查流程**:
1. FMP拉取balance sheet → APIC(t) - APIC(t-1) = ΔAPIC
2. 报告中使用的SBC值 ≤ ΔAPIC (允许±10%容差)
3. 若SBC > ΔAPIC × 1.1 → **立即标红**

**RBLX实例**: APIC Δ = $1.22B, SBC应≤$1.34B, 但使用了$2.65B(MacroTrends含DevEx/创作者支付)。

### 规则2: 来源多数决 (≥3源交叉)

**原理**: 关键财务数字(Revenue/SBC/FCF/Operating Income)须从≥3个独立来源获取，取多数一致值。

**实施**:
- P0数据预取时，对SBC/FCF/Revenue至少查3个来源(10-K, FMP, Yahoo Finance)
- 若来源间差异>20%，以10-K为准并标注分歧

### 规则3: YoY合理性边界

**原理**: 单项财务指标YoY变化>100%或<-50%时，必须有明确解释(如并购/剥离/会计变更)。

**检查**: 报告中引用的YoY增长率若超出边界，搜索是否有解释性文字。

### 规则4: 内部数值一致性

**原理**: 同一指标在不同章节中引用的值必须一致(或有明确的场景标注区分)。

**CG18实施**: 报告内grep关键数值，检测是否有冲突值共存(排除场景分析/历史对比)。

## L3 逻辑连贯 — 人工检查清单

组装Complete后，人工审读以下5类逻辑陷阱:

| # | 陷阱 | 检查方法 | RBLX实例 |
|---|------|---------|---------|
| 1 | **比较反转** | 同行排序声明vs实际数据 | "SBC 23.1%为同业最高" 但SNAP 35% |
| 2 | **场景跳变** | FY(t)→FY(t+1)数值连续性 | FY25 23.1%→FY26 47.8%(原始sed残留) |
| 3 | **Track不一致** | 多Track估值引用vs实际计算 | Track B $8.0B(sed) vs $9.5B(重算) |
| 4 | **图表脱节** | Mermaid数据vs正文数据 | 柱状图 [54,48,42] vs 正文23.1% |
| 5 | **阈值失效** | 条件触发阈值vs当前值 | "SBC>45%触发" 但当前23.1%永不触发 |

## CG18 规范

**名称**: 财务数据交叉验证声明
**级别**: WARN
**检测方式**: 报告中是否存在交叉验证相关关键词(≥3次)
**关键词**: `交叉验证|cross-validation|APIC.*验证|多源验证|数据源对比|source.*reconciliation`
**通过条件**: 关键词出现≥3次
**失败提示**: 报告可能缺少关键财务数据的多源交叉验证

## 附: RBLX v1.2 错误传播路径

```
MacroTrends SBC $2.65B (含DevEx+创作者支付)
  → Phase 0 data-prefetch采信
    → P1 Agent C: Ch9 SBC/Revenue = 54.2%
      → P2 Agent B: Ch13 "同业最高" + 3个场景表
      → P2 Agent A: Ch10 Reverse DCF假设
      → P2 Agent C: Ch14 五方法Track B $5.2B
        → P3: 竞争比较 + 广告ARPU
        → P4: 红队用54.2%做对抗(确认而非否证)
          → P5: 五方法加权 + 评级
            → 240+处级联错误
```

**根因**: P0阶段单源采信，缺少APIC硬约束校验。
**教训**: 数据错误的检测窗口越早成本越低。P0错→每个后续Phase放大10×。
