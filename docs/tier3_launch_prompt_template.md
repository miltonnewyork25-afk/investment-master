# Tier 3 深度报告启动指令模板 v2.0
> 给用户的参考——每次开新报告时，用这个模板写启动指令
> **v2.0反思**: 4行启动指令不够——4.4+报告需要"启动+确认+全程参与"
> 核心原则: **告诉AI"回答什么问题"+ 要求AI"先回计划再动手"**

---

## 模板(三步握手)

### 第一步: 你的启动指令

```
深度调研 {TICKER}

核心问题: {一句话——这家公司最让你困惑/好奇的地方}

我的初步判断: {你倾向看多/看空/中性？为什么？别怕说错——说出来AI才能校准}

特别关注: {1-3个你最想搞清楚的点}

我知道的信息: {群聊/新闻/朋友圈信号——AI搜不到的}

可比公司: {你觉得最像的1-2家已分析过的公司——帮AI锚定框架}

质量目标: 4.4分 / ≥270K
```

### 第二步: 要求AI回一个执行计划(你确认后才开始)

```
在动手前，先给我:
1. 你理解的核心矛盾是什么(用一句话)
2. 你打算围绕哪3-5个CQ展开
3. Phase 1-3各重点写什么(不要面面俱到)
4. 你觉得最大的分析挑战是什么(哪里最容易出错)
5. 预计几个session完成

我确认后你再开始。不要直接开写。
```

**为什么这一步关键**: CRM v1.0失败就是因为AI直接开写→预设bullish→叙事断裂。
如果v1.0时AI先回一个计划，用户会发现"你的核心矛盾和Reverse DCF方向不一致"→提前纠正。

### 第三步: 你的全程参与(每Phase检查点)

| 时间点 | 你需要做的 | 花5分钟 |
|--------|----------|---------|
| **Phase 1完成后** | 读summary，检查核心问题是否被回答了 | "Ch3客户分析太浅了，补深" |
| **Phase 2估值后** | 检查Bull/Bear假设是否合理 | "Bear概率30%太高/太低" |
| **Phase 3圆桌后** | 检查是否有真正的碰撞洞见 | "洞见都是常识，不够深" |
| **Phase 4红队后** | 检查红队是否有效(vs表演性) | "RT-3太软了，HLT式+21pp调整" |
| **Phase 5组装后** | 快速扫读执行摘要 | "评级和估值数字不一致" |

**每个检查点你只需要花5分钟**——不是让你全程盯着，而是在关键节点给方向性反馈。
5分钟×5个检查点=25分钟的用户投入→可能是4.0分和4.4分的差距。

## 为什么每一行都重要

### 第1行: "深度调研 {TICKER}"
- 触发Tier 3流程(orchestrator自动启动tier3_launch.sh)
- **不需要写**: "请用以下skills分析..." → orchestrator会自动调度23个skill
- **不需要写**: "请按Phase 0-5执行..." → CLAUDE.md已定义流程

### 第2行: "核心问题"——**这是高分的关键**
这一行决定了报告是"围绕问题展开"还是"围绕框架填空"。

**好的核心问题**(从高分报告提炼):

| 类型 | 示例 | 驱动什么 |
|------|------|---------|
| **身份争议** | "DDOG是监控工具还是AI数据平台？" | Phase 1围绕身份分叉组织 |
| **估值矛盾** | "CME CQI 93但PE 28x——好公司为什么不是好股票？" | 直接进入估值核心 |
| **市场定价** | "LULU PE 12x，市场在赌品牌已死还是暂时受伤？" | Reverse DCF锚定方向 |
| **战略转折** | "INTU从报税工具→金融操作系统，转型真的在发生吗？" | 证据链围绕转型进展 |
| **竞争格局** | "Siemens在蚕食PTC的PLM——速度有多快？" | 竞争分析成为核心章节 |
| **AI影响** | "AI对CRM是飞轮加速器还是seat蚕食器？" | 触发/ai-impact深度分析 |

**差的核心问题**:
- "帮我分析AAPL" → 太泛，AI会面面俱到但每个都浅
- "NVDA值多少钱？" → 跳过了理解业务直接估值
- "这家公司好不好？" → 没有方向性

### 第3行: "我的初步判断"——**防止AI猜你想听什么**

如果你不说，AI会默认中性——但可能不是你需要的。

```
好: "我初步觉得偏低估(PE 12x太低了)，但不确定品牌是否真的在衰退"
   → AI知道: 用户倾向看多但有顾虑→红队需要特别攻击"品牌衰退"假设

坏: (不写)
   → AI猜测: 用户可能看多也可能看空→两边都写一点→没有深度
```

CRM v1.0教训: AI猜测用户bullish→预设$235→Phase 4发现市场是对的→叙事断裂。
CRM v2.0成功: 用户明确说"我不确定"→AI从Reverse DCF中性起点→结论自然浮现。

### 第4行: "特别关注"——**你的信息优势在这里**

AI能搜到所有公开信息，但**你知道哪些问题最重要**。

```
好: "特别关注: (1)ServiceMax churn是否结构性 (2)Onshape能不能进大企业 (3)AI对PLM的影响"
   → AI会把30%篇幅放在这3个问题上，而不是均匀分配

坏: "请全面分析"
   → AI均匀分配→每个维度4K→没有一个深入
```

### 第5行: "我知道的信息"——**AI搜不到的信号**

这是你最大的信息优势——来自群聊/朋友圈/行业会议的非公开信号。

```
好: "我在群里看到有人说DDOG的客户在考虑从Elastic迁移，因为AI日志分析更好"
   → AI会在竞争格局章节验证这个信号(WebSearch+FMP)

好: "最近龙虾群讨论很多关于GLP-1对医疗保险MCR的影响"
   → AI会深挖GLP-1对UNH的量化影响

坏: (不写)
   → AI只用公开信息→错过你已经知道的市场情绪
```

### 第6行: "质量目标"

```
4.4分 / ≥270K → Tier 3标准(默认)
4.0分 / ≥150K → 可接受的快速深度
"密度优先" → 允许更短但每段必须有独立论点
```

## 完整示例

### 示例1: DDOG(实际使用的，4.3分)
```
深度调研DDOG

核心问题: DDOG是"监控工具卖license"还是"AI可观测性平台卖数据洞察"？
身份不同估值框架完全不同——前者值15x ARR，后者可能值25x+。

我的初步判断: 偏积极。15T+日数据点的数据护城河被低估了，
但不确定AI产品能否从"功能"变成"收入"。

特别关注:
1. BITS AI产品的付费转化率(很多AI功能还是免费的)
2. 和Elastic/Splunk的竞争——迁移方向是进还是出？
3. 消费模式(usage-based)在宏观下行时的脆弱性

我知道的信息: 群里有SRE工程师说他们团队在评估从New Relic迁到DDOG，
主要原因是AI日志分析准确率更高。

质量目标: 4.4分 / ≥270K
```

### 示例2: BKNG(实际可用)
```
深度调研BKNG

核心问题: ROIC 51%+$65B回购的完美机器，
为什么PE只有20x(vs ABNB 35x)？市场在担心什么？

我的初步判断: 中性偏积极。感觉是被"旅游周期股"标签压低了，
但不确定OTA模式在AI时代是否被颠覆(Google Travel/AI Trip Planner)。

特别关注:
1. Google Travel的直接预订渗透率——正在绕过OTA吗？
2. Alternative accommodation vs Hotels的mix shift
3. 欧洲监管(DMA)对BKNG的影响

质量目标: 4.4分 / ≥270K
```

### 示例3: 最简版(仍然有效)
```
深度调研FTNT

核心问题: 自研ASIC芯片在网络安全行业是真护城河还是过度投入？
```

即使只有2行，核心问题的存在就足够让AI围绕它组织分析——比10行无方向的指令更有效。

## 反模式(不要这样写)

```
❌ "请用orchestrator skill启动分析，先运行data-prefetch收集数据，
   然后用moat-evaluator做44因子评分，接着用financial-analysis-framework
   做6维度财务分析，估值用3种方法+Python验证..."

为什么差: 你在做AI应该做的工作(调度)。写这些不会让报告更好——
反而占用了你本应用来思考核心问题的时间。
```

```
❌ "全面分析这家公司的业务模型、竞争格局、财务状况、
   护城河深度、估值水平、管理层质量、风险因素..."

为什么差: 面面俱到=没有重点。AI会每个维度写4K字，
没有一个深入。核心问题的缺失=报告没有灵魂。
```
