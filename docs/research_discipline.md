# 研究纪律与边界规则 v22.1

> **目的**: 防止把能力浪费在低价值、低证据、低解释力的内容上。
> **设计原则**: 反面定义优于正面描述 | 具体数字替代模糊形容词 | 因果解释促进泛化
> **来源**: Claude Code 6种行为引导模式 + 40+份报告实战教训

---

## 1. 深度优先，覆盖服从于解释力

不要为了"看起来全面"而平均覆盖所有角度。不要为了"模板完整"而在低解释力维度上扩写。

如果某个问题解释力显著更高: 给它更多篇幅 + 更强证据链 + 允许前置 + 允许重排报告结构。
如果某个角度解释力很低: 即使属于标准框架也简写至≤500字，不强行展开。

**规则**: 宁可少写3个低解释力角度，也不要浅写1个高解释力角度。
**因果**: 平均分配篇幅会把最重要的洞察埋在冗余中，投资者在前5分钟读不到决策依据就会放弃。

---

## 2. 不要为了token节省而跳过承重墙

**NEVER**以下内容浅尝辄止，除非数据确实不可得（此时标注"数据不可得"而非硬写）:
- 当前股价到底在买什么（Reverse DCF隐含假设）
- 公司最关键的承重墙变量（≥1个，附证据链）
- 预期差最可能出现的层（护城河/增长/估值三维）
- Kill Switch（≥3个可量化信号+触发阈值）

token不足时的砍除优先级（从先砍到最后砍）:
1. 背景介绍和公司历史流水账
2. 低解释力的行业常识
3. 与结论无关的泛泛比较
4. ~~承重墙分析~~（**NEVER砍**）
5. ~~Kill Switch~~（**NEVER砍**）

**规则**: token不足时先砍背景，不砍主线。
**因果**: 承重墙缺失的报告无法支持投资决策，等于无效输出。背景缺失只影响阅读体验。

---

## 3. 禁止为覆盖而编造"像样的结论"

**NEVER**在以下情况下生成看似确定的判断:
- 没有≥1个硬数据支撑
- 推断链超过3步且未经交叉验证
- 关键假设依赖单一来源
- 行业数据口径冲突未解决

**允许停在**: "不知道" / "暂时无法判断" / "证据不足" / "只能做弱推断" / "置信度低"

**NEVER**因为以下原因硬写:
- 想让报告完整（**假完整比不完整更危险**）
- 想把模板写满（**模板是底盘不是目标**）
- 想显得聪明（**研究服务决策不服务表演**）

**规则**: 没有证据链时，宁可留空白，不要用流畅文字掩盖无依据判断。
**因果**: 投资者基于虚假确定性做的决策，比基于诚实不确定性做的决策，亏损风险高10倍。

---

## 4. 所有重要判断必须标注结论强度

| 级别 | 标记 | 定义 | 使用规则 |
|------|------|------|---------|
| **硬结论** | `[A]` | 有明确、可靠、可复核数据支撑 | 直接进入主论证 |
| **弱结论** | `[B]` | 有合理证据链但依赖≥1步推断 | 可用，必须写明推断链与证伪条件 |
| **猜测** | `[C]` | 启发式判断，证据不足 | 仅作为待验证线索，**NEVER**进入主结论 |

**NEVER**把弱结论写成硬结论。**NEVER**把猜测写成事实。
**因果**: 结论强度标注让投资者知道哪些判断值得下注，哪些只是线索。模糊化强度等于隐藏风险。

---

## 5. 主线问题必须胜过模板完整性

如果已发现比标准模块更重要的高解释力问题，不要因为还没"把模板走完"就压后。

**判断标准**: 如果某个问题满足以下≥3条 → 升级为主线:
1. 比标准模块更能解释股价
2. 比标准模块更能解释市场分歧
3. 更能解释未来3年价值变化
4. 同时连接护城河、增长、估值三维
5. 会显著改变最终评级
6. 具有明显非共识性
7. 能直接生成Kill Switch

一旦升级: 允许前置 / 单独成章 / 重排结构 / 新增模块。
**规则**: 模板是底盘，主线问题才是驾驶方向。

---

## 6. 逼近"决定性矛盾"

不要写百科全书。始终逼近最关键的矛盾。

**数值锚定**（替代"聚焦"等模糊描述）:
- 如果只能保留**3个**问题，应该是哪3个?
- 如果只能保留**1个**承重墙，应该是哪1个?
- 如果只能跟踪**5个**指标，应该是哪5个?
- 报告执行摘要应在**≤800字**内回答L0四个最高目标

**规则**: 你不是在写百科，你是在逼近决定性矛盾。

---

## 7. 背景只有在服务结论时才有价值

不要把"公司分析"写成"行业常识整理"。

**NEVER**扩写以下内容，除非它直接服务于解释股价/赚钱逻辑/市场分歧/结论证伪:
- 公司历史沿革（≤200字概述即可）
- 管理层履历（只写与当前thesis相关的部分）
- 产品线完整介绍（只写影响估值的产品）
- 行业规模和增速（只写与公司份额相关的部分）

**规则**: 不能服务上述目标的段落，默认压缩或删除。
**因果**: 背景的唯一价值是帮助读者理解结论。独立的背景描述 = 噪音。

---

## 8. 篇幅跟随解释力，不跟随模板标题

不要机械均匀分配。不同公司真正重要的部分不同。

**具体例子**（避免抽象泛论）:
- 对ASML: 地缘chokepoint风险 > 普通财务描述（M11稀缺vs政策折价）
- 对APP: 算法闭环moat > 业务介绍（M10模型效果vs护城河）
- 对COST: 安全边际消失风险 > "公司好不好"的证明（M12质量溢价消失）
- 对CRM: 飞轮悖论（Agent蚕食seat）> 传统SaaS指标（M2身份协同/冲突）

**规则**: 篇幅跟随解释力，不跟随模板标题。

---

## 9. 允许"不完整"，但不允许"假完整"

当发现以下情况时**必须**主动承认（不要绕过或模糊化）:
- 数据口径冲突（标注哪些口径在冲突）
- 行业数据不可验证（标注来源和可信度）
- 管理层说法无法独立验证（标注"管理层声称"而非当作事实）
- 关键变量仍属黑箱（标注认知边界）
- 推断依赖过多外推（标注外推步数和每步风险）

**规则**: 诚实的不完整，优于虚假的完整。
**因果**: 承认不知道的投资者可以等待确认信号；被虚假确定性误导的投资者会提前下注然后亏损。

---

## 10. 完成前验证门控 + 反自欺检查

> **借鉴**: Superpowers "Verification Before Completion" — "Evidence before claims, always. 声称完成而未运行验证=不诚实，不是高效。"

### 10a. 五步验证门控（Phase完成/报告提交前强制）

在做任何"完成"声称前，必须:
1. **识别**: 什么验证命令能证明你的断言?（phase_sentinel/quality_gate/wc -m）
2. **执行**: 完整运行验证命令，不依赖上次结果
3. **阅读**: 读取全部输出，注意exit code和失败项
4. **核实**: 结果是否**真正**支持你的声称?
5. **声称**: 只有完成1-4后才能说"Phase X完成"或"报告达标"

**以下不算验证证据**:
| 不算 | 原因 |
|------|------|
| "上次跑过了" | 状态可能已变 |
| "应该没问题" | "应该"是红旗词 |
| "DM密度够了" (未运行grep计数) | 感觉≠证据 |
| "因果密度合格" (未运行脚本) | 必须执行验证命令 |

### 10b. 反自欺六项检查（≤60秒）

**阶段1（诊断）** — 快速检查:
1. 有没有因为想显得全面，而稀释了最重要的问题?
2. 有没有为了省篇幅，而跳过了承重墙?
3. 有没有把弱推断[B]写得像硬事实[A]?
4. 有没有为了把模板写满，补上没有证据链的结论?
5. 如果用户只看3段，最重要的3段是否足够说明问题?
6. 主线问题是否真正被前置和突出?

**阶段2（调整）** — 任一答案为"是" → 先修改对应问题，不盲目重写全文
**阶段3（求助）** — 修改后仍不满意 → 标注问题，请求用户反馈

### 10c. 三次失败升级规则

> **借鉴**: Superpowers Systematic Debugging — "三次修复尝试失败 → 停下来质疑架构，不要继续试错。"

**在投研中的映射**:
- 如果同一个分析方向尝试3次仍无法形成有证据链的结论 → **停止**
- 不要继续沿同一路径深挖（沉没成本谬误）
- 升级为: "这个问题可能需要不同的分析框架/数据源/视角"
- 记录在handoff note中: "方向X已尝试3次未果，建议切换"

**NEVER**跳过10a门控直接声称完成。**NEVER**在10b发现问题后不修改直接输出。**NEVER**在同一死胡同里超过3次尝试。

## 11. 研究服务决策，不服务表演

写的每一段都应至少服务以下之一:
- 澄清市场在买什么（L0目标1）
- 澄清关键变量是什么（L0目标2，护城河/增长/估值三维）
- 澄清市场最可能错看哪里（L0目标3）
- 澄清当前是不是好赔率（三维状态判断）
- 澄清以后该跟踪什么（Kill Switch + 监控清单）

**NEVER**写以下内容:
- 与上述5个目标无关的"有趣但无用"的信息
- 重复已说过的结论（用不同措辞再说一遍≠深化分析）
- 为了显示"广度"而加入的低解释力段落

**规则**: 研究服务决策，不服务表演。
**因果**: 投资者的时间是有限资源。每段噪音都在稀释信号，降低报告的决策价值。

---

## 跨规则设计原则（元规则）

> 以下5条原则指导了上述11条规则的措辞和结构设计。

1. **反面定义优于正面描述** — "NEVER做X"的边界比"做Y"清晰。11条规则中9条使用否定形式。
2. **具体数字替代模糊形容词** — "≤800字""3个问题""5个指标"替代"简洁""聚焦""精选"。
3. **因果解释促进泛化** — 每条规则附"因果"说明，让AI在新场景中推导规则精神，而非机械遵循字面。
4. **冗余是刻意的** — CLAUDE.md和本文档中的核心规则有意重复，对抗注意力衰减。
5. **具体例子是抽象规则的校准器** — 每条规则配具体公司案例，帮助映射到实际分析场景。
