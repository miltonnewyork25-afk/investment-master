   - **≤-1.5 (极冷)**: 建议Tier 3深度研究，重点机会

10. **SGI速判 (v17.3新增)** — 2分钟专才/通才定位，影响后续分析策略
   - **计算公式**: `SGI = 0.30×HHI_rev + 0.25×R&D_conc + 0.20×MarketPos + 0.15×SwitchCost + 0.10×BrandClarity`
   - **五维度快速评分** (各0-10分):
     - HHI_rev: Top-1品类收入占比 (>90%=10分, 均分10+品类=0分)
     - R&D_conc: 核心品类R&D集中度 (>90%=10分, <30%=0分)
     - MarketPos: 核心品类市场份额 (>60%=10分, <10%=0分)
     - SwitchCost: 客户锁定强度 (切换成本>5年合同=10分, 轻松切换=0分)
     - BrandClarity: 一句话能否说清公司做什么 (5字说清=10分, 5分钟才能解释=0分)
   - **路由决策**:
     - SGI ≥ 7 → **专才模型**: 关注单点故障风险+品类天花板+渗透率上限
     - SGI 4-6 → **混合模型**: 关注品类间协同是否真实可量化
     - SGI ≤ 3 → **通才模型**: 关注通才陷阱+管理层资源分配+品类优先级
   - **估值预期锚定**:
     - SGI 8-10: 预期P/E溢价30-60% vs 行业中位数
     - SGI 5-7: 预期P/E溢价0-20%
     - SGI 1-4: 预期P/E折价0-25%
     - 实际P/E偏离预期>2σ → 标记为"定价异常"，Phase 4重点验证
   - **输出**: SGI分数+5维度评分+路由决策+估值预期锚 写入 `shared_context.md` SGI节
   - **跨行业验证基准** (来自SEMI_EQUIPMENT对比报告复盘):
     - 半导体设备: SGI与A-Score相关0.98 | 专才P/E溢价+33%
     - 金融: V/MA(SGI~9) vs JPM(SGI~4) | P/E溢价+104%
     - 医疗: ISRG(SGI~10) vs JNJ(SGI~3) | P/E溢价+180%
     - 工业: ITW(SGI~6) vs 3M(SGI~3) | P/E溢价+1%(品类边界不刚性)
   - **详细方法论**: `docs/a_score_v2.md` §4.4

11. **品质门控评分 (CQ-Score Phase 0)** — 数据预取完成后，立即执行 `docs/company_quality_scoring.md` 中A+D维度:

### Phase 0.75: 核心矛盾结晶 (v17.1新增)

> **来源**: LRCX v3.0反思——非共识洞见S7=2/5，KLAC达4.5/5的根因是整个报告围绕一个核心矛盾展开。Phase 0.75在分析开始前强制锁定"这份报告要回答什么别人没回答的问题"。

**目的**: 从Phase 0数据+Phase 0.5 CQ中提炼出1-2个**可证伪的非共识假说**，作为后续Phase 1-5的叙事锚。不是增加工作量，是改变工作方向——从"覆盖所有模块"到"围绕核心矛盾组织"。

**三步执行** (30-60分钟，Phase 0会话内完成):

#### Step 1: 异常狩猎

扫描Phase 0的`shared_context.md`，逐项标记"直觉 vs 数据"偏差:

```markdown
## 异常狩猎表
| # | 数据点 | 直觉预期 | 实际值 | 偏差 | DM来源 |
|---|--------|---------|--------|:----:|--------|
| A1 | [具体指标] | [分析师/常识预期] | [Phase 0实际值] | >20%? | DM-xxx |
| A2 | ... | ... | ... | | |
```

**方法**: 不靠灵感，靠系统性扫描。对Phase 0每个关键数据点问"这个数字和我预期一致吗？"偏差>20%的标记为异常候选。

**LRCX回溯**: CSBG续约率80-84%(管理层) vs 60-67%(调整后)的口径差异在Phase 0数据中可发现，但被埋在数据堆中未被聚焦。

#### Step 2: 约束碰撞测试

对Reverse DCF的隐含假设(Phase 0.5 CQ中已初步列出)，做**物理/数学/历史可能性测试**:

```markdown
## 约束碰撞测试
| 隐含假设 | 隐含值 | 碰撞测试 | 结果 |
|---------|:------:|---------|:----:|
| [假设1] | X% | 历史上是否出现过? 物理上限是多少? | 可能/不可能/无先例 |
| [假设2] | Y% | 需要什么条件同时成立? 条件间是否矛盾? | 可能/矛盾 |
```

**与信念反演(Phase 2)的区别**: Phase 2做完整的6信念+脆弱度+翻转分析。Phase 0.75只做快速碰撞——10分钟内判断"有没有明显不可能的隐含假设"。如果有，它就是报告的核心矛盾。

**KLAC回溯**: "隐含份额28-32%超过物理上限"这一发现在Phase 0.75就能产出(只需TAM数据+当前市值)，而不必等到Phase 2。

#### Step 3: 非共识假说登记 + 门控

```markdown
## 非共识假说登记表
| # | 假说 | 共识认为 | 我认为 | 异常来源 | 证伪条件 | 估值影响 | Google可得? |
|---|------|---------|--------|---------|---------|:-------:|:---------:|
| H1 | [具体声明] | [市场/卖方观点] | [基于异常/碰撞的判断] | A?/碰撞? | [具体数据] | ±?% EV | 否 |
| H2 | [具体声明] | ... | ... | ... | ... | ... | 否 |
| H3 | — | — | — | — | — | — | — |
```

**门控规则 QG-00.75**:
- **PASS**: ≥1个假说满足: (a)估值影响>10% EV, (b)Google首页搜不到相同论点, (c)有DM锚点支撑
- **WARN**: 有假说但全是"高质量常识"(如"估值偏高") → 继续但标注"本报告非共识洞见风险偏低"
- **异常狩猎≥3个偏差>20%的数据点** — 如果数据本身就不异常，强行找非共识反而有害

**禁止**: 为通过门控编造假说。有些公司确实没有非共识角度——诚实标注比硬凑好。

#### 输出与后续影响

**输出文件**: `reports/{TICKER}/data/thesis_crystallization.md` (≥1500字符)

**对后续Phase的影响**:
- **Phase 1**: 行业背景围绕假说需要的上下文组织，与假说无关的通识压缩
- **Phase 2**: Reverse DCF信念反演优先验证假说相关的信念
- **Phase 3**: 五引擎/护城河分析中专门回应假说的多空论证

**不影响**: CQ注册表(Phase 0.5已定)、DM锚点系统、质量门控流程。Phase 0.75是叠加层，不替代现有流程。

### Phase 2: 财务与价格含义

**产出**: 财务数据组织 + Reverse DCF(价格隐含假设) + [深挖]问题深入分析

> **v2.0变化**: 从"给出目标价"转为"解读市场定价隐含了什么假设"。Reverse DCF是核心工具——不是算公司值多少钱，而是反推当前价格在赌什么。传统SOTP/DCF作为参考框架呈现，不作为结论。

**必做模块**:
- **Reverse DCF（核心）+ 承重墙脆弱度表 (v10.0)**: 当前股价隐含了多少增长率/利润率/年限？这些假设合理吗？每个隐含假设用承重墙脆弱度表评估脆弱性。

**承重墙脆弱度表模板**:
```markdown
| 承重墙(隐含假设) | 当前价格隐含值 | 历史/行业参考 | 脆弱度 | 若倒塌影响 |
|-----------------|:------------:|:----------:|:-----:|:--------:|
| 收入增速(5Y CAGR) | 25% | 行业中位15% | 高 | -35% |
| 稳态利润率 | 30% | 当前22%,同行25% | 中 | -20% |
| 增长持续年限 | 15年 | 科技公司均值8年 | 高 | -40% |
| 折现率隐含 | 8% | 当前无风险4.5%+ERP | 低 | -10% |
```
**脆弱度判定**: 高=隐含值超历史/行业参考50%+ | 中=超10-50% | 低=在参考范围内

- **品质评分 Phase 2维度**: 财务分析中同步评估(写入quality_scorecard.md):
  - **B5 利润弹性**: OPM 10年趋势 — 扩张>500bps=5分, 稳定=3分, 收缩=1分。若D2<50%用真实OPM
  - **B6 资本配置纪律**: 回购+股息/FCF比例 + SBC/Rev + 稀释率 → 评分/5
  - **D2收入纯度还原**(如Phase 0标记需要): 计算费用收入基础OPM, 更新B5评分
- 周期定位（行业周期模型，定位当前位置）
- 5年财务趋势分析（收入/利润/现金流/资产负债）— 数据组织，不下估值结论
- 三情景财务推演（Bull/Base/Bear的关键变量范围）
- **资本配置分析**: R&D效率、CapEx ROI、分红/回购策略 — 属于[深挖]区，AI可以深入分析
- **[深挖]问题执行**: Phase 0.5路由到本Phase的深挖类问题在此展开
- **参考框架（[呈现]区）**: SOTP/DCF/可比公司作为多视角参考呈现，标注"参考框架，非目标价"

**字数目标**: ≥25,000字符 (wc -m)

**门控 QG-04~06**:
- QG-04: 周期定位有≥4个支撑信号
- QG-05: Reverse DCF隐含假设已明确列出 + **承重墙脆弱度表完成** + 合理性评估完成

**产出**: 竞争优势量化 + 技术壁垒 + 五引擎分析 + PPDA背离发现

**必做模块**:

  - **B4 定价权证据**: 历史提价记录+客户流失率 → 评分/5 (消费品行业×1.5权重)

**Playing to Win战略一致性测试 (v18.0新增 — EVO-STRATEGY-002)**:
A-Score评估护城河存量质量("堡垒有多坚固")，PtW评估战略方向一致性("修建方向是否正确")。两者评估不同维度——高A-Score+低PtW="方向迷失的堡垒"，低A-Score+高PtW="有方向的追赶者"。

执行步骤:
1. **五层选择评分** (每层0-10, 总分/50):
   - L1 赢的志向: 清晰性+独特性+可防御性
   - L2 在哪里赢: 聚焦度+资源匹配度(8条产品线=5分, 1条=10分)
   - L3 如何赢: 差异化来源+可持续性+不可复制性
   - L4 核心能力: 能力与方法(L3)的匹配度+深度
   - L5 管理系统: 结构/流程/指标对战略的支撑完备度
2. **一致性循环检验**: 每一层是否强化其他层？最薄弱层识别
3. **A-Score × PtW交叉矩阵**:
   ```
                 PtW高(>40)           PtW低(<35)
   A-Score高    "卓越"               "方向迷失的堡垒"
   (>7)         战略+护城河双强        护城河强但战略不连贯

   A-Score低    "有方向的追赶者"      "结构性困境"
   (<6)         战略清晰但护城河待建    护城河弱+战略不连贯
   ```

### Phase 3.5: AI深度评估（v4.0新增，强制执行）

> **设计原因**: AI浪潮下，公司级"AI受益者/被颠覆者"标签掩盖了分部间的巨大差异。同一公司的不同业务对AI的暴露度可能截然相反。详见 `docs/ai_depth_assessment.md`

**产出**: 分部级AI冲击矩阵 + AI实施深度L×S定位 + AI调整后估值

**必做三层分析**:

**Layer 1 — 分部级AI冲击矩阵 (M13)**
- 对每个主要业务分部(占营收≥90%)独立评估5个维度:
  - 收入冲击(-5~+5): AI对该分部收入的增减影响
  - 成本冲击(-5~+5): AI对该分部成本结构的改变
  - 护城河变化(强化/中性/削弱): AI对现有竞争优势的影响
  - 竞争格局变化(利好/中性/利空): AI是否改变竞争者进入壁垒
  - 时间窗口(1-3yr/3-5yr/5-10yr): 冲击兑现的时间范围
- 每个分部归类为: AI放大器 / AI赋能者 / AI中性 / AI易受冲击 / AI被颠覆
- 计算: 概率加权AI净分 = Σ(分部AI净分 × 收入权重 × 实现概率)

**Layer 2 — AI实施深度评级**
- 引用 `skills/ai_assessment/` 框架:
  - L轴(实施级别): L0观察 → L1决策支持 → L2受控自动化 → L3自主运营 → L4完全自主
  - S轴(商业兑现): S0叙事期权 → S1早期变现 → S2规模化 → S3成熟 → S4平台化
  - 五不变量检验: 区分AI叙事噪音 vs 真实进展
- 输出: L×S坐标定位 + 五不变量通过率 + 同业对比

**Layer 3 — AI对价格含义的影响**
- 从Layer 1+2推导AI如何改变Reverse DCF的隐含假设:
  - AI放大分部: 价格隐含增长率中有多少依赖AI兑现？
  - AI受压分部: 若AI颠覆发生，当前定价是否已反映？
  - AI期权分部: 市场是否为尚未兑现的AI期权付费？
- 输出: "AI调整后隐含假设" vs "基线隐含假设" = AI定价溢价/折价的归因

**字数目标**: ≥10,000字符 (wc -m)

**门控 QG-09.5**:
- 所有主要分部(占营收≥90%)已完成AI冲击评分
- L×S坐标已定位且有≥3条证据支撑
- AI调整估值与基线估值差异已量化并解释

### 五引擎数据依赖矩阵 (v5.0新增)

> 当两个引擎共享数据源时，结论一致不算"双重验证"。

| 引擎 | 独立数据源 | 与其他引擎的数据重叠 |
|------|-----------|-------------------|

- E1+E5 结论一致 → 计为2票，数据源独立
- 最终置信度 = 独立数据源支持的引擎数 / 总引擎数

## 铁律（Deep-Dive强制，十五条）

1. **数据必有源**: 每个关键数字可追溯到DM锚点，DM覆盖率≥90%
2. **判断必有据**: 每个核心判断≥2条证据链
3. **预测必可验**: 概率+时间+触发条件
4. **洞察必反证**: "但如果___则不成立"
5. **结论必可追踪**: 核心论点+关键假设+追踪信号+Kill Switch(≥15个)
6. **概率必背离分析**: 重要风险事件执行PPDA分析
7. **情绪必市场验证**: 投资情绪判断必须用PMSI等指标验证
8. **AI必分部评估**: 禁止仅给公司级AI标签，必须逐分部评分(M13)
9. **热点必回应**: Phase 0.5发现的Top 10维度，报告中必须100%回应(M14)
10. **数据必审计** (v10.0): DM锚点三层分类(H/R/S)+脚本验证+文末审计摘要，报告正文零内联标注
11. **看空必等权** (v5.0): 看空相关内容≥总篇幅30%，≥8个看空论点含四要素
12. **模块必So What** (v5.0): 每个模块通过"So What?"检验，无洞察的模块压缩
13. **Phase必Fast Gate** (v5.1): 每Phase完成→运行research_fast.sh→通过后才能git commit
14. **无源数字禁写入** (v6.0): 报告中每个数字必须来自DM锚点/外部来源/明确公式，无源数字=幻觉=禁止。详见 `docs/anti_hallucination_protocol.md`
15. **估值修正必审计** (v6.0): 每次估值调整走修正管道(L1-L5)，单层≤±15%，记审计日志。详见 `docs/valuation_correction_hierarchy.md`

## 并行Agent加速

> 并行基础见 `docs/parallel_execution.md`
> 协作协议见 `docs/agent_collaboration_protocol.md`

独立任务**必须并行**执行。推荐并行组合:
- Phase 0 + 0.5: 数据预取与注意力雷达并行
- Phase 3各子模块: 护城河/五引擎/热点补丁可并行
- Phase 3.5: Layer 1(冲击矩阵) + Layer 2(L×S定位)可并行
- Phase 5: Kill Switch + 预测清单 + 行动清单 + 护城河数据卡可并行

### 多Agent协作机制 (v1.1, AMD验证)

**每个Phase并行执行时必须遵循**:

1. **共享上下文**: dispatch前编写 `reports/{TICKER}/data/shared_context.md` (Data Master格式)，Agent只读此文件
2. **任务锁**: dispatch前创建 `reports/{TICKER}/data/current_tasks/Agent{X}.lock.md`，完成+QG通过后删锁
3. **质量门控**: Agent返回后运行 P-G (Fast Gate) + R-G (结果检查)。详见 `docs/quality_gate_v2.md`
4. **增量提交**: 每个Agent通过QG → 立即 `git commit`
5. **状态仪表盘**: 每个Agent完成时更新 `STATUS.md`
6. **Session恢复**: 新session检测到锁文件 → 执行恢复协议（检查output→判断状态→报告用户）
7. **反幻觉注入 (v6.0)**: 每个SubAgent prompt必须包含反幻觉5条禁令。详见 `docs/anti_hallucination_protocol.md`
8. **DM引用规范 (v6.0)**: Agent引用数据必须附带 `[DM-xxx vN.N]` 版本号。详见 `docs/data_version_control.md`

### 并行Agent Prompt规范 (v5.1+v6.0)

**每个SubAgent prompt必须包含** (v5.1):
1. **具体数据需求列表**: 列出每个数据点/指标（非泛泛描述）
2. **Phase前序发现**: 已完成Phase关键结论摘要
3. **CQ关联**: 与哪个Core Question相关
4. **字符目标**: 期望返回字符数范围
5. **输出格式要求**: 标注格式+表格+Mermaid图需求
6. **验证要求**: 标注数据来源和获取时间
7. **反幻觉5条禁令 (v6.0)**: 详见 `docs/anti_hallucination_protocol.md`
8. **DM/KAL引用指令 (v6.0)**: 详见 `docs/parallel_execution.md` v4.0
