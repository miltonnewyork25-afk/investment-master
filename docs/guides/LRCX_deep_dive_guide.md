## 二、问题解剖 — 8个必须修复的问题

> 问题1-5: LRCX v2.0半导体专有 | 问题6-8: AAPL 3.79/5跨行业教训

### 问题1: 体量膨胀 (470K → 目标300-400K)

**诊断**: Phase 1行业概述占~100K，大量半导体基础知识(什么是刻蚀、什么是EUV)对读者无价值。
**修复**:
- 删除基础行业科普，假设读者已了解半导体设备行业
- 行业背景压缩至10-15K(仅含与LRCX直接相关的周期定位和竞争格局)
- 已有TSM/KLAC/AMAT报告的行业知识不再重复，用交叉引用替代
- **铁律**: 每写一段问自己"删掉这段，投资决策会改变吗？"不会 → 删

### 问题2: 中国风险处理 (EV加权 → 情景分析)

**诊断**: 旧版用单一期望值(概率×影响)处理出口管制风险，无法捕捉二元/跳跃性特征。
**修复**:
- **三情景模型**: S-China1(管制放松, 15%概率) / S-China2(现状维持, 55%) / S-China3(全面限制, 30%)
- 每个情景: 独立收入影响 + 独立利润率影响 + 独立估值倍数
- 参考TSM教训: 地缘风险"不适合概率×影响简单相乘，用条件估值"
- **AAPL升级 — 单一承重墙多路径建模**: AAPL Ch8对Google协议做了6路径深度建模(四情景→六路径+TAC历史+AI基础设施论点)，中国出口管制应参考同等深度
  - 路径1: 全面限制但国产替代不足→LRCX短期受损→市场重新分配
  - 路径2: 限制扩大到日本→TEL受限→LRCX短期份额上升但长期市场萎缩
  - 路径3: 限制放松→中国需求回流→但LRCX已丢失的客户关系能否恢复？
  - 路径4-6: 政策路径+替代进度+地缘变化的交叉组合

### 问题3: 方法伪独立 (5方法 → 审计后真正独立)

**诊断**: 旧版未运行独立性审计。
**双重验证**:
- AMAT教训(3.8/5): 5方法中3个共享核心假设=实际2.5方法
- **AAPL二次验证(3.79/5)**: 5种估值方法实际仅SOTP和Reverse DCF独立。正向DCF是Reverse DCF镜像，条件估值是Reverse DCF场景化展开。评分S4=3.0/5(全报告最弱维度之一)
- **根因(AAPL 5 Whys)**: 公司核心驱动力只有2-3个 → 无论包装成几种方法，都共享同一批假设 → "多方法"是幻觉
- **修复**: Phase 3完成后**强制运行** `/valuation-independence-audit`
  - 预期: DCF和SOTP共享WFE增长假设 → 合并为"内生价值锚"
  - 真正独立: Reverse DCF(价格→假设) + 可比公司(市场定价同行) + 条件估值(情景概率)
  - **AB-007会检测**: phase_sentinel v2.1自动验证独立性审计已执行
  - **标注要求**: Complete报告中必须写明"N种方法(其中M种独立)"

### 问题4: 缺少杀手级洞见

**诊断**: 旧版有扎实的数据(44.4/万DM密度=记录)但缺乏改变框架的发现。
**修复 — 三个候选杀手级洞见方向**:
1. **CSBG隐性价值**: 安装基数8万+台设备 × 服务合同 = 类SaaS经常性收入流。独立估值CSBG可能揭示"设备+服务"二元结构中被低估的服务价值(参考AMAT AGS独立估值$31.9B发现)
2. **刻蚀工艺复杂度的结构性需求增长**: 3D NAND层数增加(200→300+层)和GAA晶体管对刻蚀步骤的需求不是线性增长，可能是超线性的。如果量化"每代制程刻蚀步骤增长曲线"，这是结构性增长vs周期性增长的关键区分
3. **信念反演**: Reverse DCF反推市场隐含WFE增长+份额假设 → 与行业共识对比 → 发现市场在赌什么/赌错什么(KLAC最强洞见方法)
   - **AAPL升级**: 不仅反推信念，还测试信念间逻辑一致性 — AAPL发现B1↔B8循环依赖=全报告最强洞见(S1 4.5/5)。LRCX的WFE增长↔AI需求↔CapEx周期之间是否存在类似环路？

### 问题5: 周期定位不够精确

**诊断**: 旧版周期分析偏定性，缺乏6层雷达量化定位。
**修复**:
- 执行6层雷达信号量化(DRAM/NAND价格趋势20% + Fab CapEx指引20% + BB Ratio 15% + 库存天数15% + 产能利用率15% + AI/DC终端需求15%)
- 明确标注"P几"阶段(P1复苏/P2扩张/P3峰值/P4减速/P5衰退)
- 与KLAC/AMAT/TSM报告时的周期定位对比: 时间推移了多少，周期阶段变化了吗？
- **AAPL PEG锚定效应技术**: AAPL Ch22发现同一P/E绝对值在不同增速背景下含义完全不同(PEG 5.2x vs 历史1.0x)。LRCX周期性P/E同理——周期底部P/E 25x vs 周期顶部P/E 25x含义截然不同。必须标注P/E所处的周期阶段

### 问题6: 多层组装引入冗余 [AAPL新增]

> **来源**: AAPL反思R6 Top Mistake — 303K中50-80K冗余来自v2.0→Assembly→Expansion四层叠加

**诊断**: AAPL的Ch14.6和Ch22 P/E溢价分解几乎完全重复；扩展章节(16.5/16.7/22.5/23.5)部分内容与主章节冗余。如果精简至250K，质量可从3.79→4.0+。
**LRCX修复**:
- **平面章节架构**(EVO-AAPL-003): Phase 1-3直接产出Complete章节Ch1-Ch25，不经Assembly/Expansion
- **冗余自检**: 每完成一个Phase，对已写章节做pairwise检查——任意两章内容重叠>10% → 必须合并或删除其一
- **具体反面模式**(AAPL):
  - Ch14.6(估值综合中的P/E分解) ≈ Ch22(P/E考古学) → 应只存在一处
  - Ch2.4-2.6(财务扩展) vs Ch2.1-2.3(财务核心) → 扩展应在原章节内，不另开子章节
  - 扩展模块(Ch16.5/16.7/22.5/23.5) → 不应存在.5章节，内容并入主章节

### 问题7: 可执行性弱 — KS/VP格式缺失 [AAPL新增]

> **来源**: AAPL S12评分3.0/5(全报告最弱维度之一) — Kill Switch和验证预测内容丰富但格式不符

**诊断**: AAPL有丰富的Kill Switch内容(Ch28场景转换触发器)和可验证预测(Ch15.X.2验证窗口)，但未使用KS-xxx/VP-xxx标记 → CG4=4(应≥12), CG5=0(应≥5)。虽然EVO-AAPL-001的NL检测已修复脚本端，但**正式格式仍是最佳实践**。
**LRCX修复**:
- Kill Switch使用 `KS-N: [触发条件] | [阈值] | [论文含义]` 正式格式，≥12个
- 验证预测使用 `VP-N: [预测] | [验证窗口] | [数据来源]` 正式格式，≥5个
- Ch24(Kill Switch + 追踪信号)中集中列出所有KS和VP，同时在相关章节中引用
- **好处**: 正式格式通过CG4/CG5的所有4层检测(包括v6.0 NL兜底)，零风险

### 问题8: Bear场景不够极端 [AAPL新增]

> **来源**: AAPL S8评分3.5/5 — S4极端场景Net Margin 22%偏保守，Bear仅是Base打折而非独立逻辑路径

**诊断**: AAPL的S4场景只是S2基准场景的降幅版(同一逻辑路径，参数缩水)。真正的极端场景应有**独立的失败逻辑**。
**LRCX修复**:
- S4极端场景必须有独立叙事(非S2打折): 例如"WFE周期崩塌+中国全面禁令+AI CapEx泡沫破裂同时发生"
- S4的关键参数必须真正极端: Operating Margin降至行业衰退期水平(参考2019周期底)
- **检查方法**: S4描述中不应出现"在S2基础上下调X%"的表述 → 每个场景必须自成逻辑

## 三、AAPL反面教材速查 — 3个具体反模式

> 这些是从AAPL 3.79/5 → 4.5/5提升路上必须跨越的障碍。LRCX v3.0必须避免。

### 反模式A: "方法伪独立"陷阱

**AAPL原文**: 5种估值方法(正向DCF/Reverse DCF/SOTP/条件估值/可比公司)
**实际独立**: 仅2种(SOTP + Reverse DCF)。正向DCF是Reverse DCF的镜像；条件估值是Reverse DCF的场景展开；Ch22估值综合与Ch14.6高度重叠。
**评分影响**: S4=3.0/5(最弱维度)
**LRCX防范**:
1. Phase 3后运行 `/valuation-independence-audit`
2. 对每对方法计算假设重叠度: 共享假设数/总假设数
3. 重叠度>60%的方法对 → 合并为"衍生方法"或删除
4. 报告中明确标注"N种方法(其中M种独立)"
5. **LRCX预期**: DCF+SOTP共享WFE假设→合并为内生价值锚；真正独立=Reverse DCF+可比公司+条件估值=3种

### 反模式B: "多层组装"冗余

**AAPL原文**: Phase 1-3 staging → v2.0合并 → Assembly(3部分) → Expansion(4模块) → Complete
**冗余量**: 50-80K字符(占总量16-26%)
**具体重复**: Ch14.6 P/E溢价分解 ≈ Ch22 P/E考古学；Ch2.4-2.6 ≈ Ch2.1-2.3扩展
**LRCX防范**:
1. 只用平面章节(Ch1-Ch25)，一次写入，不分层
2. 每Phase完成后做pairwise冗余检查
3. **决策测试**: "如果把这段移到另一章，是否信息丢失？" 不丢失 → 两章有冗余

### 反模式C: "循环依赖"盲区

**AAPL原文**: iPhone增速(B1)↔AI换机周期(B8)形成循环依赖——两个信念互相支撑但都缺乏独立验证。P(B1失败|B8失败)≈85-90%。
**洞见价值**: S1=4.5/5(报告最强维度) — 这种循环依赖识别是AAPL报告最核心的贡献
**LRCX应用**:
- **候选循环依赖**: WFE增长 ↔ AI CapEx需求 ↔ 设备商收入增长 ↔ 技术投资 ↔ 下一代制程能力 ↔ 客户需求
- Phase 1 Ch9中强制执行M1.4b循环依赖检测
- 输出信念依赖网络图(Mermaid) + 联合失败概率 + 最少几个信念翻转评级
