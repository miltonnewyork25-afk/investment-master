# Tier 3 研报质量标准 v1.0 — 4.4分基线

> **目标分数**: 4.4/5.0 (介于IHG 4.3和KLAC 4.5之间)
> **设计原则**: 每一项都有量化阈值和检测方法，不依赖主观判断
> **适用**: 所有Tier 3深度研究报告的Complete组装前门控
> **源自**: ADBE v1.0(~3.0) vs v2.0(4.2)的修复差距分析 + KLAC/IHG/ETN标杆

## 一、硬门控 (Complete前必须全部PASS，任一FAIL=禁止提交)

| # | 门控项 | 阈值 | 检测方法 | 4.4标杆值 | 说明 |
|---|--------|------|---------|----------|------|
| G1 | **字符数** | **≥270K** | `wc -m {REPORT}` | 270-350K | KLAC=248K得4.5但那是密度极高的例外。270K是保证广度覆盖的安全线 |
| G2 | **DM密度** | **≥1.5/千字** | `grep -c 'DM-' / wc -m × 1000` | 1.5-2.2 | KLAC=2.17, IHG=1.78, ADBE v1=0.05→v2=2.42。<1.5=数据无源 |
| G3 | **DM总数** | **≥450** | `grep -c 'DM-'` | 450-600 | IHG=547, KLAC=553, ADBE v1=15→v2=284(仍不够)。每个关键数字需要锚点 |
| G4 | **Mermaid图** | **≥25** | `grep -c 'mermaid'` | 25-50 | IHG=92, SMCI=47, ADBE v1=0→v2=24(差1个)。流程/结构/关系的可视化 |
| G5 | **因果密度** | **≥5.0/万字** | `grep -c '因为\|因此\|这意味着\|这解释了' / wc -m × 10000` | 5.0-9.0 | KLAC=9.28, ADBE v2=11.52(已达)。<5.0=断言替代推理 |
| G6 | **Python验证** | **必须** | 估值章节有`verify_dcf_arithmetic.py`调用记录 | 是/否 | DCF/SOTP的关键算术必须Python交叉验证。ADBE v1缺→MCO估值错误 |
| G7 | **估值离散度** | **≤30%** | 最高估值/最低估值 - 1 | <30% | ADBE v2=17.8%(好) vs MSCI v1=115%(差)。>30%=方法间矛盾未解决 |
| G8 | **CQ格式标记** | **CQ1-CQ8** | `grep -c 'CQ-[0-9]'` ≥ 5 | 5-8个CQ | 核心问题必须用CQ标记+全文闭环。H1-H4旧格式不可接受 |

### 硬门控检测脚本

```bash
#!/bin/bash
# 用法: bash docs/quality_gate_4.4.sh <REPORT_FILE>
REPORT="$1"
PASS=0; FAIL=0

chars=$(wc -m < "$REPORT" | tr -d ' ')
dm=$(grep -c 'DM-' "$REPORT" 2>/dev/null || echo 0)
mermaid=$(grep -ci 'mermaid' "$REPORT" 2>/dev/null || echo 0)
causal=$(grep -c '因为\|因此\|这意味着\|这解释了' "$REPORT" 2>/dev/null || echo 0)
cq=$(grep -c 'CQ-[0-9]' "$REPORT" 2>/dev/null || echo 0)

dm_density=$(echo "scale=2; $dm * 1000 / $chars" | bc)
causal_density=$(echo "scale=2; $causal * 10000 / $chars" | bc)

echo "G1 字符: ${chars} $([ $chars -ge 270000 ] && echo PASS || echo FAIL)"
echo "G2 DM密度: ${dm_density}/千字 $(echo "$dm_density >= 1.5" | bc -l | grep -q 1 && echo PASS || echo FAIL)"
echo "G3 DM总数: ${dm} $([ $dm -ge 450 ] && echo PASS || echo FAIL)"
echo "G4 Mermaid: ${mermaid} $([ $mermaid -ge 25 ] && echo PASS || echo FAIL)"
echo "G5 因果密度: ${causal_density}/万字 $(echo "$causal_density >= 5.0" | bc -l | grep -q 1 && echo PASS || echo FAIL)"
echo "G6 Python验证: 手动检查"
echo "G7 估值离散度: 手动检查"
echo "G8 CQ标记: ${cq} $([ $cq -ge 5 ] && echo PASS || echo FAIL)"
```

### 各维度详细评分细则

#### D1 数据基础 (目标≥8)

| 分数 | 标准 |
|------|------|
| 10 | DM总数≥600 + A级占比≥80% + 所有估值输入有DM |
| 8 | DM总数≥450 + A级占比≥70% + 关键估值输入有DM |
| 6 | DM总数≥300 + A级占比≥60% |
| 4 | DM总数≥150 + 有DM但密度不足 |
| 2 | DM总数<150, 大量数据无源 |
| 0 | 无DM系统或DM<50 |

**A级DM**: 来自10-K/10-Q/行业权威报告的硬数据
**B级DM**: 来自Earnings Call/管理层指引/分析师估计
**C级DM**: 来自推算/类比/二手来源

#### D2 问题定义 (目标≥8)

| 分数 | 标准 |
|------|------|
| 10 | CQ1-CQ8全部定义 + 每个CQ有明确假说 + 全文闭环(结论回答每个CQ) |
| 8 | CQ1-CQ5定义 + 大部分闭环 + thesis_crystallization完成 |
| 6 | 有核心问题但用H1-H4旧格式 或 闭环不完整 |
| 4 | 问题定义模糊，分析方向不清晰 |
| 0 | 无问题定义，直接开始分析 |

**关键要求**: Phase 0.75的`thesis_crystallization.md`必须≥1500字符，包含:
- 异常狩猎结果(≥3个异常)
- 约束碰撞分析
- 非共识假说登记(≥2个)

#### D3 分析深度 (目标≥7)

| 分数 | 标准 |
|------|------|
| 10 | 因果密度≥8.0/万字 + ≥3个原创分析框架(X1/X2/X3标记) + 每个核心论点3层证据链 |
| 8 | 因果密度≥6.0 + ≥2个原创框架 + 多数论点有证据链 |
| 7 | 因果密度≥5.0 + ≥1个原创框架 + 关键论点有证据链 |
| 5 | 因果密度3.0-5.0 + 无原创框架但分析逻辑清晰 |
| 3 | 因果密度<3.0 = 断言替代推理(铁律N违规) |
| 0 | 无因果推理，纯描述性报告 |

**原创框架**: 报告中首创的分析工具/模型，用X1/X2/X3标记。如:
- KLAC: "良率经济学不对称模型"
- MCO: "利润率混合陷阱"
- ADBE v2: "护城河迁移进度模型"

**证据链3层**: 每个影响估值的核心论点必须:
1. ≥1个硬数据(带DM)
2. ≥1个因果推理("因为X→所以Y")
3. ≥1个反面考量("在什么条件下不成立")

#### D4 风险认知 (目标≥7)

| 分数 | 标准 |
|------|------|
| 10 | 风险拓扑图(协同/反协同关系) + ≥8个风险节点 + ≥3个KS + "温水煮青蛙"场景 |
| 8 | ≥6个风险节点 + ≥3个KS + 风险间关系分析 |
| 7 | ≥5个风险节点 + ≥2个KS |
| 5 | 有风险清单但无系统性分析 |
| 3 | 风险分析敷衍(<3个风险) |
| 0 | 无风险分析 |

**KS(Kill Switch)标准**: 每个KS必须包含:
- 触发条件(具体、可观测)
- 触发后行动(具体、不含糊)
- 监测频率(季度/年度)

#### D5 估值框架 (目标≥8)

| 分数 | 标准 |
|------|------|
| 10 | ≥4种独立方法 + 离散度≤20% + Python验证 + 概率加权用偏差修正后概率 + 铁律K全通过 |
| 8 | ≥3种方法 + 离散度≤30% + Python验证 + 年化/累计区分清楚 |
| 7 | ≥3种方法 + 离散度≤40% + 有交叉验证 |
| 5 | ≥2种方法但离散度>40% 或 无Python验证 |
| 3 | 单一方法 或 明显算术错误 |
| 0 | 无估值 或 估值内部自相矛盾(MCO v1.0问题) |

**铁律K检查清单**(每项必须PASS):
- [ ] 列出所有独立估值结果
- [ ] ≥60%方向一致
- [ ] 概率加权使用偏差修正后概率(非Phase 3原始)
- [ ] 区分"5年退出价"和"当前公允价值"
- [ ] 温度计/评级/执行摘要数字与估值章节一致

#### D6 数据验证 (目标≥8)

| 分数 | 标准 |
|------|------|
| 10 | 数据审计摘要 + DM覆盖率标注 + ≥2源交叉验证关键数字 + verify_data_sources.sh通过 |
| 8 | 审计摘要 + 关键数字有交叉验证 + DM A级占比标注 |
| 6 | 有DM但无审计摘要 |
| 4 | DM稀疏，部分数据无源 |
| 0 | 无数据验证，数字来源不可追溯 |

**审计摘要模板** (报告末尾必须包含):
```
DM审计: 总计{N}个锚点 | A级{n}({pct}%) | B级{n} | C级{n}
覆盖率: 估值输入{covered}/{total} | 关键假设{covered}/{total}
交叉验证: {N}个关键数字通过2源验证
```

#### D7 非共识洞见 (目标≥7)

| 分数 | 标准 |
|------|------|
| 10 | ≥3个CI(Counter-Intuitive)标记洞见 + 每个有完整论证 + ≥1个可能改变投资者决策 |
| 8 | ≥2个CI + 论证充分 |
| 7 | ≥1个CI + 论证充分 + 多数分析有独立视角 |
| 5 | 分析有独立视角但无明确CI标记 |
| 3 | 纯共识观点重述 |
| 0 | 报告无任何独立观点 |

**CI洞见标准**: 必须满足以下全部:
- 与市场共识或分析师主流观点不同
- 有数据+逻辑支撑(不是凭感觉)
- 可能影响估值≥5%
- 标记为CI-01, CI-02等

#### D8 可视化 (目标≥8)

| 分数 | 标准 |
|------|------|
| 10 | Mermaid≥40 + 数据表格≥30 + 每章至少1个可视化元素 |
| 8 | Mermaid≥25 + 数据表格≥20 + 关键流程有图示 |
| 7 | Mermaid≥15 + 数据表格≥15 |
| 5 | Mermaid≥5 或 有表格但图示不足 |
| 0 | 纯文字，无图表(ADBE v1.0=0) |

**Mermaid使用场景**:
- 业务结构/收入构成(必须)
- 竞争格局/市占率(必须)
- 风险拓扑图(必须)
- 估值方法论流程(必须)
- 决策树/情景分支(建议)

#### D9 追踪体系 (目标≥7)

| 分数 | 标准 |
|------|------|
| 10 | ≥3个KS + ≥12个TS(Tracking Signal) + KS有条件依赖网络 + 监测日历 |
| 8 | ≥3个KS + ≥8个TS + KS间关系清晰 |
| 7 | ≥2个KS + ≥5个TS |
| 5 | 有KS但无TS |
| 3 | KS模糊不可操作 |
| 0 | 无追踪体系 |

**TS(Tracking Signal)标准**: 每个TS包含:
- 指标名称和当前值
- 监测频率
- 阈值(触发重新评估的条件)
- 标记为TS-01, TS-02等

#### D10 结构完整度 (目标≥7)

| 分数 | 标准 |
|------|------|
| 10 | Phase 0-5全标签 + 评分表完整 + CG门控全通过 + 策略卡同步 |
| 8 | Phase标签完整 + 评分表 + CG基本通过 |
| 7 | Phase标签基本完整 + 有评分表 |
| 5 | 结构可识别但缺少标签/评分 |
| 2 | 结构混乱，Phase不清晰(ADBE v1.0) |
| 0 | 无结构 |

**必须包含的结构元素**:
- 执行摘要(≥2000字符, 含评级+估值+核心逻辑)
- 评分表(A-Score或品质评分)
- 策略卡(内部文档B, 含入场纪律+KS)
- DM审计摘要(D6要求)

#### D11 正交度 (目标≥8)

| 分数 | 标准 |
|------|------|
| 10 | 每章回答不同的CQ + 零重复结论 + 章节间交叉引用而非重述 |
| 8 | 大部分章节独立 + 重复≤2处 |
| 6 | 有重复但不严重(≤5处) |
| 4 | 明显重复(>5处同一结论出现) |
| 0 | 大量复制粘贴，章节间高度重复(HLT v1.0问题: NUG×4/回购×5) |

**正交度检测**: 如果某个结论在报告中出现≥3次(不同章节)，必须:
- 保留最深入的1处
- 其余改为交叉引用("详见ChX分析")
- 单章最大占比≤15%(铁律M)

## 三、维度间关系和优先级

### 3.1 致命缺陷 (任一<5分 = 总分自动降至3.5以下)

| 致命维度 | 为什么致命 |
|---------|----------|
| D5 估值框架 < 5 | 估值错误直接导致投资者亏损(MCO教训) |
| D1 数据基础 < 5 | 无数据=无分析，纯叙事 |
| D3 分析深度 < 5 | 断言替代推理=误导投资者 |

### 3.2 乘数效应

| 组合 | 效果 |
|------|------|
| D3高 + D7高 | 深度分析产生非共识洞见 → 报告价值倍增 |
| D1高 + D6高 | 数据扎实+验证充分 → 结论可信度极高 |
| D5高 + D4高 | 估值准确+风险充分 → 投资决策质量最高 |
| D8高 + D11高 | 可视化+正交 → 读者体验最好 |

### 3.3 分数区间含义

| 总分/110 | 等级 | 对应评分 | 含义 |
|----------|------|---------|------|
| ≥99 | 卓越 | 4.5+ | KLAC级别：密度+洞见+零缺陷 |
| **88-98** | **优秀** | **4.2-4.4** | **本标准的目标区间** |
| 77-87 | 良好 | 3.8-4.1 | 可发布但有改善空间 |
| 66-76 | 合格 | 3.5-3.7 | 勉强可发布，需要注意缺陷 |
| <66 | 不合格 | <3.5 | 不应发布，需要重大修改 |

## 五、4.4分报告的具体画像

一份4.4分报告应该长这样:

```
字符: 270-350K (广度充分)
DM: ≥450个, 密度≥1.5/千字 (每个关键数字有源)
Mermaid: ≥25个 (关键流程和关系可视化)
因果密度: ≥5.0/万字 (每个论点有完整推理链)
原创框架: ≥1个 (报告有独特分析视角)
CQ: 5-8个, 全部闭环 (问题驱动, 不是流水账)
CI: ≥2个 (有非共识洞见, 不是共识重述)
KS: ≥3个 + TS: ≥8个 (可追踪, 不是写完就扔)
估值: ≥3种方法, 离散度≤30%, Python验证
正交度: 每章回答不同问题, 重复≤2处
```

**标杆参考**:
- KLAC (4.5): 248K, DM 553, 因果9.28, CI 5个 → 密度之王
- IHG (4.3): 307K, DM 547, Mermaid 92 → 可视化之王
- ETN (4.3): 331K, 产业链纵深 → 行业深度之王
- **4.4分目标**: 取三者之长，每项≥7分，总分≥88/110
