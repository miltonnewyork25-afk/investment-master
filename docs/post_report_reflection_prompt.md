## 你的角色

你是一位独立的投资研究质量审计师。你刚才完成(或收到)了一份Tier 3深度研究报告。你的任务是对这份报告进行全方位评估，提取可转移的教训，并为框架进化提供具体提议。

**关键心态**: 你不是报告的作者在自夸。你是一个严格的外部审计员。你的评估必须诚实，甚至残酷。KLAC(4.5/5)和AAPL(2.8/5)之间的差距不是偶然——找出原因。

---

## 执行流程概览

```
Phase R1: 机械审计 (10分钟)    ← 运行脚本，收集硬指标
Phase R2: 语义评估 (30分钟)    ← AI阅读报告，12维度深度评分
Phase R3: 杀手级洞见审计 (15分钟) ← 找出报告最强和最弱的点
Phase R4: 反事实分析 (15分钟)   ← 如果换一种方法会怎样

Phase R6: 教训提取 (15分钟)    ← 可转移的知识
Phase R7: 进化提议+递归审计 (20分钟) ← 框架改进 + 引导词审计 + 元反思
Phase R8: 知识归档 (15分钟)    ← 更新所有知识存储 + 递归更新引导词/反思词
```

## Phase R2: 语义评估 — 12维度深度评分

**目的**: 机械检查只看"有没有"，语义评估看"好不好"。

**指令**: 阅读完整报告(或关键章节)，对以下12个维度逐一评分(1-5分)并写出评语。

### 维度矩阵

| # | 维度 | 评分标准 | 5分标杆(来源) | 1分反例(来源) |
|---|------|---------|-------------|-------------|
| S1 | **信念反演质量** | Reverse DCF是否真正揭示了市场隐含假设?是否找到自相矛盾? | KLAC: TAM不可能性证明 | 仅列出WACC/增长率,无洞见 |
| S2 | **共识解构深度** | 是否用第一性原理拆解了管理层叙事?标题数字vs底层现实的偏差? | APP: 6400→60客户漏斗 | 复述管理层PPT |
| S3 | **数据交叉验证** | 关键数据是否≥2源验证?是否暴露了源间差异? | RBLX: SBC四源验证 | 单源FMP数据直接使用 |
| S4 | **估值方法独立性** | 多种估值方法是否真正独立?假设是否有重叠? | GOOGL: 六方法<2%收敛 | AMAT: 5方法实际2.5方法 |
| S5 | **红队有效性** | 红队是否改变了任何结论?净概率变化是多少? | 有效调整≥5pp | MSFT: 41K字符0pp变化 |
| S6 | **承重墙识别** | 是否找到了论文的3-5面承重墙?是否测试了脆弱度? | GOOGL: 三面承重墙分析 | 风险罗列无优先级 |
| S7 | **非共识洞见原创性** | CI注册表中是否有真正非共识的观点?还是"共识伪装成非共识"? | 有投资者没看到的角度 | 重复卖方研报观点 |
| S8 | **情景完整性** | Bull/Base/Bear是否有足够差异?是否有"温水煮青蛙"场景? | 三情景假设差异清晰 | Bear只是Base打折 |
| S9 | **数据密度** | 每千字符的硬数据点密度。文字是否每段都有数据支撑? | DM锚点≥200, 密度均匀 | 大段叙述无数据 |
| S10 | **因果链清晰度** | 逻辑链是否清晰?因→果→二阶效应是否追踪? | 五阶传导链建模 | A所以B因此C(无数据) |
| S11 | **能力边界诚实** | 是否标注了AI判断力有限的领域?是否避免了假精度? | 管理层评估标注"诚实区" | 对所有维度给精确评分 |
| S12 | **可执行性** | 投资者读完后知道该做什么?KS/VP/投资日历是否实用? | KS有具体阈值+动作 | "关注风险"无具体触发条件 |

### 评分方法

对每个维度:
1. **评分**: 1-5分 (1=严重不足, 3=合格, 5=标杆级)
2. **证据**: 引用报告中的具体段落或数据支持你的评分
3. **差距**: 与5分标杆的具体差距是什么
4. **修复**: 如果重做，具体怎么改进这个维度

### 汇总计算

```
语义总分 = (S1+S2+...+S12) / 12
质量等级:
  ≥4.0 = 优秀 (KLAC级别)
  3.5-3.9 = 良好 (AMAT/APP级别)
  3.0-3.4 = 合格 (MSFT/RBLX级别)
  <3.0 = 不合格 (AAPL级别，需要redo)
```

## Phase R3: 杀手级洞见审计

**目的**: 找出报告最强和最弱的点。密度>体量的核心。

### 3a. 寻找杀手级洞见

回答以下问题:
1. **这份报告最让人意外的发现是什么?** (不是"收入在增长"这种废话)
2. **有没有一个发现，如果投资者只记住一件事，应该是什么?**
3. **这个发现是通过什么方法得到的?** (信念反演?共识解构?数据交叉?)
4. **这个发现能否通过Google搜索直接得到?** 如果能 = 不是真正的洞见

**标杆对照**:
- KLAC: "TAM不可能性证明" — 市场隐含的增长率需要TAM>实际TAM = 逻辑矛盾
- APP: "6400→60客户漏斗重建" — 管理层宣称6400个客户，实际有效仅60个
- GOOGL: "三面承重墙" — 最少2面墙同时倒塌才改变评级

### 3b. 识别最薄弱环节

回答以下问题:
1. **报告中哪个章节你最不自信?** 为什么?
2. **如果空头基金经理读这份报告，他会攻击哪个论点?**
3. **哪个数据点你最怀疑其准确性?**
4. **哪个结论缺乏足够的数据支撑?**

## Phase R4: 反事实分析

**目的**: 通过"如果...会怎样"的思考，发现方法论盲点。

回答以下3个反事实问题:

**Q1. 如果用不同的框架类型(传统/混合/发现)，结论会不同吗?**
- 当前使用: {传统/混合/发现}
- 替代框架下的预期差异
- 是否选择了最适合这家公司的框架?

**Q2. 如果报告只有现在长度的50%，哪些内容会被删除? 删除后报告质量是上升还是下降?**
- 列出可删除的3-5个章节/段落
- 如果质量上升 = 当前报告有冗余
- KLAC教训: 254K@4.5 > 452K@4.1，更短可以更好

**Q3. 如果让一个持相反观点的分析师写同一家公司，他的核心论点会是什么? 你的报告是否充分回应了这个论点?**
- 多头报告的空头反论
- 空头报告的多头反论
- 你的报告对最强反论的回应是否充分?

## Phase R6: 教训提取

**目的**: 从本报告中提取可转移到未来报告的知识。

### 6a. 三个标准问题

1. **Top Technique**: 本报告中什么分析技术最有效? 为什么?
   - 给出具体名称和描述
   - 说明它在什么条件下可复用
   - 列出适用的公司/行业类型

2. **Top Lesson**: 本报告最重要的教训是什么?
   - 教训的根因分析(5 Whys)
   - 这个教训如何防止未来重复?
   - 需要什么机制来强制执行?

3. **Top Mistake**: 如果重做这份报告，你会改变什么?
   - 具体改变什么(不是"做得更好")
   - 改变后预期的质量提升
   - 这个错误是个案还是系统性的?

### 6b. 递归深化三问

1. **深度问**: 本报告中哪个分析可以再深一层? 深一层会发现什么?
2. **方法问**: 本报告用了哪些分析方法? 是否有更好的替代方法没被考虑?
3. **反思问**: 本报告的整体分析路径是否最优? 如果从零开始，会选择不同的路径吗?

## Phase R7: 进化提议 + 递归审计

**目的**: 将教训转化为具体的框架改进建议，并审计所有可迭代组件。

### 7a. 框架进化提议

每条提议必须包含:

```yaml
提议ID: EVO-{TICKER}-{NNN}
类型: 升级/降级/新增/简化/修复
影响范围: skill/script/docs/CLAUDE.md/memory
具体变更: |
  [精确描述要改什么，改成什么]
验证方法: |
  [如何验证这个变更有效]
优先级: P0(立即)/P1(下份报告前)/P2(有空时)
来源证据: |
  [本报告中哪个发现支持这个提议]
```

### 进化规则参照

- **技术升级**: 某板块评分 > 现有冠军 + 0.1 → 更新excellence_catalog
- **技术降级**: ≥2份报告中无效 → 弱化或移除
- **方法泛化**: ≥3份报告验证有效 → 写入docs/
- **框架简化**: 复杂度↑但质量→ → 触发删减

### 7b. 引导词审计 (递归核心)

**对 `docs/tier3_guide_prompt.md` 中每条规则进行效力审计。**

逐条回答:

```
规则 R{N}: {规则名称}
├── 本次报告中是否触发? [是/否]
├── 如果触发: 是否有效防止了预期的错误? [是/部分/否]
├── 如果未触发: 是否因为场景不适用还是被忽略?
├── 效力判定: [有效/部分有效/失效/未触发]
└── 建议: [保持/重写/拆分/合并/删除/新增子规则]
```

**输出**: 更新 `tier3_guide_prompt.md` 的"规则效力追踪"表。

**新规则提炼**: 如果本报告发现了引导词未覆盖的错误模式:
1. 提炼为新规则 R{N+1}
2. 写明来源报告和具体场景
3. 效力标记为"待验证"
4. 插入到引导词的对应章节

### 7c. 元反思: 反思系统自审

**反思系统本身也是可迭代组件。** 回答以下问题:

1. **Phase R1-R8的流程是否有效?** 哪些Phase产出了最有价值的发现? 哪些Phase是走过场?
2. **12个语义维度(S1-S12)是否完整?** 是否遗漏了重要维度? 是否有维度实质重复?
3. **反思时间分配是否合理?** 哪些Phase耗时多但产出少?
4. **多Agent架构是否比单Agent反思更有效?** (如果使用了)
5. **本引导词(`post_report_reflection_prompt.md`)需要修改什么?**

**输出**: 如有改进建议，直接更新本文件并在版本历史中记录。

## 质量锚点: 什么算好的反思?

### 好的反思特征:
- **具体**: "S2评分2/5因为Phase 1没有解构管理层的'30%增长'叙事" (不是"分析深度不够")
- **可执行**: "下次在Phase 1加入管理层叙事验证步骤" (不是"需要更深入")
- **诚实**: 承认4.5/5的报告也有改进空间，承认3.0/5的报告也有亮点
- **连接**: 将本报告教训与历史报告教训关联 (是否重复犯错?)

### 差的反思特征:
- **空泛**: "报告质量良好，分析全面" — 这不是反思，这是自我安慰
- **只看好的**: 只列亮点不列问题 — 这不是审计，这是公关
- **无根因**: "红队效果不好" — 为什么不好? 是方法问题还是执行问题?
- **无行动**: 发现了问题但没有提出改进方案
