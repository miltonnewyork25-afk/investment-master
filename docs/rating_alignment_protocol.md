# Rating Alignment Protocol v1.0

> 跨报告评级校准协议 — 确保同行业报告评级的横向可比性

## 问题定义

28份报告使用相同的4级评级体系(深度关注/关注/中性关注/审慎关注)，但各报告独立产出评级，缺乏横向校准。这导致：
- 同行业内高P/E获高评级 vs 低P/E获低评级的潜在矛盾
- 早期框架(v8-v12)与成熟框架(v15-v17)的方法论差异未标注
- 报告老化后评级时效性不明

## 校准机制

### 1. 校准触发器

| 触发场景 | 动作 |
|----------|------|
| 同行业新报告完成后 | `bash scripts/rating_calibration.sh --industry {行业}` |
| 跨行业重大事件(衰退/利率变化) | `bash scripts/rating_calibration.sh` 全量扫描 |
| 季度定期审查 | 每季度末运行全量校准 |

### 2. 评级有效期

| 报告类型 | 有效期 | 说明 |
|----------|--------|------|
| Tier 3完整报告 | 至下一个年报+1月 | 基于年报数据，有效至新年报消化期后 |
| Tier 2标准分析 | 6个月 | 半年后数据基础可能过时 |
| Tier 1快速扫描 | 3个月 | 仅供即时参考 |

过期报告评级仍可参考，但在校准对比中标注"过期"，不作为评级一致性判断的硬锚点。

### 3. 框架版本可比性

| 框架版本 | 方法论特征 | 可比性 |
|----------|-----------|--------|
| v8-v10 | 早期框架，无A-Score/SGI/CQ体系 | 低 — 评级方法不同，仅作定性参考 |
| v11-v14 | 过渡期，部分引入结构化评级 | 中 — 评级逻辑趋近但工具不同 |
| v15-v17 | 成熟框架，A-Score/SGI/CQ/红队完整 | 高 — 可直接横向对比 |

**原则**: 不追溯修改历史报告评级。早期报告标注框架版本即可。

### 4. 异常解释义务

当校准脚本检测到同行业内评级异常时(高P/E获更好评级)，新报告必须在"估值对比"章节解释原因。

**合理异常示例**:
- IHG(PE 29x, 关注) vs RCL(PE 20x, 中性关注): IHG为资产轻特许模型，应享更高P/E；RCL为重资产邮轮，行业周期性更强
- SOFI(PE 48x, 关注) vs TSM(PE 22x, 中性关注): SOFI为高增长金融科技(不同行业)，两者不直接可比

**不合理异常示例**:
- 同行业、同商业模型、同增速的两只股票，P/E更高者评级更好 → 需重新审视

### 5. 跨行业对比原则

- 不同行业的P/E不直接可比(科技 vs 金融 vs 消费品有不同估值锚点)
- 跨行业对比应使用期望回报(ret)而非P/E
- 期望回报的计算方法在不同框架版本间可能不一致

## 工具

```bash
# 全量校准
bash scripts/rating_calibration.sh

# 按行业校准
bash scripts/rating_calibration.sh --industry 消费品

# 自定义过期阈值(默认90天)
bash scripts/rating_calibration.sh --stale-days 60
```

## 数据要求

L0_index.yaml 每条目必须包含:
- `fw`: 框架版本 (v8/v10/v15/v17等)
- `date`: 报告日期 (YYYY-MM-DD)
- `pe`: 报告时P/E (用于异常检测)
