## 零、v1.0→v2.0升级的诚实反思

### ADBE实战暴露的7个框架缺陷

| # | 缺陷 | 表现 | 影响 | v2.0修复 |
|---|------|------|------|---------|
| **1** | **评分主观性未消除** | v1.0说"分析师判断打分"→v1.1加了FVF→但FVF的"验证通过/不通过"本身仍是判断 | 两个分析师可能对同一维度打出±2分差异→净影响±0.5 | 引入**锚定评分法**(每个分数必须对应具体可观测指标) |
| **2** | **S和B维度不对称** | 5个S维度 vs 4个B维度→结构性偏向看空(S多一项→加总倾向负面) | v1.0未红队时净影响+1.04→实际应更高 | **增加B5(生态增强)** 使S和B各5项对称 |
| **3** | **缺少管理层维度(M)** | AIAS评估AI对"业务"的影响→但CEO交接这种"管理层"因素对净影响的改变>任何S/B | ADBE CEO交接将AIAS区间从[+0.2,+0.8]→[-0.35,+1.00]→M因素主导了不确定性 | **增加M调整因子**(管理层执行力对AIAS的折扣/溢价) |
| **4** | **衰减系数缺乏锚定** | v1.1的衰减系数(0.3~0.9)由分析师"根据传导步数"估计→无历史校准 | 不同报告的衰减系数不可比→ADBE的×0.5 vs CRM的×0.5含义不同 | **标准化衰减矩阵**(基于传导步数+时间窗口的统一查询表) |
| **5** | **动态权重缺少拐点识别** | v1.1模拟了FY2025→FY2030权重变化→但未识别"AIAS翻转的临界权重" | 不知道"Firefly需要占多大比例才能让AIAS从+0.4→+1.0" | **增加拐点分析**(识别AIAS>+2.0的最低权重组合) |
| **6** | **跨公司可比性弱** | CRM/NOW/ADSK的AIAS"快速预评"质量远低于ADBE→结论不可靠 | "Adobe是唯一PE-AIAS不一致"的发现可能是因为其他公司评估不够深 | **定义"AIAS-Lite"标准评估协议**(快速预评的最低要求) |
| **7** | **分裂体检测阈值固定** | v1.0定义"至少一条≤-5且一条≥+5"→但阈值5是任意选择 | 如果阈值=3→很多公司都是"分裂体"(失去诊断价值) | **分裂体指数**(连续值→而非二元检测) |

### ADBE实战的3个核心成功

1. **"分裂体"概念验证**: CC消费(-7.6) vs Firefly(+9.4)→用单一PE估值必然失真→双引擎SOTP是正确的方法→**分裂体不是理论→是可量化的估值缺陷**
2. **FVF一线验证的价值**: 89%满意率→B1从理论+4→确认+4。Express全面不如Canva→B2从理论+3→下调+2。**FVF让AIAS从"观点"升级为"观点+证据"**
3. **PE-AIAS一致性检验**: NOW/ADSK的PE与AIAS一致→但ADBE不一致→**这个"异常检测"本身就是投资洞见的来源**

## 一、v2.0框架结构

### 1.1 维度体系升级 (5S + 5B + M调整)

| 类型 | 维度 | v1.0→v2.0变化 | 评分范围 |
|------|------|-------------|---------|
| **S1** | 功能替代 | 不变 | 0~-5 |
| **S2** | 座位压缩 | 不变 | 0~-5 |
| **S3** | 工作流绕过 | 不变 | 0~-5 |
| **S4** | 低端颠覆 | 不变 | 0~-5 |
| **S5** | 平台脱媒 | 不变 | 0~-5 |
| **B1** | 功能增强 | 不变 | 0~+5 |
| **B2** | TAM扩张 | 不变 | 0~+5 |
| **B3** | 基础设施化 | 不变 | 0~+5 |
| **B4** | 信任溢价 | 不变 | 0~+5 |
| **B5** | **生态增强(新增)** | AI增强公司的生态系统/平台效应 | 0~+5 |
| **M** | **管理层调整因子(新增)** | 管理层对AI转型的执行力折扣/溢价 | ×0.5~×1.5 |

### B5: 生态增强 (Ecosystem Enhancement) — v2.0新增

**定义**: AI让公司的生态系统/第三方集成/平台效应变得更强——超越了对单一产品的影响。

**传导机制**:
```
AI降低第三方开发成本 → 更多插件/集成/应用围绕平台构建
→ 平台价值↑ → 用户因生态锁定留下 → 竞品更难撬动用户
```

**为什么需要B5？** ADBE实战中发现: Adobe的"模型超市"策略(PS内集成Gemini/FLUX/Runway)创造了一种v1.0框架未捕获的价值——**不是产品本身变强(B1)→而是平台变成了"AI模型的聚合器"**。类似iOS App Store让iPhone更有价值→模型超市让PS更有价值。这个效应不属于B1(功能增强→是产品层面)也不属于B3(基础设施化→是API层面)→需要独立维度。

**评分标准(0-5)**:

| 分数 | 描述 | 代表 |
|------|------|------|
| 0 | AI不增强生态系统 | 独立工具(无生态) |
| 1 | AI增加<5个新集成/插件 | 边缘生态 |
| 2 | AI增加10-50个新集成→生态明显增强 | Adobe模型超市(25+模型) |
| 3 | AI创造了新的第三方开发者平台 | Salesforce Einstein生态 |
| 4 | AI让生态系统产生飞轮效应(更多数据→更好AI→更多用户→更多数据) | CRM CDP+Einstein |
| 5 | AI让公司成为行业AI基础设施(类似AWS对云) | NOW的AI workflow平台 |

**ADBE B5预评**: 2.5 (模型超市25+模型+API生态在建→但不是平台级飞轮)
**CRM B5预评**: 3.5 (Einstein+AppExchange+CDP数据飞轮→接近平台级)

### M: 管理层调整因子 — v2.0新增

**定义**: 管理层对AI战略的执行力→对AIAS净影响的折扣(执行差→打折)或溢价(执行优→加成)。

**为什么需要M？** ADBE实战的最大教训: **CEO交接将AIAS区间从[+0.2,+0.8]扩展到[-0.35,+1.00]→管理层因素比任何S/B维度的影响都大**。v1.0/v1.1完全忽视了这个维度→导致AIAS给出的是"业务层面的AI影响"→但实际上"谁来执行"决定了影响是正是负。

**M的评分(×0.5~×1.5)**:

| M值 | 含义 | 典型情况 |
|-----|------|---------|
| ×0.5 | 执行力极差→AIAS正面打5折 | CEO反AI/方向错误/组织僵化(IBM Watson时代) |
| ×0.7 | 执行力差→正面打7折 | CEO理解AI但执行缓慢(Oracle) |
| ×0.85 | 执行力一般→轻微折扣 | CEO在位但AI战略模糊(Adobe CEO交接中) |
| ×1.0 | 执行力合格→不调整 | 默认值(管理层稳定+方向明确) |
| ×1.15 | 执行力好→轻微溢价 | CEO有AI背景+已证明执行力(Salesforce Benioff) |
| ×1.3 | 执行力优秀→显著溢价 | CEO是AI转型典范(Microsoft Nadella) |
| ×1.5 | 执行力卓越→最大溢价 | CEO创造了新的AI范式(极罕见) |

**ADBE M评估**: ×0.85 (CEO交接中→方向不确定→但GenStudio/Firefly团队在位且执行中)
→ AIAS v1.1净影响+0.60 × M(0.85) = **+0.51** (vs红队后+0.42→接近→验证M因子的校准合理)

**CRM M预评**: ×1.05 (Benioff在位→AI战略明确(Agentforce)+但Einstein变现历史参差)

### 1.2 标准化衰减矩阵 (v2.0新增)

v1.1的衰减系数由分析师估计(ADBE的S1衰减=0.4, S2=0.5等)→不同报告间不可比。v2.0定义**标准化衰减查询表**:

| 传导步数 | 时间窗口<12月 | 12-24月 | 24-48月 | >48月 |
|----------|-------------|---------|---------|-------|
| **1步(直接)** | ×0.9 | ×0.8 | ×0.7 | ×0.5 |
| **2步(一阶间接)** | ×0.7 | ×0.6 | ×0.5 | ×0.3 |
| **3步(二阶间接)** | ×0.5 | ×0.4 | ×0.3 | ×0.2 |
| **4步+(高阶)** | ×0.3 | ×0.2 | ×0.15 | ×0.1 |

**使用方法**:
1. 确定每个S/B维度的传导步数(从AI触发→到影响该业务线的因果链长度)
2. 确定时间窗口(该影响在多久后显现)
3. 查表得到衰减系数
4. 衰减后评分 = 原始评分 × 衰减系数

**ADBE校准验证**:
- S1(CC专业)→传导1步(AI直接替代PS功能)+时间>48月→衰减×0.5→v1.1用的×0.4→**接近→v2.0的×0.5略高→更保守→合理**
- S2(CC专业)→传导2步(AI提升效率→企业裁人→seat减少)+时间12-24月→衰减×0.6→v1.1用的×0.5→**v2.0的×0.6略高→差异在合理范围**

### 1.3 分裂体指数 (v2.0新增)

v1.0用二元检测(有/无分裂体)→v2.0改为连续值**分裂体指数(Split Index)**:

```
Split Index = |最负业务线AIAS| + |最正业务线AIAS|
```

| Split Index | 分类 | 估值含义 |
|-------------|------|---------|
| 0-3 | 统一型 | 单一PE估值合理 |
| 3-8 | 轻度分裂 | 建议做SOTP敏感性→但单一PE可接受 |
| 8-15 | 中度分裂 | **必须双引擎SOTP→单一PE显著失真** |
| >15 | 重度分裂 | 公司可能应该考虑分拆→SOTP释放巨大价值 |

**ADBE Split Index**: |-7.6| + |+9.4| = **17.0 (重度分裂)** → 验证了双引擎SOTP的必要性
**CRM Split Index预评**: |-4| + |+5| = **~9 (中度分裂)** → 建议双引擎SOTP

### 1.4 锚定评分法 (v2.0新增)

每个S/B评分必须对应**至少一个可观测指标**→消除主观性。

**模板**:

| 评分 | 必须锚定的可观测指标 | 类型 |
|------|---------------------|------|
| S1=-1 | 替代品覆盖<10%核心用例 | 行业对标(Gartner/G2) |
| S1=-2 | 替代品覆盖10-30%且质量"够用" | 用户调研(FVF) |
| S1=-3 | 替代品覆盖30-60%且质量≥原产品80% | 功能对标+用户满意度 |
| S1=-4 | 替代品覆盖60-80% | 市占率数据 |
| S1=-5 | 替代品覆盖>80%且更便宜/更好 | 收入/seat数据下降确认 |

**CRM-specific锚定示例**:
- S1(功能替代): "ChatGPT/Claude能否完成CRM的核心功能(pipeline管理/联系人管理/预测)？"→锚定于Gartner Peer Insights评分对比
- S2(座位压缩): "AI agent能否替代多少%的SDR(Sales Dev Rep)？"→锚定于Gartner/McKinsey关于AI对销售组织的影响报告
- B3(基础设施化): "Agentforce的API收入占Salesforce总收入多少%？"→锚定于财报数据

## 二、CRM (Salesforce) AIAS预评 v2.0

### 2.1 CRM业务线定义

| 业务线 | FY2025E收入 | 占比 | AI影响方向(预判) |
|--------|-----------|------|----------------|
| Sales Cloud | ~$8.0B | ~23% | **受威胁**(AI agent替代SDR→seat压缩) |
| Service Cloud | ~$9.0B | ~26% | **重度受威胁**(AI客服替代人工→seat大幅压缩) |
| Platform/Other(含MuleSoft/Tableau) | ~$7.5B | ~22% | **受益**(Data Cloud+AI平台化) |

### 2.2 CRM AIAS v2.0预评矩阵

| 业务线 | S1 | S2 | S3 | S4 | S5 | B1 | B2 | B3 | B4 | **B5** | **净** |
|--------|----|----|----|----|----|----|----|----|----|----|-----|
| Sales Cloud | -2 | **-4** | -1 | -2 | -1 | +3 | +1 | +2 | +2 | +2 | **0** |
| Service Cloud | -3 | **-5** | -2 | -3 | -2 | +3 | +1 | +3 | +2 | +2 | **-4** |
| Platform/Data | -1 | -1 | 0 | -1 | 0 | +3 | +3 | **+4** | +3 | **+4** | **+14** |
| Marketing/Commerce | -2 | -2 | -1 | -3 | -1 | +2 | +2 | +2 | +1 | +1 | **-1** |
| Agentforce/Einstein | 0 | 0 | 0 | 0 | 0 | +4 | +4 | **+4** | +3 | +3 | **+18** |
| Slack+Integration | -2 | -1 | -2 | -2 | -1 | +2 | +1 | +1 | +1 | +1 | **-2** |

**公司级净影响(权重加权)**:
= (0×23%) + (-4×26%) + (+14×22%) + (-1×15%) + (+18×3%) + (-2×12%)
= 0 - 1.04 + 3.08 - 0.15 + 0.54 - 0.24 = **+2.19**

**M调整**: ×1.05 (Benioff在位+Agentforce战略明确但Einstein历史执行参差)
**M调整后**: +2.19 × 1.05 = **+2.30**

**CRM Split Index**: |-4(Service)| + |+18(Agentforce)| = **22 (重度分裂)**

### 2.3 CRM vs ADBE AIAS对比

| 维度 | ADBE | CRM | 差异原因 |
|------|------|-----|---------|
| 净影响(M调整后) | +0.51 | +2.30 | CRM的Platform/Agentforce受益更大(B3+B5更高) |
| Split Index | 17 | **22** | CRM的分裂更严重(Service -4 vs Agentforce +18) |
| 最大受害业务 | CC消费(-7.6) | **Service Cloud(-4)** | CRM受害侧"绝对值"小于ADBE→但**收入权重更大(26% vs 19%)** |
| 最大受益业务 | Firefly(+9.4, 1%权重) | **Agentforce(+18, 3%权重)** | 两者都是小基数高分→但CRM的Agentforce更成熟($1B vs $250M) |
| M因子 | ×0.85(CEO交接) | ×1.05(CEO在位) | **CRM的管理层确定性远>ADBE** |
| PE vs AIAS一致性 | **不一致**(PE 9.6x vs应有17x) | **基本一致**(PE 13.5x→AIAS+2.3应有~15-18x) |

### 2.4 CRM调研的核心问题 (AIAS驱动)

基于AIAS预评→CRM调研应聚焦以下问题:

**CQ-1: Service Cloud的seat压缩有多快？**
- S2=-5是全矩阵最极端的评分→需要验证
- 锚定: Gartner关于AI客服替代率的预测+CRM财报中Service Cloud seat增长数据
- 如果S2实际=-3(没那么快)→净影响从+2.3→+2.8(更正面)→当前PE 13.5x更低估

**CQ-2: Agentforce是真的$2B+潜力还是又一个Einstein(雷声大雨点小)？**
- Agentforce B3=+4+B5=+4→如果实际只有B3=+2→净影响从+2.3→+1.7(仍正面但缓冲小)
- 锚定: Agentforce付费客户数+平台开发者数+API收入(vs Einstein的历史轨迹)
- Einstein FY2019-2024的ARR始终模糊→Agentforce是否重蹈覆辙？

**CQ-3: Platform/Data Cloud的生态飞轮是否成立？**
- B5=+4是CRM最关键的评分→Data Cloud+AppExchange+MuleSoft集成→是否真的形成了"更多数据→更好AI→更多用户"的飞轮？
- 锚定: Data Cloud客户数增速+AppExchange AI应用数量+MuleSoft API调用量增速

## 三、AIAS v2.0操作指南

### 3.1 完整AIAS评估的最低要求

| 步骤 | 要求 | 估时 | 产出 |
|------|------|------|------|
| 业务线定义 | ≥4条业务线+收入权重 | 2h | 业务线表 |
| S1-S5评分 | 每个评分≥1个锚定指标(行业报告/财报/用户数据) | 4h | S评分矩阵+锚定证据 |
| B1-B5评分 | 同上 | 4h | B评分矩阵+锚定证据 |
| FVF验证 | ≥3个一线数据源(Gartner/G2/Reddit/行业媒体) | 3h | FVF校准表 |
| 衰减系数 | 使用v2.0标准化衰减矩阵(无需主观估计) | 0.5h | 衰减后评分 |
| M因子评估 | CEO背景+AI战略清晰度+执行track record | 1h | M值 |
| 分裂体指数 | 自动计算 | 0h | Split Index |
| 动态权重 | FY+5年权重模拟+拐点识别 | 1h | 权重变化表+拐点 |
| **合计** | | **15.5h** | |

### 3.2 AIAS-Lite(快速预评)的最低要求

用于跨公司对比(如ADBE报告中对CRM/NOW/ADSK的预评):

| 步骤 | 要求 | 估时 | 产出 |
|------|------|------|------|
| 业务线定义 | ≥3条业务线+收入权重 | 0.5h | 简化业务线表 |
| S/B快速评分 | 每个维度一句话理由(不需要锚定) | 2h | 简化矩阵 |
| 净影响计算 | 权重加权 | 0.5h | 净影响数 |
| **合计** | | **3h** | |

**AIAS-Lite的限制**: 精度±1.5(vs完整AIAS ±0.5)→只能用于"方向判断"(正/负/中性)→不能用于估值。
