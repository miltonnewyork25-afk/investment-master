# 演绎分析方法论 v1.0 — 因果链推演与跨行业传导

> **核心问题**: 归纳法回答"过去发生了什么→未来可能重复"，演绎法回答"如果X发生→必然导致Y→进而改变Z"。
> **适用场景**: AI/自动驾驶/量子计算等范式变革，以及CapEx周期、监管变化等结构性转折。
> **禁止**: 对范式变革公司仅用类比分析("Uber颠覆出租车，所以AI会颠覆X")。

---

## 1. 归纳 vs 演绎：何时用什么

| 维度 | 归纳法 (Inductive) | 演绎法 (Deductive) |
|------|---------------------|---------------------|
| **逻辑方向** | 历史数据→模式→外推 | 前提/触发→因果链→结论 |
| **适用业务** | 成熟稳定业务 (COST会员、KO饮料) | 范式变革、新业务线、结构转折 |
| **优势** | 数据充足、可验证 | 能处理"无历史先例"的情况 |
| **风险** | 对非线性变化失效 | 因果链假设可能错误 |
| **输出** | 增长率外推、均值回归 | 条件情景、传导路径、时间窗口 |

**决策规则**: 如果分析对象满足以下任一条件，**必须启用演绎分析**（可与归纳并行）：
- 业务线<3年历史（无法归纳）
- 行业处于范式转换期（历史模式可能失效）
- 关键驱动因素发生结构性变化（如AI agent出现改变token经济学）
- 跨行业传导效应显著（上游变化重构下游需求）

## 2. 演绎分析六步法

### Step 1: 触发事件识别

明确因果链的起点。触发事件必须是**可观测的结构性变化**，不是模糊趋势。

| 类型 | 示例 | 特征 |
|------|------|------|
| 技术突破 | AI Agent规模化、GAA工艺量产 | 改变成本/性能曲线 |
| 政策变革 | 出口管制升级、碳税实施 | 改变行业约束条件 |
| 需求范式 | Token消耗从对话→Agent自主执行 | 改变需求量级和结构 |
| 资本周期 | CapEx从$10B→$60B的加速 | 改变供给格局和回报率 |

**质量检验**: 触发事件是否有DM锚点级的数据支撑？如果只是"市场预期"，标注为低置信度。

### Step 2: 因果链构建

从触发事件出发，推导每一步的逻辑必然性。

**模板**:
```
触发事件 [数据锚点]
  → 一阶效应: 直接、可量化的影响 [×系数, 时间滞后]
    → 二阶效应: 行业结构变化 [×衰减系数]
      → 三阶效应: 商业模式/竞争格局重构 [条件性]
```

**关键要求**:
- 每个"→"必须有**传导机制**（不是"所以"，而是"通过什么机制"）
- 每个节点标注**衰减/放大系数**（上游$1变化=下游多少$变化？）
- 每个节点标注**时间滞后**（效应何时显现？）

### Step 3: 跨行业传导映射

当因果链跨越行业边界时，必须显式映射传导路径。

**已验证的传导模式**:

| 模式 | 结构 | 实例 |
|------|------|------|
| **需求漏斗衰减** | 终端需求 ×0.8→ 中间需求 ×0.6→ 上游设备 | KLAC: AI需求→GPU→代工→设备(200x衰减) |
| **CapEx→D&A→利润传导** | 投资支出→折旧滞后→利润压缩 | MSFT: $64.6B CapEx→FY29 D&A $72B→OPM -500bps |
| **供应链重构** | 地缘事件→供应链迁移→需求分布变化 | KLAC: 出口管制→友岸外包→多地建厂→设备需求↑但效率↓ |
| **自动化替代** | 技术投资→人力替代→运营成本重构 | AMZN: 物流自动化→-350bps履约成本→$19B/年节省 |

### Step 4: 时间轴标定

因果链不是瞬时发生的。每个节点需要时间窗口。

```
触发(已发生)──→一阶(6-12月)──→二阶(12-24月)──→三阶(24-60月)
     │              │               │               │
  可观测数据     领先指标可验证    滞后指标出现    格局稳定
```

**已验证的时间滞后基准**:
- CapEx→D&A显现: 3-5年 (MSFT)
- CapEx→收入转化: 12-18月 (ORCL/AMZN)
- GPU部署→云收入增长: 6-12月 (AWS/Azure)
- 自动化投资→OpEx节省: 18-24月 (AMZN)

### Step 5: 证伪条件设定

每条因果链必须附带**可观测的证伪条件**。

**模板**:
```
因果链: A → B → C
证伪条件:
  - 如果A发生但B在[时间窗口]内未出现 → 传导机制可能错误
  - 如果B出现但系数<预期的50% → 衰减超预期
  - 如果出现替代路径D绕过B直接到C → 因果模型需重构
```

### Step 6: 与归纳基准对比

最后一步：演绎分析的结论和归纳外推的差异有多大？

| 对比项 | 归纳外推 | 演绎推导 | 差异 |
|--------|---------|---------|------|
| FY2028收入 | $XXB (CAGR外推) | $YYB (因果链推算) | ±Z% |
| 利润率 | XX% (历史均值回归) | YY% (结构性变化) | ±Wbps |

**差异>20%时**: 必须在报告中显式讨论，说明"哪个假设驱动了分歧"。

## 4. 当前最重要的演绎问题（待分析）

以下是当前市场最值得用演绎法分析的因果链，可在未来报告中展开：

```
AI Agent规模化部署 [触发: 2025-2026]
  → Token消耗模式变化: 对话式(短突发) → Agent式(长链持续) [×5-20x token/task]
    → 推理计算需求重构: GPU从训练为主→推理为主 [NVDA产品路线图验证]
      → 数据中心架构变化: 功耗/散热/网络带宽重新配置

          → 设备厂商受益差异化: KLAC(检测) vs AMAT(沉积) vs LRCX(刻蚀)
```

**自动驾驶 → 城市经济重构**:
```
L4自动驾驶商业化 [触发: 时间不确定]
  → 出行成本下降50-70%
    → 私人车辆拥有率↓ → 汽车销量↓但利用率↑
      → 保险模式重构: 个人保险→车队保险
        → 停车需求↓ → 城市土地用途重构

```

## 5. 使用指南

**Phase 0**: 判断是否需要演绎分析（看决策规则）
**Phase 1**: 识别1-2条核心因果链，构建传导图
**Phase 2**: 量化每个节点的系数和时间滞后
**Phase 3**: 与归纳基准对比，标注分歧点
**Phase 4**: 红队检验因果链（承重墙测试：哪个节点断裂→整链失效？）
**Phase 5**: 将因果链结论纳入情景概率分配

**与现有skill的关系**:
- `/assumption-audit` M1信念反演: 验证因果链各节点是否站得住
- `/red-team-suite` RT-1承重墙: 测试因果链最脆弱的环节
- `/risk-topology`: 映射因果链的风险传导网络
