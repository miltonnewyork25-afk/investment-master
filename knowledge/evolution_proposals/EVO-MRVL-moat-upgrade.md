# EVO-MRVL: 护城河框架升级提案 — 源自MRVL v2.0深度研究

> **触发**: MRVL v2.0暴露3个框架盲区 + 1个机制缺失
> **日期**: 2026-03-30
> **影响范围**: 所有多业务线公司(AVGO/AMD/GOOG/META/MRVL等) + 所有IP依赖公司

---

## 盲区诊断

MRVL的护城河评估揭示了一个根本问题: **CQI给每家公司一个数字, 但MRVL的光学DSP(7.5/10)和Custom Silicon(3.0/10)是完全不同的护城河性质**。用加权均值5.0/10描述这种异质性——就像用"平均体温36.5℃"描述一个左手在冰水里、右手在火上的人。

现有框架对此的处理:
- C1-C8: 逐维度评分, 但**每个C只有一个公司级数字**, 不区分业务线
- D4趋势T: 捕捉公司级方向, 但不解释**为什么方向在变**(mix shift机制)
- C7自维持性: 衡量护城河是否需要持续投入, 但**不区分每个业务线的维持性不同**
- moat_v3.1: 有"衰减"概念, 但**没有数学化——只有定性描述**

## 4个EVO提案

### EVO-MRVL-001: 护城河离散度指标 (Moat Dispersion Index, MDI)

**问题**: CQI单一数字掩盖业务线间的护城河异质性。MRVL护城河离散度4.5点(7.5-3.0), 但CQI只显示5.0。

**提案**: 在CQI评分卡中新增**MDI(Moat Dispersion Index)**:
```
MDI = max(业务线护城河) - min(业务线护城河)

判定:
  MDI < 2.0: 低离散(同质型) → CQI单一数字有效
  MDI 2.0-3.5: 中离散(混合型) → CQI有效但需标注
  MDI > 3.5: ★高离散(异质型) → CQI单一数字**失效** → 必须分部评分+SOTP估值
```

**触发动作**: MDI>3.5时:
1. CQI评分卡标注"⚠️ 高护城河离散——单一CQI不具代表性"
2. 强制输出分业务护城河评分(类似MRVL的分部C1-C6表)
3. 估值框架强制使用SOTP(不允许单一PE)

**优先级**: P0 (影响所有多业务线公司)

**影响评估**:
| 公司 | MDI(估) | 触发? | 含义 |
|------|--------|-------|------|
| **MRVL** | **4.5** | ✅ 高离散 | CQI 5.0失效, 必须SOTP |
| AVGO | 3.0 | ⚠️ 中离散 | Semi(8.2) vs VMware(不同性质, 但都强) |
| GOOG | 4.0+ | ✅ 高离散 | Search(9+) vs Cloud(5) vs Waymo(2) |
| META | 3.5 | ⚠️ 中离散 | FB/IG(8) vs Metaverse(2-3) |
| AMD | 2.5 | ⚠️ 中离散 | GPU(6) vs CPU(4) vs embedded(3) |
| NVDA | 1.5 | ❌ 低离散 | GPU+CUDA生态一致性强 |
| KLAC | 1.0 | ❌ 低离散 | 检测设备同质 |

**验证**: MRVL(4.5) + GOOG(4.0+) + META(3.5) — 3家以上验证, 且直觉上这3家确实不应用单一PE估值。

### EVO-MRVL-002: C1锁定动态方向标注 (Lock-in Directionality Tag)

**问题**: C1评分是静态快照。MRVL光学DSP的C1在**递增**(代际兼容性每代更强), Custom Silicon的C1在**衰减**(每代重新竞标)。同样C1=5分, 一个在变强一个在变弱——但CQI看不出。

**提案**: C1评分增加**方向标签**:
```
C1标注格式: C1 = X / 方向标签

方向标签:
  ↑↑ 强递增: 每代/每年客户锁定加深(代际兼容/数据积累/网络效应增强)
  ↑  弱递增: 锁定缓慢加深, 速度<递增型
  →  稳定: 锁定度不变
  ↓  弱衰减: 锁定缓慢减弱(竞品追赶/IP到期)
  ↓↓ 强衰减: 每代/每合同期锁定显著减弱(竞标机制/IP可许可)
```

**与D4趋势T的区别**: D4是**公司级**方向(涵盖所有维度), C1方向是**维度级**方向(仅C1)。D4=→(公司整体稳定)但C1光学=↑↑+C1 ASIC=↓↓完全可能(MRVL就是这样)。

**触发动作**: 当同一公司不同业务线C1方向相反(一个↑一个↓)→标注"C1方向分裂"→MDI检测自动触发。

**优先级**: P1 (C1是权重最高的护城河维度)

**MRVL验证**:
- 光学DSP C1=8.5/↑↑(代际兼容→递增锁定)
- Custom Silicon C1=3.5/↓↓(竞标机制→衰减锁定, L(t)函数已建模)
- Standard Networking C1=5.5/→(稳定, 惯性锁定)

**跨公司验证**:
- NVDA CUDA C1=9/↑↑(开发者生态递增)
- AVGO Google TPU C1=8/→(独家关系稳定)
- ARM C1=7/↓(RISC-V替代方案增长→弱衰减)
- INTC C1=2/↓↓(失去制程领先→客户快速流失)

### EVO-MRVL-003: IP可许可性降级规则 (IP Licensability Cap)

**问题**: 框架假设自研IP(如MRVL SerDes)是强护城河(C3/C6高分)。但MRVL发现: Trainium 3的PCIe SerDes来自Synopsys IP许可——意味着"10年研发积累"可以被"$10-30M许可费"替代。C3/C6应该有"可许可性检查"。

**提案**: C3和C6评分增加**IP可许可性检查**:
```
评分时增加一个检查步骤:

问: 公司的核心IP是否可以从第三方(Synopsys/Cadence/ARM等)许可?
  是 → C3/C6分数 cap at 3.0(因为竞争者可以用许可获得等价IP)
  部分可(核心不可, 辅助可) → C3/C6分数 cap at 4.0
  否(完全独占, 无许可替代) → C3/C6分数不受限

例:
  NVDA CUDA: 无法许可 → C3不受限 → C3=5
  MRVL SerDes: Synopsys/Cadence有等价IP许可 → C3 cap 3.0 → C3从5降至3
  ARM架构: ARM自己就是许可方 → C3=5(许可方≠被许可方)
  ASML EUV: 无替代 → C6不受限 → C6=5
```

**优先级**: P1 (影响所有IP依赖型公司的护城河评估)

**MRVL验证**: P3发现SerDes可被Synopsys许可 [DM-P3-006, DM-P3-009]→直接导致Custom Silicon C3从6降至5(P3已做)。如果应用IP licensability cap→C3应进一步降至3→Custom Silicon护城河从4.0降至3.5。

**跨公司影响评估**:
| 公司 | 核心IP | 可许可? | C3当前 | C3修正 | CQI影响 |
|------|--------|--------|--------|--------|--------|
| NVDA | CUDA | ❌ 独占 | 5 | 5(不变) | 0 |
| MRVL | SerDes | ✅ Synopsys替代 | 5 | **3(-2)** | -3~-5 |
| ARM | 架构IP | 许可方(不适用) | 5 | 5 | 0 |
| AVGO | ASIC设计 | 部分(Cadence IP) | 4 | 4(不变) | 0 |
| KLAC | 检测算法 | ❌ 独占 | 5 | 5 | 0 |
| ASML | EUV光刻 | ❌ 独占 | 5 | 5 | 0 |

影响范围有限(主要影响fabless ASIC/IP公司)——但在这些公司中影响显著。

### EVO-MRVL-004: 增长侵蚀护城河预警 (Growth-Moat Dilution Warning)

**问题**: MRVL增速+42%但加权护城河从5.3降至5.0——因为增长主要来自护城河最弱的业务(Custom Silicon 3.0)。这是一个**反直觉**的模式: 增长越快, 护城河越弱。

**提案**: 不新增因子, 但在CQI评分流程中增加**检查步骤**:
```
增长侵蚀护城河检查:

1. 识别增速最快的业务线(>公司平均增速的1.5倍)
2. 该业务线的护城河评分是否低于公司加权均值?
   是 → 触发"增长侵蚀护城河"预警
   否 → 通过(增长在强化护城河)

3. 如果触发预警:
   - 计算FY2028E加权护城河(用FY2028收入权重)
   - 如果FY2028E加权 < FY当前加权 > 0.5点 → 标注"护城河衰减中(mix shift)"
   - 要求D4趋势T至少降一档(如→降至↘)

预警标注:
  "⚠️ 增长侵蚀护城河: 增速最快的[业务线](+X%)的护城河(Y/10)低于公司均值(Z/10)。
   FY2028E加权护城河可能从Z降至W。"
```

**优先级**: P2 (预警而非评分因子, 影响较间接)

**MRVL验证**: Custom Silicon增速+100%(最快) + 护城河3.0(低于均值5.0)→触发。FY2028E加权护城河从5.3→5.0(确认衰减)。

**跨公司验证(需要)**:
- GOOG Cloud: 增速>30% + 护城河~5/10(低于Search的9+) → 可能触发
- META Metaverse: 增速高(从低基数) + 护城河~2/10 → 可能触发
- AVGO AI ASIC: 增速>50% + 护城河~8/10(高于均值) → **不触发**(增长在强化护城河)
