# P4.5 参考扫描模块 v1.0

> **位置**: Phase 4完成后 → **P4.5扫描** → Phase 5组装
> **设计原理**: P0阶段对公司理解浅→参考匹配粗糙。P4完成后AI已深度理解公司→此时匹配参考报告精度10倍于P0→能精准找到"这个分析维度别的报告怎么做的"而非"同行业报告长什么样"
> **解决问题**: 组装时字符/维度不足 → 禁止凑备注/注释/空洞补充 → 改为借鉴已验证的分析视角重新写实质内容
> **来源**: CRM v2.0组装经验 + FRO/COSCO审计发现 + 用户反馈

---

## 一、为什么P4.5比P0更精准

| | P0参考扫描 | **P4.5参考扫描** |
|---|---|---|
| 公司理解 | 初步(行业+基本面) | **深度(护城河/风险/估值全知)** |
| 匹配维度 | "同行业" | **"同分析挑战"** |
| 参考质量 | 可能选错报告 | **精准匹配最相关章节** |
| 补充方向 | 猜测可能缺什么 | **确切知道缺什么** |
| 典型产出 | "参考KLAC的估值框架" | "Ch14护城河迁移可借鉴ARM CDS弹性函数的连续定价权量化方法" |

## 二、触发条件

**必须触发**:
- Phase 4(红队)完成后
- 且发现以下任一情况:
  1. 报告总字符 < 目标的80%
  2. D10覆盖检查有≥2项未覆盖
  3. 某个分析维度(D1-D10)预估<3.5
  4. 红队发现的缺口在Phase 1-3产出中无法直接修补

**可选触发**:
- 任何时候AI感觉"这个维度分析偏浅但不知道怎么加深"

## 三、执行流程 (3步)

### Step 1: 缺口诊断 (5分钟)

Phase 4完成后，AI列出:

```
当前缺口清单:
□ D2竞争格局: 只有3个竞品，缺第4-5个的深度对比
□ D3护城河: C2网络效应分析偏浅，只有定性没有量化
□ D7原创洞见: 只有2个CI，目标≥3个
□ D8可视化: Mermaid仅12个，多数是简单流程图
□ 总字符: 当前staging合计180K，目标270K
```

### Step 2: 精准参考匹配 (10分钟)

**不是找"同行业报告"，而是找"同分析挑战报告"**。

基于P4后的理解，AI执行:

```bash
# 先看知识索引
bash scripts/find_relevant_knowledge.sh {TICKER} {INDUSTRY}

# 然后在excellence_catalog中搜索同类冠军
grep -i "网络效应\|network\|定价权\|pricing" knowledge/excellence_catalog.yaml
```

**匹配逻辑** (按优先级):

| 优先级 | 匹配维度 | 示例 |
|:------:|---------|------|
| 1 | **同分析挑战** | "飞轮真实性评估"→找MCO Ch6.2 |
| 2 | **同护城河类型** | "C1制度嵌入"→找FICO/MCO/SPGI |
| 3 | **同估值困境** | "PE>30x周期股"→找MCO/HLT |
| 4 | **同行业** | 传统P0匹配 |
| 5 | **同质量标杆** | 目标4.5→找KLAC方法 |

**P4.5 vs P0的精度差异示例**:

分析PTC时:
- P0: "PTC是工业软件→找ADBE(也是软件)" → 匹配中等
- P4.5: "PTC的PLM→IoT飞轮需要验证" → **找MCO飞轮+摩擦力模块** → 精准匹配
- P4.5: "PTC的perpetual→SaaS转型对留存率的影响" → **找CRM定价权剪刀差** → 精准匹配
- P4.5: "PTC PE 28x但有制造业CapEx周期暴露" → **找MCO周期暴露模块** → 精准匹配

### Step 3: 借鉴写实质内容 (主要时间)

**严格禁止**:
- ❌ 补备注/注释/免责声明来凑字数
- ❌ 把已有结论换个说法重复一遍
- ❌ 添加"未来有待观察"等空洞内容
- ❌ 插入与估值无关的背景介绍

**必须做的**:
- ✅ 从参考报告借鉴**分析方法**(不是结论)
- ✅ 用本公司数据重新跑参考报告的分析框架
- ✅ 每个新增内容必须包含: 数据(DM)+因果推理+反面
- ✅ 新增内容必须改变或加强至少1个估值假设

**产出标准**: 每个借鉴模块产出≥3K字符的实质分析(不是1段介绍)

## 四、产出格式

P4.5的产出是一个**补充任务清单**，嵌入Phase 5组装:

```markdown
## P4.5 参考扫描结果

### 缺口→参考→补充计划

| 缺口 | 参考源 | 借鉴什么 | 预计字符 | 影响哪个D |
|------|--------|---------|:--------:|:--------:|
| 飞轮验证不足 | MCO Ch6.2 飞轮+摩擦力 | 力vs摩擦双向评估方法 | 5K | D3+D7 |
| 周期PE未调整 | MCO Ch2.4 周期暴露 | ABC收入拆解+经营杠杆 | 3K | D5 |
| 回购效率缺失 | MCO/HLT η模块 | eta计算+5信号检测 | 3K | D4 |
| 竞品深度不足 | ADBE Ch竞争 | Canva commoditize分析 | 4K | D2 |

### 严禁清单
- □ 不添加无DM的备注
- □ 不重复已有结论
- □ 不用"有待观察"凑段落
- □ 每个新增内容≥1个DM+1个因果链
```

## 六、analysis_modules的角色

`knowledge/analysis_modules/`目录下的通用模块是P4.5扫描的**第一搜索源**:

| 模块 | 何时被P4.5匹配 |
|------|-------------|
| `buyback_efficiency_module.md` | 公司有回购行为 |
| `flywheel_with_friction_module.md` | 管理层有飞轮叙事 |
| `cycle_exposure_module.md` | PE>20x+周期收入 |
| (未来更多模块) | 随报告积累增长 |

**模块增长飞轮**:
每份新报告完成 → 提炼可泛化的分析视角 → 写入analysis_modules → 下份报告P4.5扫描时发现 → 更好的分析 → 更多模块 → ...

这才是真正的飞轮——每份报告都让下一份更好。
