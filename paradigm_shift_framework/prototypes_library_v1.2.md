## 13 Alpha Type Prototypes (v0.4)

### P-1. Value-Capturing Operator

**条件**: M5 ≥ L3 + M6 ≥5/7 + M11 Tier 4+ + M12 strong + M13 strong

**核心特征**: 同时通过五道闸门 (M2 时钟 + M5 写入 + M11 责任 + M12 归因 + M13 捕获)

**估值语言**: Authority + responsibility premium (PE 32-40x), SOTP 主体 + 弱业务折让

**Anchor**: INTU (TurboTax Live + QBO + Payroll, FY25 \$2B Live revenue +47%)

**通常路径**: 数据飞轮 + 责任承担 + 行业语义 + 默认入口 → 客户付费买"金融/合规/法务确定性"

**Kill 信号**: 监管端冲击 (Direct File 类) / 政策端 / 责任理赔事件 / 银行/支付生态 bundling

---

### P-2. Closed-Loop Operator

**条件**: M6 ≥5/7 + M5 ≥L2

**核心特征**: 真闭环 (sense+state+decide+execute+feedback+correct+rollback) + 中等责任转移

**估值语言**: Industrial control-layer PEG 1.0-1.2 + FCF, 可加期权溢价

**Anchor**: PTC (CAD+PLM+ALM+SLM, BMW Codebeamer enterprise wins, ARR cc +8.5%)

**通常路径**: 工业 / 受监管制造 / 长生命周期 → governance + traceability + audit log

**Kill 信号**: 大型客户自建 / 老牌 incumbent (Siemens/Dassault) 全链条挤压 / 实施周期过长

---

### P-3. State Machine Owner

**条件**: M4 strong + M5 L2+ + M3 control-variable quality

**核心特征**: 控制业务对象状态机, 数据已是控制变量

**估值语言**: 同 P-2 + 语义权溢价

**Anchor**: PTC Windchill / Codebeamer

---

### P-4. Semantic Layer Definer

**条件**: M4 ≥15/20 (cross-customer 语义层 / 行业操作语言候选)

**核心特征**: 定义 object / state-machine / permission / interface / audit / rollback 规则

**估值语言**: 用 SaaS multiple + 语义权溢价 (5-10% premium)

**Anchor**: ADSK (.dwg/.rvt) / PTC Windchill / INTU (chart of accounts + tax category)

**风险**: AI 时代如果 generative-era 语义不在公司手里 (例 ADBE Photoshop 老语义 vs prompt/latent 新语义), 语义权可能被分割

---

### P-5. Liability-Backed Operator

**条件**: M11 Tier 4+ + M7 ≥4 + M8 P3+

**核心特征**: 真承担 outcome 责任 + AI L4+ + 财报已显示 outcome 收入

**估值语言**: P-1 子集, 加责任溢价

**Anchor**: INTU TurboTax 业务线 (\$100K accuracy guarantee + IRS 审计接受)

---

### P-6. Attribution-Backed Vendor

**条件**: M12 strong + M8 P2+ + M11 below Tier 4

**核心特征**: 客户能归因, 但 vendor 还没承担 outcome 责任 → outcome pricing 路径开放但未走完

**估值语言**: Workflow Operator 倍数 (25-30x), 加期权打折 (按 P 档位概率加权)

**Anchor**: 理论候选 (没有完美 v0.4 锚)

---

### P-7. Accountability-Thin Operator

**条件**: M7 high + M11 weak

**核心特征**: AI 等级看起来很高, 但责任弱 / 不可转移 → 不能 outcome pricing

**估值语言**: AI Copilot 增强倍数 (15-22x), 不能给第二曲线溢价

**Anchor**: ADBE Firefly (单独, AI L2-L3 但 Tier 1-2)

---

### P-8. Pricing-Stuck Vendor

**条件**: M5 L0-L1 + M8 P0-P1

**核心特征**: 写入权浅 + 没有付费证据 → 仍是 seat / subscription, AI 不能升级收费

**估值语言**: 老 SaaS / Pricing-Stuck 倍数 (15-18x)

**Anchor**: ADBE Creative Consumer / Express (被 Canva + 大模型分流)

---

### P-9. Burden-Trapped SaaS

**条件**: M9 burden + M7 ≤2

**核心特征**: 复杂度是负担 (PS 占比上升, 实施周期延长, NRR 持平), AI 没改变

**估值语言**: PE 12-15x, 估值压缩长期

**Anchor**: 历史 ERP / 老牌实施重 SaaS (无 v0.4 直接锚)

---

### P-10. Stack Coherence Winner

**条件**: M10 五门 mostly strong + M13 strong

**核心特征**: 五道门控 4-5 道占领 + 价值主要留在公司

**估值语言**: 高 SaaS 倍数 + 复利溢价

**Anchor**: INTU (5/5 五门强 + 价值留住)

---

### P-11. Mixed Profile

**条件**: 没有主导 subtype

**估值语言**: 按基本面打分, 不给 AI 第二曲线溢价

---

### P-12. Split Entity (NEW v0.4)

**条件**: 公司在不同业务线有 ≥3 个发散的 M11/M12/M13, 且不同业务线 Tier 差异 ≥1 档

**核心特征**: 多业务线分裂 — 一部分是 Pricing-Stuck Vendor, 另一部分可能是 Workflow Default 或 Semantic Layer Definer

**估值强制规则**:
- **必须 SOTP**, 不允许整体 100 分制单一打分
- 必须输出 ≥3 子评分 (每个业务线独立打)
- 估值语言必须分叉 (不同业务线用不同倍数)

**Anchor**: ADBE (Creative Consumer 下行 vs Document/GenStudio/Foundry/CX Enterprise/AEP 进攻)

**子评分例 (ADBE)**:
| 业务线 | AI 第二曲线分 | 估值倍数 |
|---|---:|---|
| Creative Cloud Pro | 中等 | 22-25x |
| Express / Consumer | 偏弱 | 15-18x (Pricing-Stuck) |
| Document Cloud | 中强 | 25-28x (Workflow Operator) |
| GenStudio + CX Enterprise | 期权强但证据不足 | 期权打折 (按 P2 概率加权) |

**关键风险**: 把 Split Entity 当统一资产估值会同时低估和高估某些业务线。

---

### P-13. Platform Migration Candidate (NEW v0.4)

**条件**: M14 ≥3 (Marketplace 上线) + 平台路径成为关键期权

**核心特征**: 公司在从 seat-based 向 platform-based 迁移中 — Marketplace + API + MCP 是真路径, 但还没 P3 财务化

**估值强制规则**:
- M14 评分必须显示 (期权加分 0-5)
- 必须输出 R-ABSTRACT 风险评估 (是否被抽象成后端)
- 监控指标必须含 Marketplace usage / take-rate revenue / 第三方 agent 数

**Anchor**: ADSK (APS + MCP + Design and Make Marketplace + Revit Assistant Tech Preview)

**估值语言**: 平台经济期权打折 (按 M14 评分 × P 档位概率加权)
- M14 = 3 + P1-P2 → 期权值 = 平台 fully-realized value × 30-40%
- M14 = 4 + P2 → 期权值 = 平台 fully-realized value × 50-60%
- M14 = 5 + P3 → 期权值 = 平台 fully-realized value × 80-90%

**关键风险 (R-ABSTRACT)**: 如果第三方 agent 通过 API 完成 80%+ 用户操作 → 用户不再进公司 UI → 公司沦为后端 data provider, seat 经济崩塌。

**R-ABSTRACT 监控信号**:
- 第三方 agent 数 / 用户活跃度比 (越高越危险)
- API call / 用户登录 UI 比 (>10:1 是警告)
- Marketplace 第三方 revenue / 公司直接 revenue 比

## 多原型混合 (Composite Profile)

实际公司常常是多个原型组合, 例如:

| 公司 | 原型组合 |
|---|---|
| INTU | P-1 Value-Capturing Operator + P-5 Liability-Backed (TurboTax 业务线) + P-10 Stack Coherence Winner |
| PTC | P-2 Closed-Loop Operator + P-3 State Machine Owner + P-4 Semantic Layer Definer (在 ALM 端) |
| ADSK | P-4 Semantic Layer Definer + P-13 Platform Migration Candidate (新增) |
| ADBE | **P-12 Split Entity** (强制 SOTP) + 子评分: P-8 Pricing-Stuck (Consumer) / P-7 Accountability-Thin (Firefly) / P-4 Semantic (Document) |
