## 第一部分: 现有框架的认知覆盖度审计

在评估4个架构选项之前，必须先回答一个前置问题: **v18.0框架已经覆盖了多少"投资大师"的认知能力？**

如果覆盖度已经很高，新系统的边际价值就低，实施成本就难以合理化。

### 1.1 认知引擎 vs 现有机制映射

| 认知引擎 | 核心能力 | 现有覆盖机制 | 覆盖度 | 未覆盖缺口 |
|----------|---------|-------------|:------:|-----------|
| **巴菲特/芒格** | 护城河+安全边际+能力圈+长期持有 | assumption-audit M1信念反演(市场在赌什么) + RT-1承重墙测试 + Reverse DCF优先(v9.0) + SGI专才/通才 | **80%** | 能力圈边界的**显式声明**; "不做什么"比"做什么"更重要的哲学 |
| **李录** | 新兴市场+文明演进+逆向思维 | Phase 0.75非共识假说登记 + RT-7替代解释 | **30%** | 长周期文明视角(10-30年); 制度性风险的系统化评估; 东西方市场差异框架 |
| **阿克曼** | 激进价值+催化剂+集中持仓+治理 | Phase 3催化剂日历(RT-6时间框架) + CEO沉默分析(v18.0) | **45%** | 企业治理量化评分; 激进股东行动可能性评估; "修复价值"计算 |
| **德鲁肯米勒** | 宏观趋势+技术面+仓位管理+择时 | 投资温度计(CAPE/Buffett/ERP) + Phase 0温度路由 | **25%** | 宏观-微观传导链; 技术面信号整合; 仓位建议(被out_of_scope排除) |
| **达里奥** | 全天候+风险平价+经济机器+债务周期 | risk-topology(风险拓扑) + RT-5黑天鹅压力测试 | **35%** | 债务周期定位; 经济机器框架; 组合层面风险(单股分析无法触及) |
| **Cathie Wood** | 颠覆创新+指数增长+跨行业融合 | 演绎分析(deductive_analysis.md) + 期权估值(optionality_valuation.md) | **50%** | 技术S曲线量化; 跨行业融合的系统性识别; Wright定律成本曲线 |
| **Bear检察官** | 做空+财务欺诈+估值泡沫+叙事解构 | red-team-suite(RT-1~RT-7) + bear-case-generator + RT-2认知偏差 + RT-3空头钢人 | **75%** | 财务欺诈专项检测(Beneish M-Score等); 管理层诚信度量化审计 |

### 1.2 关键发现

**已高度覆盖 (>60%)**: 巴菲特/芒格(80%), Bear检察官(75%)
**中度覆盖 (40-60%)**: Cathie Wood(50%), 阿克曼(45%)
**低度覆盖 (<40%)**: 达里奥(35%), 李录(30%), 德鲁肯米勒(25%)

**结论**: 框架对"微观基本面分析"和"对抗性审查"的覆盖已经很强，但在**宏观-微观传导**、**长周期文明视角**、**企业治理/催化剂**三个维度存在结构性缺口。投资委员会系统的价值主要来自填补这三个缺口，而非重复已有能力。

## 第二部分: 四个架构选项的深度评估

### 2.1 评估维度定义

| 维度 | 权重 | 评估标准 |
|------|:----:|---------|
| **与v18.0兼容性** | 30% | 是否需要修改现有Phase结构/门控/脚本？回退成本？ |
| **Token效率** | 25% | 增量token消耗 vs 增量信息价值。是否有大量重复分析？ |
| **产出质量** | 25% | 是否产出**可操作的差异化洞见**？还是表演性覆盖？ |
| **实施复杂度** | 20% | 需要多少新脚本/skill/门控？维护负担？ |

### 2.2 Option A: 独立Phase (Phase 4.5插入)

**架构描述**: Phase 4红队完成后，插入Phase 4.5"投资委员会"。7个Agent各自以大师视角审阅Phase 1-4产出，给出独立评级+论点，最终投票汇总。

**优势**:

| 优势 | 说明 |
|------|------|
| 接口清晰 | 单一Phase，输入=Phase 1-4产出，输出=委员会决议。不侵入现有Phase |
| 可开关 | 用户可选择跳过。不影响Phase 5估值 |
| 7个视角完整呈现 | 读者可以看到每个大师的独立判断，信息透明 |

**劣势**:

| 劣势 | 严重度 | 说明 |
|------|:------:|------|
| Token爆炸 | **致命** | 7个Agent各读Phase 1-4全文(~150K字符) = 1.05M输入token。各输出~5K = 35K输出。加上投票汇总~10K。**单Phase消耗>1M token**，接近一个完整报告的context量 |
| 时间线冲突 | 高 | Phase 4.5在红队之后、估值之前。但红队RT-1~RT-7已经做过承重墙/空头/黑天鹅分析。巴菲特/Bear检察官的视角与红队高度重叠 |
| 晚期投入回报递减 | 高 | 在Phase 4之后引入新视角，已无法重塑报告叙事结构。委员会的洞见只能作为"附录评论"，无法渗透Phase 1-3的分析深度 |
| 与铁律A冲突 | 中 | 铁律A: 单会话禁跨Phase。Phase 4+4.5+5可能需要拆分会话，增加组装复杂度 |

**评分**: 兼容30×0.7 + Token25×0.2 + 质量25×0.5 + 复杂度20×0.8 = **21+5+12.5+16 = 54.5/100**

---

### 2.3 Option B: 嵌入现有Phase (分散插入)

**架构描述**: 将大师视角分散到现有Phase中——P1用巴菲特/李录评护城河，P3用阿克曼/德鲁肯米勒评催化剂+宏观，P4用Bear检察官增强红队，P5用达里奥/Cathie校准期望回报。

**优势**:

| 优势 | 说明 |
|------|------|
| 自然融合 | 大师视角在产出时就被整合，不是事后评论 |
| Token分摊 | 每个Phase只多1-2个Agent视角，增量可控 |
| 影响报告叙事 | P1的护城河评估直接影响后续Phase的分析方向 |

**劣势**:

| 劣势 | 严重度 | 说明 |
|------|:------:|------|
| Phase耦合 | **高** | 每个Phase的门控(QG-01~QG-14)、sentinel、phase_complete.sh都需要修改以容纳新子步骤。v18.0已有18+个Phase子步骤，再嵌入会增加脆弱性 |
| 大师分裂 | 高 | 巴菲特只在P1出现、德鲁肯米勒只在P3出现——但真实的巴菲特会对估值(P5)也有强烈意见。分散插入**阉割了每个大师的完整视角** |
| 维护噩梦 | 高 | 如果要调整一个大师的权重或替换一个引擎，需要在3-4个Phase文件+多个脚本中修改。违反单一职责原则 |
| 与现有skill重复 | 中 | P1巴菲特护城河 vs consumer_deep.md已有的CI-CONS-01~04承重墙。P4 Bear检察官 vs red-team-suite。分不清"谁的产出算数" |

**评分**: 兼容30×0.3 + Token25×0.7 + 质量25×0.6 + 复杂度20×0.3 = **9+17.5+15+6 = 47.5/100**

---

### 2.4 Option C: 多点触发 (关键决策点)

**架构描述**: 不是每份报告都启用，而是在特定触发条件下(评级争议、估值离散度大、行业转折等)按需启动。不固定Phase位置，而是在"需要多元视角"时调用。

**优势**:

| 优势 | 说明 |
|------|------|
| Token最优 | 只在需要时消耗。对于"教科书式"的消费品公司(如PG)可能不需要投资委员会 |
| 避免表演性 | 不强制7个大师对每份报告都发言。有些报告的争议很少，强制7路评审=表演性覆盖(参考铁律5: 5K有效>50K表演) |
| 灵活路由 | 可以根据公司类型只启用3-4个相关大师，而非全部7个 |

**劣势**:

| 劣势 | 严重度 | 说明 |
|------|:------:|------|
| 触发判断主观 | **中** | "什么时候需要多元视角"本身就是一个判断。如果由AI自行决定，可能系统性跳过(AI倾向于"效率优先")。如果由脚本决定，需要量化触发条件 |
| 一致性问题 | 中 | 报告A有投资委员会、报告B没有——比较时缺乏统一维度 |
| 容易滑坡 | 中 | "这次不需要"反复发生后，系统退化为从不触发 |

**评分**: 兼容30×0.9 + Token25×0.9 + 质量25×0.6 + 复杂度20×0.8 = **27+22.5+15+16 = 80.5/100**

---

### 2.5 Option D: 全面渗透 (每章批注)

**架构描述**: 每个关键结论旁附大师视角，类似"批注模式"。

**优势**:

| 优势 | 说明 |
|------|------|
| 信息密度最高 | 每个判断都有多视角校准 |

**劣势**:

| 劣势 | 严重度 | 说明 |
|------|:------:|------|
| 可读性灾难 | **致命** | 当前报告已有30章+7附录+Mermaid图+DM锚点。每章再加7个大师批注 = 报告体量×3-4。铁律1(密度>体量)直接违反 |
| Token地狱 | **致命** | 7大师×30章 = 210次角色切换。每次需要理解上下文+产出评论。粗估增量>500K token |
| 组装不可能 | 致命 | 铁律J(单会话组装)在当前542K(SBUX v3.0)已是极限。加入批注后>1.5M，单会话不可能完成 |
| 噪声淹没信号 | 高 | 大部分批注将是"同意"或"无异议"。真正有价值的分歧被淹没在噪声中 |

**评分**: 兼容30×0.1 + Token25×0.1 + 质量25×0.3 + 复杂度20×0.1 = **3+2.5+7.5+2 = 15/100**

## 第三部分: 推荐方案 — 改良Option C + Option A元素

### 3.1 方案名称: "按需委员会" (On-Demand Committee)

核心设计: **Option C的触发机制 + Option A的独立执行空间，但压缩到3个超级引擎而非7个独立Agent**。

### 3.2 为什么是3个超级引擎而非7个独立Agent

**问题诊断**: 7个独立Agent的最大问题不是数量，而是**认知重叠**。

```
巴菲特 ∩ 李录 = 长期价值投资(方法论重叠80%+)
阿克曼 ∩ 巴菲特 = 护城河+安全边际(方法论重叠60%+)
达里奥 ∩ 德鲁肯米勒 = 宏观周期判断(方法论重叠50%+)
Bear检察官 ∩ 红队(已有) = 对抗审查(功能重叠75%)
```

7个Agent中，有效独立信息源只有3-4个。其余是重复或与现有框架重叠。

**三种实施模式对比**:

| 模式 | Agent数 | 优势 | 劣势 |
|------|:-------:|------|------|
| 7独立Agent | 7 | 视角纯粹 | token浪费、重叠高、管理复杂 |
| 角色切换(1 Agent) | 1×7轮 | 简单 | 无法真正"遗忘"前一个角色的判断，互相污染 |
| **3超级引擎** | 3 | 互补MECE、token可控、并行执行 | 需要精心设计合并规则 |

**推荐: 3个超级引擎**

### 3.3 三个超级引擎设计

#### Engine-V: 价值之锚 (Value Anchor)

**融合**: 巴菲特/芒格 + 李录 + 阿克曼(价值部分)

**核心问题**: "以10年持有的视角，这个企业的内在价值是被低估还是高估？为什么？"

**独特贡献**(相对于现有框架):
- **能力圈边界声明**: "分析这家公司超出了哪些能力边界？" — 当前框架缺乏显式的"我不知道什么"声明
- **制度性风险评估**: 李录的新兴市场视角 — 对于在中国/印度等市场有重大敞口的公司尤其有价值
- **企业治理评分**: 阿克曼的治理视角 — 管理层激励结构对齐度量化
- **"不做什么"清单**: 巴菲特的能力圈哲学 — 列出这份分析中**不应该尝试预测**的3件事

**不做什么**(避免与现有机制重叠):
- 不重复Reverse DCF(assumption-audit M1已覆盖)
- 不重复护城河定性评估(consumer_deep.md CI-CONS-01~04已覆盖)
- 只提供**增量视角**: 能力圈边界 + 治理 + 制度风险 + 长周期

#### Engine-M: 宏观透镜 (Macro Lens)

**融合**: 德鲁肯米勒 + 达里奥

**核心问题**: "宏观环境对这家公司的核心论文是顺风还是逆风？这个顺/逆风还能持续多久？"

**独特贡献**(相对于现有框架):
- **债务周期定位**: 达里奥的经济机器框架 — 当前处于长期债务周期的哪个阶段？对这家公司意味着什么？
- **宏观-微观传导链**: "如果利率维持high-for-longer 2年，这家公司的哪个业务线最先受压？" — 当前投资温度计只给宏观评分，不做传导分析
- **货币/财政政策窗口**: "当前政策环境是在创造还是摧毁这家公司的核心优势？"
- **择时信号**: 不是"买不买"，而是"如果要买，现在是好时机还是应该等什么信号？"

**不做什么**:
- 不给仓位建议(out_of_scope)
- 不做技术面分析(LLM能力边界之外)
- 不替代投资温度计(温度计做宏观**评分**，Engine-M做宏观**叙事传导**)

#### Engine-D: 颠覆探测器 (Disruption Detector)

**融合**: Cathie Wood + Bear检察官(叙事解构部分)

**核心问题**: "有没有一个技术/商业模式变革正在发生，将在5年内使当前估值框架失效？"

**独特贡献**(相对于现有框架):
- **S曲线定位**: 关键技术在adoption S曲线的哪个位置？是否接近拐点？ — 当前deductive_analysis.md提到因果链但没有S曲线量化
- **跨行业融合扫描**: 哪些看似无关的行业变革正在汇聚到这家公司的领域？ — optionality_valuation.md关注现有期权，不关注外部入侵
- **叙事解构**: 管理层的"创新叙事"是真实的还是marketing话术？ — Bear检察官的叙事解构能力，但聚焦于创新真伪而非做空
- **Wright定律/学习曲线检验**: 如果管理层承诺成本下降，历史学习曲线支持吗？

**不做什么**:
- 不重复红队RT-1~RT-7(红队做全面对抗，Engine-D只关注颠覆维度)
- 不重复做空论文(bear-case-generator已覆盖)
- 不给估值(Phase 5职责)

### 3.4 触发机制设计

**核心原则**: 默认不触发，量化条件触发，用户可强制。

#### 自动触发条件 (任一满足即触发)

```yaml
auto_trigger:
  # 条件1: 估值离散度
  valuation_dispersion:
    metric: "(bull_case - bear_case) / base_case"
    threshold: "> 0.80"  # 牛熊估值差>80%基准价
    engine: [V, M, D]  # 全部触发
    rationale: "估值范围极宽意味着市场对核心假设分歧大"

  # 条件2: 可能性宽度高
  possibility_width:
    metric: "PW score"
    threshold: ">= 7"
    engine: [D]  # 只触发颠覆探测器
    rationale: "PW>=7 = Discovery System = 颠覆可能性高"

  # 条件3: 宏观温度极端
  macro_temperature:
    metric: "investment_temperature"
    threshold: "abs > 1.5"
    engine: [M]  # 只触发宏观透镜
    rationale: "宏观极端时需要理解传导机制"

  # 条件4: 评级争议
  rating_conflict:
    metric: "cross-validation score"
    threshold: "Phase 3/4 rating divergence >= 2 grades"
    engine: [V, M]  # 价值和宏观视角
    rationale: "内部分析自相矛盾时需要外部视角裁决"

  # 条件5: 行业转折信号
  industry_inflection:
    metric: "Phase 0.5 hot_patch count"
    threshold: ">= 3"  # 框架预设模块覆盖不足
    engine: [D]  # 颠覆探测器
    rationale: "大量热点补丁说明行业正在发生框架未预见的变化"
```

#### 手动触发

```yaml
manual_trigger:
  user_command: "/investment-committee [V|M|D|all]"
  timing: "Phase 4完成后, Phase 5开始前"
  override: true  # 即使自动条件未满足也可手动触发
```

#### 预期触发频率

基于31份历史报告回溯估计:

| 触发条件 | 历史满足频率 | 代表报告 |
|---------|:----------:|---------|
| 估值离散>80% | ~30% | NVDA, INTC, ARM |
| PW>=7 | ~15% | NVDA(7.2), INTC(8) |
| 温度极端 | ~20% | (取决于宏观环境) |
| 评级争议 | ~10% | (内部矛盾较少见) |
| 行业转折 | ~15% | (新兴行业更常见) |
| **任一触发** | **~45-55%** | 约每2份报告触发1次 |

**这是合理的频率**: 不是每份都触发(避免表演性)，但也不罕见(确保系统不退化)。

### 3.5 执行位置: Phase 4.5 (条件性)

```
Phase 4: 红队 (RT-1~RT-7 + 校准 + 有效性)
    ↓
Phase 4.5: 投资委员会 [条件触发]
    ├── Engine-V: 价值之锚 (~5K字符产出)
    ├── Engine-M: 宏观透镜 (~5K字符产出)  ← 可并行
    └── Engine-D: 颠覆探测器 (~5K字符产出)
    ↓
    Committee Synthesis (~3K字符): 分歧地图 + 权重投票 + 对Phase 5估值的建议调整
    ↓
Phase 5: 估值 (吸收委员会建议)
```

**为什么在Phase 4之后而非之前**:
- 红队已经做完对抗性审查，委员会读红队产出可以避免重复做空分析
- Phase 5需要整合所有信息，委员会建议作为估值输入更自然
- 如果在Phase 4之前，委员会缺乏红队的对抗视角，容易被叙事裹挟

**Token预算**:

| 组件 | 输入token | 输出token | 说明 |
|------|:---------:|:---------:|------|
| 每个Engine读Phase 1-4摘要 | ~30K | — | 不读全文，只读staging摘要+shared_context |
| Engine-V产出 | — | ~5K | 能力圈+治理+制度风险+长周期 |
| Engine-M产出 | — | ~5K | 债务周期+传导链+政策窗口 |
| Engine-D产出 | — | ~5K | S曲线+融合扫描+叙事解构 |
| Synthesis | ~15K | ~3K | 读3个Engine产出，合成分歧地图 |
| **总计(3引擎全触发)** | **~105K** | **~18K** | **约等于一个中等Phase** |
| **单引擎触发** | **~35K** | **~8K** | 极低成本 |

对比: Phase 4红队本身消耗~120K token。投资委员会全触发的增量约等于红队的85%，单引擎触发约30%。**可接受**。

### 3.6 与现有框架的集成点

|--------|---------|:------:|
| `docs/deep_dive_protocol.md` | 新增Phase 4.5节(条件性) | 低 |

## 第四部分: 动态权重机制

### 4.1 推荐: YAML配置 + LLM微调

**纯YAML**: 刚性但可审计。适合"哪些引擎参与"的粗粒度路由。
**纯LLM判断**: 灵活但不可复现。适合"引擎内部如何权衡"的细粒度推理。

**混合方案**: YAML做引擎选择，LLM做引擎内推理。

```yaml
# committee_weights.yaml

# 按公司类型的引擎权重 (总和=1.0, 0=不触发)
company_profiles:

  # 成熟消费品 (KO, PG, MCD)
  mature_consumer:
    engine_v: 0.50  # 巴菲特视角最相关
    engine_m: 0.30  # 宏观影响中等
    engine_d: 0.20  # 颠覆风险较低但不为零
    rationale: "护城河和长期持有是核心，宏观通过消费信心传导"

  # 高增长科技 (NVDA, ARM)
  high_growth_tech:
    engine_v: 0.20  # 能力圈边界声明重要
    engine_m: 0.25  # 利率对成长股估值影响大
    engine_d: 0.55  # 颠覆可能性是核心问题
    rationale: "技术S曲线和跨行业融合是最大的未知"

  # 转型/Turnaround (INTC)
  turnaround:
    engine_v: 0.35  # 治理+激进价值视角
    engine_m: 0.25  # 产业政策(CHIPS Act等)
    engine_d: 0.40  # 转型成功=颠覆; 失败=被颠覆
    rationale: "治理和颠覆视角同等重要"

  # 周期性 (半导体设备, 邮轮)
  cyclical:
    engine_v: 0.25  # 长期价值锚
    engine_m: 0.55  # 周期定位是核心
    engine_d: 0.20  # 颠覆可能性较低
    rationale: "宏观周期驱动短中期表现"

  # 金融 (JPM, GS)
  financial:
    engine_v: 0.30  # 制度性风险(李录视角)
    engine_m: 0.50  # 利率/信用周期
    engine_d: 0.20  # Fintech颠覆
    rationale: "金融公司与宏观高度耦合"

  # 默认
  default:
    engine_v: 0.35
    engine_m: 0.35
    engine_d: 0.30
```

**实施细节**:
- Phase 0完成后，脚本根据公司特征匹配profile → 写入checkpoint.yaml
- 如果后续触发委员会，权重直接从checkpoint读取
- 权重影响的是Synthesis环节的"投票权重"，不影响各Engine的独立产出
- 用户可在`/investment-committee`命令中覆盖权重

## 第五部分: 与现有红队/反思系统的去重

### 5.1 职责边界矩阵

| 维度 | 红队 (RT-1~7) | Deep Reflection (R1-R3) | 投资委员会 | 重叠风险 |
|------|:-------------:|:-----------------------:|:----------:|:--------:|
| **时机** | Phase 4 (分析中) | 报告Complete后 | Phase 4.5 (分析中) | 委员会与红队相邻 |
| **目标** | 挑战分析中的错误/偏差 | 提取教训+改进框架 | 引入**外部认知框架** | 低(目标不同) |
| **输入** | Phase 1-3产出 | 完整报告 | Phase 1-4产出(含红队) | 委员会输入包含红队 |
| **输出** | 校正值+风险量化 | EVO提议+模块评分 | 分歧地图+估值建议 | 中(估值建议可能冲突) |
| **对抗性** | 高(专门找错) | 低(建设性反思) | 中(独立视角但非对抗) | 低 |

### 5.2 具体去重规则

**规则1: 委员会不做红队已做的事**

```
禁止: Engine-V重新做RT-1承重墙测试
允许: Engine-V评论"红队RT-1发现的最脆弱承重墙，从巴菲特的视角看是否改变了我的持有意愿？"
区别: 红队找出问题(what)，委员会解读影响(so what)
```

**规则2: 委员会读红队产出，不重做红队分析**

每个Engine的prompt中注入:
```
你已经获得了红队Phase 4的完整产出。不要重复以下分析:
- 承重墙测试 (RT-1已完成)
- 认知偏差审计 (RT-2已完成)
- 空头钢人 (RT-3已完成)
- 黑天鹅压力测试 (RT-5已完成)

你的职责是: 在红队发现的基础上，从你的认知框架出发，提供红队不会提供的视角。
```

**规则3: 委员会与Deep Reflection完全正交**

Deep Reflection在报告完成后执行(R1-R3)，关注"框架改进"。投资委员会在报告完成前执行(Phase 4.5)，关注"当前报告的判断"。两者没有功能重叠。

**规则4: 委员会产出有字符上限**

每个Engine产出上限5000字符。Synthesis上限3000字符。**总计不超过18K字符**。这是硬约束——防止委员会膨胀成"第二个Phase 4"。

对比: 红队Phase 4产出通常20-40K字符。投资委员会控制在红队的50%以内。

## 第六部分: 实施路线图

### 6.1 阶段规划

| 阶段 | 范围 | 产出 | 耗时 |
|------|------|------|------|
| **Alpha** | 只实现Engine-V(价值之锚) + 手动触发 | 1个skill + 1个yaml配置 | 1-2小时 |
| **Beta** | 3个Engine + 自动触发 + Synthesis | 完整skill + trigger脚本 + yaml | 3-4小时 |
| **GA** | 集成phase_sentinel + Complete组装 + 实战验证 | 全套脚本 + 2份报告验证 | 2份报告 |

### 6.2 Alpha验证标准

在下一份Tier 3报告(如果满足触发条件)上手动测试Engine-V:
- 产出是否包含至少1个红队未涉及的洞见？
- 产出是否改变了Phase 5的估值判断？
- Token消耗是否在预算内(<35K)？

如果3个问题中有2个回答"是"，推进到Beta。如果"否"居多，说明增量价值不够，暂停系统。

### 6.3 退出条件(什么时候放弃)

- Alpha验证3份报告后，如果没有一次产出改变估值判断 → 放弃
- 任何引擎的产出与红队重叠>50% → 合并到红队而非独立系统
- Token预算持续超标(>150K/次) → 重新设计输入压缩

## 第七部分: 总结与核心建议

### 7.1 一句话推荐

**改良Option C: 3个超级引擎(价值/宏观/颠覆) + 5个量化触发条件 + Phase 4.5条件性执行 + YAML权重配置**。

### 7.2 五个关键设计决策

| # | 决策 | 选择 | 理由 |
|---|------|------|------|
| 1 | 架构选项 | C(多点触发) | Token最优+兼容性最高+避免表演性 |
| 2 | 引擎数量 | 3超级引擎(非7独立) | 认知重叠去除+MECE互补+并行可行 |
| 3 | 权重机制 | YAML配置+LLM微调 | 粗粒度可审计+细粒度灵活 |
| 4 | 执行位置 | Phase 4.5(红队后、估值前) | 读红队产出避免重复+影响估值 |
| 5 | 触发频率 | ~45-55%报告(非100%) | 有价值才触发，不强制表演 |

### 7.3 最大风险

**风险1: 角色扮演深度不足**。LLM"扮演巴菲特"可能只是表面模仿(说"护城河"多几次)，而非真正内化其决策框架。**缓解**: prompt中嵌入具体决策标准而非人格特征，例如"如果10年持有的税后复合回报<15%，你不会投资"而非"你是一个长期投资者"。

**风险2: 信息增量为零**。3个引擎的产出可能只是"用不同语言重述Phase 1-4已有结论"。**缓解**: 每个Engine的prompt中明确列出"已有结论清单"，要求"只输出与以上不同的判断"。Alpha阶段验证此风险。

**风险3: 触发条件校准**。初始阈值可能过高(从不触发)或过低(每次触发)。**缓解**: 前5份报告手动记录所有触发指标值，事后校准阈值。
