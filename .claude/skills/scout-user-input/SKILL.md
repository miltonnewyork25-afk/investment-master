# Scout User Input v1.0 — 读者信号收集

> **设计原因**: NVDA"第五行"写作中，OpenClaw龙虾(AI推理流量爆炸)和OpenAI砍$8000亿预算两个关键信号都是用户补充的，Scout三路搜索全部没搜到。最好的文章是"你正在想的那件事，我恰好研究过"——如果不知道读者在想什么，就写不出这个交集。
>
> **定位**: Content Engine Layer 2.5 Scout的前置步骤。在WebSearch侦察之前执行。

---

## 触发条件

每次执行`/content-engine scout`或`/content-engine scout-frame`时，自动在Step 1之前插入本步骤。

---

## 执行流程

### 问用户一个问题

```
准备写 {TICKER} 的文章。在我去搜索之前——

你最近在群里、朋友圈、Twitter、或任何地方看到关于这家公司（或相关话题）的什么讨论？
可以是截图、转发、朋友说的一句话、一个让你注意到的数字，什么都行。
没有也没关系，我直接去搜。
```

**设计要点**:
- 问一个问题，不是五个。降低用户负担
- "什么都行"——不预设格式，不要求结构化输入
- "没有也没关系"——不阻断流程，用户跳过也能继续

### 处理用户输入

用户回复后，提取3类信号:

| 信号类型 | 示例 | 用途 |
|----------|------|------|
| **热议事件** | "群里都在转那个AI龙虾" | 文章切入点/环境嵌入 |
| **读者情绪** | "朋友说再不上车来不及了" | FOMO/恐惧/困惑 → 文章回应的心理锚点 |
| **未回答的问题** | "大家在问为什么财报这么好还跌" | 文章的核心张力候选 |

**输出格式** (传给Scout Step 1):
```
## 用户信号
- 热议: {事件/截图/转发}
- 情绪: {FOMO/困惑/恐惧/乐观/...}
- 未答问题: {读者在问但没人回答的}
- 原始输入: "{用户原话}"
```

### 融入Scout流程

用户信号成为Scout的**第四路信号源**:

```
Scout 四路侦察:
1. 中文社区 (雪球/微信/知乎) — WebSearch
2. 英文社区 (FinTwit/Reddit/Substack) — WebSearch
3. 事件/财报/13F — 公开数据
4. ★ 用户输入 ★ — 本skill收集

→ 四路交叉 → 找到"我们有洞见 + 读者恰好在想"的交集
```

**优先级**: 用户输入 > 搜索结果。原因：用户就是目标读者，他看到的=读者关心的。搜索可能有延迟或遗漏，用户信号是实时的。

---

## 用户跳过时的处理

用户说"没有"或不回复 → 正常执行三路Scout，不阻断。

但在Frame模板中标记:
```
用户信号: 无 (纯搜索模式，注意可能漏掉社群热点)
```

这个标记提醒写作者：这篇文章的切入点没有经过读者验证，发布前可能需要多一轮确认。

---

## 已验证案例

| 文章 | 用户提供的信号 | Scout搜到了吗 | 对文章的影响 |
|------|--------------|:------------:|------------|
| NVDA第五行 v2→v3 | OpenClaw龙虾(AI推理流量) | 没搜到 | 成为"龙虾是真的。借债也是真的。"金句的素材 |
| NVDA第五行 v2→v3 | OpenAI砍$8000亿预算 | 没搜到 | 成为"已经有人开始停了"的论据 |
| RCL水线 | 注册地是利比里亚不是巴哈马 | N/A(事后纠错) | 修正了v1的事实错误 |

## 调用方式

本skill不单独调用。它嵌入Content Engine的Scout流程:

```
/content-engine scout {TICKER}       # 自动先问用户，再搜索
/content-engine scout-frame {TICKER} # 自动先问用户，再搜索+Frame
```

如果需要单独收集用户信号（不跑Scout）:
```
/scout-user-input {TICKER}
```
