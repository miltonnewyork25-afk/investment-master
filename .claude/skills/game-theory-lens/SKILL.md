# 博弈论互动结构透镜 v2.0 (PDD 验证后推广)

## v2.0 升级 (PDD v2.0 教训, P1)

### Mandatory 模式 — 中重度竞争场景必备 (新增)

**强制触发条件** (任一即触发, P3 阶段强制):
- **双寡头/三寡头格局** (CR3 ≥60%)
- **监管驱动的产业** (金融/电信/医药/电商/能源)
- **治理博弈存在** (大股东 vs 小股东 / VIE 结构 / 集中控股)
- **政策定价产品** (关税/补贴/牌照敏感)
- **核心矛盾本身就是博弈问题** (PDD 治理 reset / NVDA 出口管制 / TSM 地缘)

**Mandatory 输出要求** (沉淀自 PDD P3 3.16, ~12K 字符):
- **至少 3 场关键博弈** 完整闭环, 每场覆盖:
  1. **博弈结构**: 双寡头/序贯/重复 + 信息对称性 + private/common value
  2. **当前均衡**: 写出 (action_A, action_B) 具体策略, 标注稳定性 (稳定/不稳定/负向稳定)
  3. **谁会先动**: 量化先动者优势/劣势, 不能只说"看情况"
  4. **可信承诺机制**: 需要什么样的"退出成本"才能让承诺可信
  5. **信号 vs 廉价表态**: 哪些动作是真信号 (有退出成本), 哪些是 cheap talk
  6. **估值含义**: **必须给出具体的 $/sh 或 OPM pp 影响**, 不能停在定性
- **综合表**: N 场博弈的均衡 + 演化 + 估值含义一行总结
- **Phase 5 章节锚点**: 每场博弈连接到 P5 哪个章节使用

# 博弈论互动结构透镜 v1.0 内容 (保留)

> **核心价值**: 普通分析把竞争当价格战、把均衡当最优、把口头当承诺、把赢标当创造价值。本skill强制追问"别人也会反应"之后的二阶结果。
> **不是什么**: 不是博弈论术语贴纸。禁止堆砌Nash/dominance等术语而不解释商业含义。
> **服务于**: L0第3目标(市场最可能错看的那一层) + 铁律N(因果链) + 红队偏离路径检验

## 何时触发

| 模式 | 触发 | 输出 | 字符 |
|------|------|------|------|
| **Lite** (默认) | Phase 3竞争格局完成后自动 | staging YAML + Phase 5叙事段落 | ~3K |
| **Full** | 用户显式调用 / 核心矛盾本身就是强互动问题(平台双边/竞标/牌照争夺/价格战/监管博弈) | 完整11 Step + YAML + 多段叙事 | ~10K |

**与现有skill的边界**:
- `moat-evaluator` 主导护城河评分 → 本skill补充"均衡稳定性 + 改哪个参数会迁移"
- `red-team-suite` → 本skill作为RT补充透镜:"哪些威胁不可信 / 哪些方案只在主路径成立"
- `assumption-audit` → 本skill补充"信号vs廉价表态"分离
- `risk-topology` → 本skill补充"哪些风险其实是均衡迁移触发器"
- `investment-committee` → 圆桌可调用本skill做结构化视角切换

## 五大反模式 (写之前先自检)

写出任何博弈论结论前,检查是否落入这五个陷阱:

1. **把互动当单点优化** — "只要我做X就赢"忽略对手反应
2. **把均衡当最优** — 解释不了"既然不好为什么没人停下来"
3. **只看主路径** — 对手反击/客户犹豫/渠道摇摆时方案就崩
4. **把口头当承诺** — 没问"未来那个节点他还有激励兑现吗"
5. **把赢标当创造价值** — common value问题中没做赢家修正

## Lite 模式 (Phase 3 默认)

**4 个 Step,输出 staging YAML + Phase 5 嵌入叙事(2-3段)**

### Step L1: 结构识别 (1段)

判断并写明:
- 单点优化 还是 战略互动?
- 一次性 还是 重复关系?
- 同时行动 还是 顺序行动?
- 信息对称 还是 不对称?
- private value 还是 common value? (若涉及竞标/并购/牌照)

**输出**: 一句话定性,例如 "AAPL服务收入是双边重复博弈+信息不对称(开发者不知道Apple真实成本)+顺序行动(Apple先定规则)"

### Step L2: 当前均衡为何稳定 (核心,1段)

回答两个问题:
1. **为什么没人愿意单独偏离?** — 谁先变谁先受损,代价是什么?
2. **这是好均衡还是坏均衡?** — 对哪一方好,对哪一方坏?

**禁止**: "因为大家都知道这样最好" / "因为行业惯例" — 这不是解释。
**正确**: 量化偏离代价。例: "单个开发者下架iOS = 失去40%收入, 30%抽成 = 收入×0.7, 30% << 40% → 不偏离"

### Step L3: 主导竞争变量 (1段)

区分**表面竞争**和**真实竞争**。问:
- 行业普遍说在竞争X(价格/份额/技术)
- 但真正决定结果的是不是Y(默认位置/兼容性/转换成本/时间窗口/渠道占位)?
- 我方在Y上的位置决定了X竞争的结果

**输出**: 一句"市场以为在打X战,真正的战场是Y"。这往往就是预期差。

### Step L4: 均衡迁移参数 + 失效条件 (1段)

回答:
- **改哪一个参数,当前均衡会迁移?** (监管/技术替代/客户教育/对手并购/资本市场容忍度)
- **本次分析的thesis,在什么条件下失效?** — 必须可检验,链接到Kill Switch

### Lite 输出格式

**staging YAML** (`reports/{TICKER}/data/game_theory_lens.yaml`):
```yaml
ticker: {TICKER}
mode: lite
structure:
  interaction_type: "战略互动/单点优化"
  repetition: "重复/一次性"
  timing: "同时/顺序"
  information: "对称/不对称"
  value_type: "private/common/N/A"
current_equilibrium:
  description: "..."
  why_stable: "单个偏离的具体代价 = ..."
  good_or_bad: "对X方好,对Y方坏"
  type: "好均衡/坏均衡/共赢均衡"
dominant_variable:
  surface: "市场以为在打..."
  real: "真正决定结果的是..."
  our_position: "..."
migration_triggers:
  - trigger: "..."
    direction: "向...迁移"
    probability: "高/中/低"
failure_conditions:
  - "thesis在...条件下失效 → 链接KS-XX"
```

**Phase 5 叙事**: 2-3段嵌入"竞争格局"或"预期差"章节,**不出现"博弈论"四个字**,直接用商业语言写。

## Full 模式 (11 Step)

只在以下情况启动:
- 用户显式 `/game-theory-full {TICKER}`
- 核心矛盾(P0.75 thesis)本身是强互动问题:平台双边动态/反垄断/价格战均衡/竞标资产/牌照争夺/标准之争/合作-背叛动态

**11 Step 大纲** (详见 `references/full_protocol.md`):

1. **问题类型识别** (Lite L1扩展) — 加可验证性 / 子博弈结构
2. **关键玩家激励矩阵** — 至少6方:我方/对手/客户/渠道/供应商/监管+资本市场。每方写:目标/害怕/约束/可选动作/最可能反应/底线
3. **视角切换** — 至少4视角重建问题(我方/对手/客户/渠道),必要时+监管+资本市场
4. **删劣策略三轮** — 逻辑删/互动删/持续性删
5. **当前均衡** (Lite L2扩展) — 加迁移路径推演
6. **主导竞争变量** (Lite L3扩展) — 加"竞争维度重构"可能性
7. **顺序/承诺/威胁** — 谁先动?是否道德风险?先手是真实优势还是幻觉?承诺/威胁是否可信?声誉效应?谈判力量从哪来?
8. **信息结构 + 子博弈检验** — 谁知道什么?哪些方案只在"某些路径不被走到"时成立?是否依赖不可信威胁?
9. **长期关系与惩罚** — 未来能否约束今天?终局是否破坏合作?惩罚是否存在且可信?
10. **信号与筛选** — 可验证→沉默是否已是负面信号(unraveling)?不可验证→什么信号对高质量者便宜对低质量者贵?哪些是生产性投入vs信号性投入?
11. **竞标与赢家诅咒** — private/common?若赢说明我最乐观?是否做赢家修正?

**Full 输出**: YAML(扩展版) + Phase 5 多段叙事 + Phase 4红队补充清单

## 写作纪律 (与 narrative-discipline 一致)

- ❌ 禁止术语:"Nash均衡""dominance""mixed strategy""backward induction" 不出现在正文
- ✅ 用商业语言:"没人愿意单独让步""谁先变谁先输""倒推一下他的下一步会发现..."
- ❌ 禁止抽象:"博弈结构复杂"
- ✅ 具体量化:"开发者偏离代价 = 失去40%收入,继续支付代价 = 30%抽成,40>30 → 不偏离"
- ❌ 禁止"可能/或许/某种程度上" (铁律N减法1)
- ✅ 不确定就说"我们不知道X" / "证据不足以判断X"

## 灰度规则

**v1.0 灰度阶段** (前2-3份Tier 3报告):
- Lite模式自动触发,不阻断 — 结果记录到staging,Phase 5决定是否采纳
- 验收标准:(1)Phase 5叙事中至少1个观点明确改写了原Phase 3结论 (2)失效条件可链接到Kill Switch (3)未出现博弈论术语
- 若3份报告中≥2份达到验收 → 升级为Phase 3硬门控
- 若<2份达到 → 修订Step设计或降级为可选

**禁止**:
- 在灰度期间把本skill产出当结论引用(只作为补充透镜)
- 让本skill替代moat/red-team/assumption-audit任何一个的核心职责

## 最终五问 (任何输出前回答)

1. 当前局面为什么会这样?
2. 为什么它会稳定?
3. 真正决定结果的变量是什么?
4. 哪个动作最可能改写他人的最佳回应?
5. 这个动作在什么条件下成立,什么条件下失效?

任何一问答不出来 → 重写,不要交付。
