# 叙事纪律 v1.0 (灰度版)

> **一句话目标**: 报告不是"让读者知道更多",而是"替读者解开他正在卡住、自己解不开的问题"。
>
> **核心原则**: 分析层自由使用专业工具语言,组装层必须翻译成自然的投资者语言,所有框架内部比喻词(AI味)从头到尾禁用。

---

## 触发条件

| 层级 | 是否启用 |
|------|---------|
| Tier 1 快速扫描 | 不启用 |
| Tier 2 标准分析 | **强制** |
| Tier 3 深度研究 | **强制** |

启用后,Skill 在 3 个节点介入:

1. **Phase 0.75 扩展** — 核心矛盾结晶后,顺带做一次"读者视角检查"
2. **Phase 4→5 之间** — 新增一步,产出 `staging/reader_questions.md`
3. **Phase 5 组装** — 写作过程中持续执行五重纪律,完成后脚本扫描

---

## 一、根本命题(设计依据)

投资者打开一份报告时,手里通常已经有:
- 管理层叙事
- 卖方共识
- 媒体解读
- 一两个朋友的口头意见

他们**缺的不是信息**,是**某个让他们卡住的具体问题没人给答案**。例如:
- 为什么这家公司的估值已经涨到这里、但内部人还在卖?
- 为什么管理层指引连续3个季度超预期、但股价不涨?
- 同行业另一家质量更差的公司 PE 反而更高,是市场错了还是我漏看了?
- 护城河故事讲了5年,为什么新进入者还是能蚕食份额?

**一份报告的真正价值,是在这种"读者已经卡住的地方"提供可信的解答,而不是再讲一遍管理层叙事。**

这个命题之下的所有纪律,都是为了保证报告不漂离它。

## 二、八条承重墙原则

> 这是整套 Skill 的骨架。其他细则都是这 8 条的落地。

### 原则 1: 每份报告围绕一个核心矛盾运行
- 全文只有一个 CQ(core question),子问题都是它的下属
- 任何章节必须能回答"这部分和核心矛盾的关系"
- 做不到的章节合并或删除

### 原则 2: 核心矛盾不是"是什么",是"为什么和表面看起来不一样"
- "公司好不好" → 低阶问题,管理层叙事已经回答
- "为什么市场看不见这个好 / 为什么市场的贵是错的" → 高阶问题,这才是报告的价值
- 本质上和"预期差"同构,但在**写作层**重新表达

### 原则 3: 观点-理由-证据 三层结构
每个核心判断必须能拆成:
- **观点**(主张什么)
- **理由**(为什么)
- **证据**(凭什么)

任何一层缺失 = 断言,不是论证。与铁律 N 同构,在段落级强制。

### 原则 4: 段落一事一议
每段只承担一个功能: 提出判断 / 解释机制 / 给证据 / 比较说法 / 处理反驳 / 过渡收束。**NEVER** 在一段混多个功能。

### 原则 5: 长短句有节奏
- 短句下判断、收束、强调
- 长句解机制、展开条件、描述链条
- 一段全长句 = 拖沓;一段全短句 = 碎片
- 自然搭配,不机械交替

### 原则 6: 知道 vs 判断分层贯穿全文
不只在结论处标注 [A]/[B]/[C],全文推理都要让读者看清:
- 哪是事实
- 哪是解释
- 哪是推论
- 哪是猜测
- 哪已经稳固
- 哪仍待验证

允许不确定,不允许混淆层次。

### 原则 7: 结尾收束判断,不是重复摘要
结尾要完成 4 件事:
1. 提炼核心回答(用一两句话回应开头的核心矛盾)
2. 给出最重要的判断
3. 指出剩余的不确定之处
4. 提示下一步应继续追问的方向

**NEVER** 把结尾写成"综上所述,本文分析了 X、Y、Z..."这种礼貌性结束。

### 原则 8: 段与段之间必须有桥,不让读者自己补逻辑

原则 4(段落一事一议)管段**内**封闭,本条管段**间**流动。两者配对——缺一方就会要么段内散,要么段间断,读起来像 PPT 页而不是文章。

**一座桥必须完成 3 件事之一**:
- **承接**: 明确引用上段的结论或证据(不用"如前所述",要具体说)
- **转折**: 点出本段与上段的关系(补充 / 反驳 / 深化 / 换角度)
- **预告**: 本段结尾提示下一段要处理的问题

**反例(段间断开)**:
```
[段 1] 公司的护城河体现在 94% 续约率和 5 年 NPS 72。
[段 2] 2024 年公司收入增长 18%,超出指引上限 3 个百分点。
```
两段都对,但读者不知道你为什么把它们放一起。没有桥。

**正例(有桥)**:
```
[段 1] 公司的护城河体现在 94% 续约率和 5 年 NPS 72。换句话说,
      一旦客户进来,平均要用 7 年才会考虑离开。
[段 2] 这种粘性解释了 2024 年的 18% 收入增长里,70% 来自老客户
      扩容而不是新签约——这是规模效应的早期信号,不是单纯的需求回暖。
```
段 2 的"这种粘性"回指段 1 结论,"不是单纯的需求回暖"暗示本段真正要说的"规模效应",段间钩住了。

**禁止的"假桥"**:
- "此外" / "另外" / "同时" / "值得一提的是" → 这些词把"衔接"变成"并列堆积",等于没接
- "综上所述" / "由此可见" → 这是总结词,不是桥。真正的桥是具体内容的钩连,不是逻辑词
- "如前所述" / "上文提到" → 偷懒。具体引用上段的哪个数字/哪个判断,**NEVER** 让读者回翻

**桥的密度**:
- 短章节(<5 段): 每 2-3 段一座显性桥
- 长章节(>10 段): 每段都应有隐性或显性的钩连
- **过度钩连 = 机械感,读起来更累**。自然 > 齐整

## 三、无痕化纪律(最关键)

> **目标**: 报告读起来像资深分析师写的备忘录,不像 AI 跑框架跑出来的。

### 保留词(投资者通用语,自由使用)

这些词已经是投资行业的专业语汇,读者看到不会觉得是 AI 味:
- 核心矛盾 / 预期差
- 护城河 / 转换成本 / 网络效应 / 规模经济
- Kill Switch / 认知边界 / 能力圈
- 安全边际 / 催化剂
- 定价权 / 单位经济 / Owner Earnings
- 反身性 / 周期位置

### 禁用词(AI 味比喻 + 框架内部词)

这些词只存在于分析师的内心和 SKILL 内部,**NEVER** 出现在 staging 或 Complete:

**内部框架比喻**:
- 谜题 / 解谜 / 抽丝剥茧
- 问题引擎 / 问题驱动 / 变量化思考
- 承重墙 / 脚手架 / 骨架 / 底盘
- 钩子 / 叙事驱动

**AI 味比喻**:
- 温水煮青蛙 / 死亡螺旋(除非已作为行业术语)
- 降维打击 / 范式跃迁 / 认知迷雾
- 护城河雷达 / 预期差雷达
- 拨开迷雾 / 层层剥开 / 直击本质

**辩论术语**(LITE v4 反馈新增):
- 稻草人 / 诉诸权威 / 诉诸群众
- 滑坡谬误 / 循环论证 / 以偏概全
- 正方 / 反方 / 支持者 / 反对者
- 这些是逻辑学/辩论术语,投资行业不用。Bull case 的"最强形态"用"最佳论证""最强逻辑链"等自然说法,不用"不是稻草人"

**军事/网安术语**(LITE v4 反馈新增):
- 红队 / 蓝队 / 红方 / 蓝方
- "红队"是网络安全和军事推演的术语,投资行业的自然说法是"压力测试""对抗审查"
- **meta 层豁免**: 框架内部 SKILL/rule/script 文件可保留"红队"作为流程名(对应 `red-team-suite` skill),但 staging 和 Complete 报告**禁止**出现

**对抗性论证的自然说法**(LITE v4 反馈新增):
- 替代"反方": 区分两种语境
  - 对**同一事实的不同解释** → "替代解释" / "对立解释"
  - 对 **thesis 的反方向论证** → "反向论证" / "反向证据" / "质疑"
- 替代"红队结论": "压力测试结论" / "对抗审查结论"
- 描述对立观点的标准投资行业写法: "**多头逻辑 / 空头逻辑**" / "**Bull case / Bear case**" / "**看多 / 看空**"
- **NEVER** 用"正方""支持者"等人称化标签,描述的是观点不是人

**审美空泛表达**(LITE v4 反馈新增):
- "它的荒谬就具体了" / "数学上无解" / "不证自明"
- "令人震惊的是" / "值得玩味的是"
- **替代原则**: 直接陈述事实和对比,不用情绪性修饰

**套路转场词**:
- "综上所述" / "值得一提的是" / "不难发现"
- "本报告认为" / "笔者观察到" / "本节将从 X 个角度展开"
- "首先... 其次... 最后..."(作为段首转场,非列点时)

**第一人称(LITE v4 反馈新增,覆盖 rule-N 减法 4)**:
- "我" / "我们" / "我们的" / "我们认为" — 全部禁用
- "本报告认为" / "笔者" — 全部禁用
- **替代方式**: 直接陈述结论、用被动结构、用"本研究"(仅在必须有主语时)、用"分析表明/数据显示/判断是"等第三方句式
- **原则**: 投资研究报告站在第三方视角,不是"对话"。"我们"会让报告像辩论发言,不像分析文档
- **注意**: 这一条与 rule-N 减法 4("我们"优于"本报告/笔者")相反。LITE v4 实测显示"我们"仍有第一人称感,完全的第三方视角更专业。rule-N 减法 4 在灰度迁移时将被本条覆盖

**读者称谓**(LITE v4 反馈新增):
- "读者" — 禁用
- **替代**: "投资者"。投资研究报告的受众是投资者,不是"读者"。"读者"暗示阅读关系,"投资者"是决策关系
- **例外**: 如果真的在谈阅读体验本身(而非投资决策),才可以用"读者",但 Tier 2/3 报告中几乎不该出现这种语境

**脚本检查**: `bash scripts/ai_flavor_check.sh {REPORT}` 扫描清单,命中 → WARN(不阻断)。清单在脚本中维护,需要增删时直接改脚本。

### 这一条的执行范围

**staging 和 Complete 都必须遵守禁用词纪律**。理由: staging 是 AI 惯性的源头,源头不干净下游会泄漏。Phase 1-4 的 staging 也要用自然语言推理,不要用"这是一个谜题"开头。

**唯一例外**: Skill 内部 prompt 和 meta 文件(本文件、scripts/)可以使用内部术语。

## 四、三个介入点的具体动作

### 介入点 1: Phase 0.75 核心矛盾扩展

P0.75 已有"核心矛盾结晶"流程。本 Skill 在它完成后追加一次**读者视角检查**:

```
问题清单(写入 thesis_crystallization_P0.75.md 尾部):
  投资者打开这份报告时,他手上已经有什么信息?
  → 管理层叙事、卖方共识、媒体解读(各1-2句)

  他最可能卡在哪 3-5 个具体问题上?
  → 每个问题必须是"他知道但解释不了"的类型,不是"他不知道"的类型
  → 不要写成"X 的护城河有多强",要写成"为什么 A 的 PE 比 B 高 30%,但 ROIC 更低?"

  我(分析师)对这几个问题,真的有比市场更好的答案吗?
  → 如果没有,本报告的价值基石不牢,核心矛盾需要重新找
```

**产物**: 写入现有 `thesis_crystallization_P0.75.md`,不另起文件。

### 介入点 2: Phase 4→5 之间的"读者问题提炼"

Phase 4(红队)完成后、Phase 5 组装前,新增一步:

```
从 Phase 1-4 的全部分析中,提炼 3 个"真正值得展开的读者问题"作为
Phase 5 主要章节的叙事入口。

每个问题必须满足:
  - 读者打开报告时确实会问这个问题(不是分析师自嗨)
  - 本报告有比市场更好的答案(能交付,不是装腔)
  - 答案会影响投资决策(不影响决策的问题不要)

每个问题附:
  - 问题的自然语言表述(准备直接进 Complete)
  - 本报告的答案骨架(300字以内)
  - 这个答案依赖 staging 里哪几个章节的发现
```

**产物**: `staging/{TICKER}_reader_questions.md`。这个文件是 Phase 5 组装的**叙事索引**,不是章节内容本身。

### 介入点 3: Phase 5 组装的写作纪律

Phase 5 组装时,**每写完一个主要章节(≥3000字)**,执行以下 5 重 self-check:

**Check 1 — 段落功能**: 每段只做一件事?
- 每段首句是否是该段的中心判断?
- 段内有没有混入另一个话题?
- 段落长度是否 > 400字?如果是,大概率混了多个功能

**Check 2 — 长短句节奏**: 这一章读起来有没有呼吸感?
- 连续 5 句以上 40+ 字无短句打断 → 拖沓
- 连续 10 句以上短句 → 碎片化,缺机制解释
- 短句用在哪: 段落开头亮相 / 段落结尾收束 / 强调关键判断
- 长句用在哪: 解释机制 / 展开条件链 / 描述多变量关系

**Check 3 — 观点-理由-证据**: 每个核心判断都能拆三层?
- 如果某段只有观点没有理由,要么补理由,要么删观点
- 如果只有证据没有观点,要么补观点,要么这段其实是别章的素材

**Check 4 — 知道 vs 判断分层**: 读者能分清你在讲什么?
- 硬数据 → 用具体数字和来源
- 推论 → 用"这意味着 / 因此"等因果语言,不用"显然 / 毋庸置疑"
- 猜测 → 用"可能 / 尚待验证",并说明触发验证的条件
- **禁止**用 hedging 掩盖判断层次(铁律 N 已覆盖)

**Check 5 — 无痕化扫描**: 这章有没有 AI 味词?
- 脑内扫一遍禁用词清单
- 如果出现,当场改掉,不等到脚本检查

### Phase 5 完成后的脚本扫描

```bash
bash scripts/ai_flavor_check.sh {REPORT_PATH}
```

输出 3 类信号:
- **AI 味词命中**: 列出行号和词,WARN
- **句长方差**: 计算全文平均句长和标准差,方差 < 阈值 → 节奏单调,WARN
- **套路转场词**: 命中"综上所述 / 值得一提的是 / 本节将..." → WARN

全部 WARN 不阻断 commit,但 Phase 5 autopsy 会读取 WARN 数,记录到 digest card。

## 五、吸收的 5 条减法规则(来自 rule-N-evidence-style.md)

以下 5 条从 Sprint 7 的减法规则吸收进本 Skill,rule-N 暂不删除(等灰度验证后再迁移)。

### 减法 1: 删 hedging 词

**禁用**(除非真不确定,那就明说"我们不知道"):
- 可能 / 或许 / 某种程度上 / 一定程度上 / 值得关注 / 有待观察
- 大概率 / 小概率 / 很可能 / 不无可能
- may / might / could / possibly / potentially

**正确写法**:
```
✗ "公司可能面临一定的竞争压力"
✓ "公司面临两个具体竞争压力: Innolight 的价格优势和 Coherent 的技术追赶"
```

真正不确定 → 直接"我们不知道 X"或"证据不足以判断 X",比 hedging 诚实 10 倍。

### 减法 2: 删箭头链

```
✗ "AI 需求↑ → GPU 出货↑ → 光模块需求↑ → LITE 收入↑ → 利润率扩张↑"
✓ "AI 需求驱动 GPU 出货,每个 GPU 需要 6 个光模块,LITE 是 200G/lane EML 的
   唯一量产供应商。这个传导链在 Q2FY26 的收入 +65% YoY 中已经体现。"
```

三个以上连续的 `→` 一律改为散文叙述。箭头链是"假装在思考"。

### 减法 3: 删审美形容词

**禁用**: 漂亮 / 优雅 / 干净利落 / 完美 / 出色 / 卓越 / 安静地 / 默默地

```
✗ "公司有漂亮的资产负债表"
✓ "Net cash $5.2B,debt-to-equity 0.15,比同业中位数低 60%"
```

审美形容词不传递信息,用具体数字替换。

### 减法 4: voice 微调

```
✗ "本报告认为..." / "笔者观察到..."
✓ "我们认为..." / "我们的观察是..."
```

不需要变成"朋友吃饭式",专业的"我们"足够。

### 减法 5: Top 5 必须包含范畴重分配

Phase 4.5 的 Top 5 lens,至少 3 条必须明确把公司从范畴 X 重分类到范畴 Y。

**模板**:
```
[公司] 不是 [旧范畴],而是 [新范畴]
→ 应该用 [新范畴的估值方法] 而不是 [旧范畴的估值方法]
→ 关键变量从 [旧变量] 变成 [新变量]
```

这一条不改写成自然语言(它是分析方法而非表达技巧)。

## 六、TOC 重构的精神与落地

### 宏观层原则: BLUF(Bottom Line Up Front),不是"已知到未知"

投资报告和一般说理文章有一个**结构冲突**: 通用写作原则(贝尔彻的"已知→未知/简单→复杂/过去→现在")假设读者有耐心陪你从基础走到结论。**投资报告的读者没有这种耐心**——专业投资者一天扫 5-20 份报告,前 2 分钟决定是否继续读。

所以宏观结构必须是 **BLUF**:
```
结论 → 证据 → 反方 → 细节
```
不是:
```
背景 → 铺垫 → 论证 → 结论
```

**贝尔彻 6 条原则在本 Skill 下的处理**:

| 原则 | 宏观用 | 微观用 | 说明 |
|------|--------|--------|------|
| 已知到未知 | ❌ | ✓ | 宏观违反 BLUF;章节内解释新机制时可用 |
| 简单到复杂 | ❌ | ✓ | 同上。宏观先说"最重要变量",不是"最简单变量" |
| **共识到争议** | **✅** | **✅** | 完全适合。这就是预期差的写法: 先市场共识,再分歧点 |
| 普通到特殊 | ⚠ 有条件 | ✓ | 行业分析可用,公司分析反而要先讲独特之处 |
| 过去到现在 | ❌ | ⚠ 短用 | 禁用"先回顾公司历史"。历史只在解释当前状态的因果时就地使用 |
| 空间依次展开 | ⚠ | ✓ | 只对"业务分部/分地区"有用 |

**宏观层的标准开头顺序**(服从 BLUF):
1. 执行摘要(核心判断 + 评级 + 公允价值)
2. 核心矛盾(读者为什么打开这份报告)
3. 最关键驱动变量(决定估值方向的 1-2 个)
4. 关键风险 / Kill Switch
5. 估值含义
6. 正文展开(按"影响力"排序,不是按"简单→复杂")

**微观层可用贝尔彻原则**:
- **共识到争议**(段落层): "市场认为 X → 证据 A、B → 但忽略了 C → 所以实际是 Y"。这是预期差的标准写法
- **已知到未知**(解释机制时): "读者熟悉的类比 → 这家公司的独特之处 → 为什么类比部分失效 → 真正的机制"
- **过去到现在**(因果解释时,必须短): "5 年前 GM 是 X%,今天是 Y%,这 Z 个百分点解释了..." —— **NEVER** 写"让我们先回顾公司历史"

### 精神: 允许围绕核心矛盾重构章节结构
- ASML 以地缘为主轴,不是以财务为主轴
- APP 以广告闭环为主轴,不是以产品线为主轴
- COST 以安全边际为主轴,不是以增长为主轴

### 落地: 保留一套"底盘章节"做防漏
- 执行摘要 / 业务 / 护城河 / 财务 / 估值 / 风险 / 红队 / 认知边界 → 仍然要有
- 但章节**顺序和篇幅权重**可以根据核心矛盾动态调整
- 主轴章节(解释核心矛盾的那几节)篇幅可以占到 40-50%

### 语言层禁八股(无论 TOC 怎么排)

**禁用**:
```
✗ "本节将从三个角度分析公司的护城河..."
✗ "首先,公司拥有强大的品牌。其次,公司有规模优势。最后,公司有转换成本..."
✗ "综上所述,公司的护城河是坚实的。"
```

**替代写法**:
```
✓ 直接切入: "公司的护城河能不能扛住 Amazon Fresh 的进攻,取决于一件事——
   会员续费率。过去 5 年这个数字从 X% 升到 Y%,背后的机制是..."
```

## 七、灰度期的执行要求

本 Skill 处于**灰度状态**:

1. **不进入铁律** — CLAUDE.md 不改,rule-N 的 5 条减法不删
2. **只在 Tier 2/3 中声明引用** — "本报告写作遵循 narrative-discipline v1.0(灰度)"
3. **跑完 1-2 份 Tier 2/3 报告后做效果评估**:
   - AI 味词命中数变化
   - 句长方差变化
   - 读者视角问题是否真的被识别到(还是只是走个流程)
   - 是否出现"过度压抑专业表达"的副作用
4. **评估通过才迁移**(迁移清单):
   - `rule-N-evidence-style.md` 的 **5 条减法规则** → 迁入本 Skill(已双写,删 rule-N 原文)
   - `rule-N-evidence-style.md` 的 **降认知负荷规则 A-F**(一段一事/先结论后展开/抽象词翻译/短句/比较因果/只写影响判断的信息) → 合并进本 Skill 第四章的段落 self-check,rule-N 原文删除
   - `rule-N-evidence-style.md` 的 **"3 秒检验"** → 合并进本 Skill 第九章的"快速自检卡",rule-N 原文删除
   - rule-N 保留: 证据链三层结构 / 因果推理密度门控 / 三 PE 并列 / 概率赋值三重锚定 / 专业友好型术语解释(这些是数据与论证纪律,不属于本 Skill 范围)
   - CLAUDE.md 加一行 Skill 引用
   - status 从 gray 改为 stable

## 九、快速自检卡(写作时贴在脑前)

每写完一章,30 秒自检:

```
□ 这一章服务的核心矛盾是什么?(说得出来)
□ 每段首句是否亮明了该段的中心判断?
□ 段与段之间有没有桥?读者能看出为什么这段接着上段写?
□ 有没有连续 5 句以上 40+ 字无短句打断?
□ 有没有只说"X 很强"而没有"因为 Y,所以..."的断言?
□ 读者能分清哪是事实、哪是推论、哪是猜测?
□ 有没有 AI 味词(谜题/承重墙/钩子/...)溜进来?
□ 有没有"综上所述 / 本节将..."这类八股转场?
□ 这一章删掉,核心矛盾的回答会不会塌?
```

9 项全过 → 章节可交付。任何一项不过 → 当场改,不留到组装。
