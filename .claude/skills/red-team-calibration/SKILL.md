# 红队双向校准器 v1.0

> **核心价值**: 完美校准的红队应该同时向上和向下调整。全部下调=系统性悲观偏差，全部不调=红队无效。至少1个CQ上调是健康红队的标志。
> **来源验证**: AMAT P4 (4/5但全部下调，暴露偏差) | GOOGL Ch19 (5/5，识别出"矛盾风险"实际降低了联合概率)

## 触发条件

Phase 4红队完成后、CQ置信度更新**之前**强制执行。

与`red-team-executor`和`cq-lifecycle-tracker`配合：红队产出→本Skill校准→CQ更新。

## 为什么需要这个Skill

| 问题 | AMAT的教训 | 本Skill的解决方案 |
|------|-----------|-----------------|
| 全部CQ下调 | 8/8下调，0上调，系统性悲观 | 强制识别≥1个过度悲观维度 |
| 概率敏感性缺失 | -2.1%结论在概率微调2-3%后翻转 | 附加概率±3%的评级影响测试 |
| 红队="永远看空" | P4被执行为"找问题"而非"校准" | 重新定义为双向校准 |

## 执行流程

### Step 1: 红队方向审计

在RT-1~RT-7完成后，汇总所有CQ调整方向：

```markdown
## 红队方向审计

| CQ | P3值 | RT建议P4值 | 方向 | RT来源 |
|----|:----:|:--------:|:---:|--------|
| CQ1 | 70% | 65% | ↓ | RT-1承重墙 |
| CQ2 | 65% | 60% | ↓ | RT-5黑天鹅 |
| CQ3 | 55% | 50% | ↓ | RT-5黑天鹅 |
| CQ4 | 55% | 45% | ↓↓ | RT-2偏差 |
| CQ5 | 80% | 75% | ↓ | RT-2偏差 |
| CQ6 | 65% | 60% | ↓ | RT-1承重墙 |
| CQ7 | 80% | 80% | → | — |
| CQ-B | 70% | 70% | → | — |

**方向统计**: ↓: 6 | →: 2 | ↑: 0
**诊断**: ⚠️ 零上调 — 触发双向校准
```

### Step 2: 过度悲观识别 (强制执行)

对每个CQ，显式问："**原始分析是否在这个维度上过度悲观?**"

```markdown
## 过度悲观检测

| CQ | 原始分析的悲观假设 | 有证据支持更乐观吗? | 结论 |
|----|------------------|:--:|------|
| CQ1 | "通才折价30-40%合理" | 有: 安装基础锁定创造转换成本 | **潜在上调候选** |
| CQ2 | "DRAM是双刃剑" | 部分: HBM4需求比周期更持久 | 维持 |
| CQ5 | "AGS 5x EV/Rev偏高" | 有: 经常性收入占比在提升 | **潜在上调候选** |
| CQ7 | "CapEx正常化路径清晰" | 已经是最稳健CQ | 维持 |
```

**强制规则**:
- 如果全部CQ建议下调，**必须**从潜在上调候选中选择≥1个执行上调
- 上调理由必须与下调理由同样严谨(有数据支撑)
- 如果真的没有任何CQ值得上调，必须写明："经审慎评估，所有CQ确认偏乐观，零上调的原因是[具体原因]"

### Step 3: 校准后CQ调整

```markdown
## 校准后CQ调整

| CQ | P3 | RT建议 | 校准后 | 变化 | 说明 |
|----|:--:|:-----:|:-----:|:---:|------|
| CQ1 | 70% | 65% | 67% | -3 | RT-1下调合理但幅度过大，安装基础转换成本被低估 |
| CQ5 | 80% | 75% | 77% | -3 | RT-2下调合理但5x→4x过于激进，3.5-4.5x更合理 |
| CQ4 | 55% | 45% | 45% | -10 | 确认：EPIC Center零收入，大幅下调合理 |
| ... | | | | | |

**校准前加权平均**: XX.X% (红队原始)
**校准后加权平均**: YY.Y% (双向校准后)
**偏差**: ZZ.Z pp
```

### Step 4: 概率敏感性分析 (AMAT缺失的关键)

**当期望回报在±10%以内时必须执行。**

```markdown
## 概率敏感性: 评级稳定性测试

**当前概率分配**:
| 场景 | 概率 | EV |
|------|:---:|:--:|
| S1(熊市) | 15% | $X B |
| S2(基准) | 45% | $Y B |
| S3(牛市) | 30% | $Z B |
| S4(超牛) | 10% | $W B |

**概率加权EV**: $XX B | **期望回报**: Y.Y%
**当前评级**: [X关注]

### 敏感性矩阵: 概率±3%的评级影响

| 调整 | 新概率分配 | 新期望回报 | 评级变化? |
|------|----------|:--------:|:-------:|
| S1+3%, S3-3% | 18/45/27/10 | Z1% | 是/否 |
| S2+3%, S3-3% | 15/48/27/10 | Z2% | 是/否 |
| S3+3%, S2-3% | 15/42/33/10 | Z3% | 是/否 |
| S4+3%, S3-3% | 15/45/27/13 | Z4% | 是/否 |
| S1-3%, S3+3% | 12/45/33/10 | Z5% | 是/否 |

### 稳定性结论
- **评级翻转需要的最小概率调整**: ±X% (在S_Y上)
- **评级稳定性**: 高(需>5%调整才翻转) / 中(3-5%) / 低(<3%即翻转)
- **建议**: [如果稳定性"低"，在报告中显式标注"评级对概率假设高度敏感"]
```

**AMAT教训**: -2.1%期望回报，S1概率从15%调到18%就可能翻转为审慎关注。这意味着"中性关注"结论**脆弱**——报告应该显式告知读者这一点。

### Step 5: 反向检验

对每个已执行的CQ调整，问："**如果反向调整，逻辑是否同样成立?**"

```markdown
## 反向检验

| CQ | 实际调整 | 反向假设 | 反向逻辑成立? |
|----|---------|---------|:----------:|
| CQ1 -5% | "通才折价合理" | "安装基础锁定被低估" | 部分成立 |
| CQ4 -10% | "EPIC零收入" | "Samsung合作是先行指标" | 弱,缺数据 |
```

**这一步的价值**: 暴露哪些调整是基于**强证据**(反向不成立)，哪些是基于**方向偏好**(反向同样成立)。后者应该减小调整幅度。

## 输出规范

写入CQ evolution更新之前，作为校准中间步骤:

| 指标 | 要求 |
|------|------|
| 方向审计 | 统计↑/→/↓比例 |
| 过度悲观检测 | 每个CQ检查 |
| 校准后调整表 | 含原始RT建议和校准后值 |
| 概率敏感性 | 期望回报±10%时必做 |
| 反向检验 | ≥3个CQ |

## 质量门控

| 检查项 | 要求 | 严重度 |
|--------|------|:------:|
| 方向审计完成 | ↑/→/↓统计 | BLOCK |
| 零上调有显式解释 | 或≥1个CQ上调 | BLOCK |
| 概率敏感性(期望回报±10%时) | 矩阵+稳定性结论 | BLOCK |
| 反向检验≥3个CQ | 标注强/弱证据 | WARN |
