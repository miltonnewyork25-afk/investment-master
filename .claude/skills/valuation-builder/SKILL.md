## 7个估值必须 (不满足=FAIL)

### 必须1: Reverse DCF起点

> **标杆**: CRM/KLAC/ANET/VRT全部使用 | **源自铁律O**

**在Phase 1 Ch1已完成Reverse DCF。Phase 2的职责是：**
1. 回顾Phase 1的Reverse DCF结论——市场隐含了什么假设？
2. 评估这些隐含假设是否合理(偏保守/偏激进/合理)
3. 用正向估值验证/挑战Reverse DCF的结论

```
Phase 1 Ch1: "市场在$150隐含FCF CAGR 8%"
Phase 2: "我们认为合理FCF CAGR是6-10%，取决于[具体假设]"
        → 如果合理=8% → 市场定价正确 → 中性关注
        → 如果合理=12% → 市场偏保守 → 关注
        → 如果合理=5% → 市场偏乐观 → 审慎关注
```

**检验**: 估值章节必须引用Phase 1的Reverse DCF数字，并明确说明"我们的正向估值与市场隐含假设是否一致"。

### 必须2: ≥3种独立估值方法 + 方法独立性审计

> **标杆**: ANET(5方法+审计) / CME(6方法+可信度排序)

**最少3种方法**:
- **DCF(概率加权)** — 至少3情景
- **SOTP 或 可比法** — 至少1种交叉验证
- **行业特有方法** — 根据公司特点选择(见下方行业模板)

**方法独立性审计**(ANET教训):
```
检查: 3+方法是否共享关键假设(Revenue CAGR/WACC/OPM)?
  如果3种方法都用同一个Revenue CAGR → 不是3重验证，是同一假设的3种包装
  必须标注: "方法A和B共享[收入增速]假设，因此收敛不代表独立验证"
```

### 必须3: ≥3情景概率加权 + 每情景绑定明确假设

> **标杆**: CRM(5情景) / CME(6情景双轴) / RCL(4情景+Tail)

**情景构建规则**:

```
每个情景必须回答3个问题:
1. 什么假设不同? (不是"乐观/悲观"，是"ARR增速12% vs 8%")
2. 为什么这个概率? (基准率/历史/可比，不是拍脑袋)
3. 这个情景下估值是多少? (DCF/P&L具体计算)

最低3情景:
  Bull (15-25%): [核心假设A成功 + 假设B成功]
  Base (40-55%): [核心假设A成功 + 假设B中性]
  Bear (20-35%): [核心假设A失败 或 宏观下行]

推荐加Tail (5-10%): [极端事件——衰退/监管/技术替代]
```

**情景叙事**(RCL标杆): 每个情景不只是数字表格，还有200-500字的"故事"——在这个情景下公司的处境是什么样的。

### 必须5: 离散度量化 + 诚实性声明

> **标杆**: KLAC(方法级1.74x vs 情景端点4.7x) / VRT(CV 44.5%)

**两种离散度必须分别报告**:
- **方法级离散度**: 3+种方法给出的fair value最高/最低比值。≤1.3x=紧收敛，≤1.5x=正常，>1.5x=需解释
- **情景级离散度**: Bull/Bear的EV比值。反映公司的不确定性程度

**诚实性声明**(KLAC教训):
```
"本报告X种估值方法的收敛(离散度X.Xx)可能部分反映共享假设(均使用WACC X%和
 Revenue CAGR X%)，而非完全独立的验证。如果[关键假设]不同，估值范围可能
 显著扩大。"
```

**门控**: 离散度>30%且未解释 = FAIL(铁律K/G7)

### 必须6: 敏感性矩阵(≥2维)

> **标杆**: RCL(P/E×EPS 6×6) / KLAC(WACC×g) / CRM(OPM×增速×WACC)

**最少2维敏感性矩阵**:
```
推荐组合(选最相关的):
  WACC × 终端增长率 → 对DCF影响(通用)
  OPM × 收入增速 → 对盈利影响(SaaS/科技)
  P/E × EPS → 对股价影响(成熟公司)
  产能利用率 × ASP → 对收入影响(半导体)
  RevPAR × 客房增速 → 对收入影响(酒店)
```

**矩阵要暴露**: 估值对哪个变量最脆弱(KLAC: WACC±100bp=$630差异=估值最脆弱)

### 必须7: 行业特有估值创新

> **标杆**: CME(Core PE) / VRT(双重身份SOTP) / RCL(ZREIP+YPD) / ANET(信念翻转)

**通用框架不能捕捉行业特有风险/机会。** 每份报告的估值必须有≥1个"只有深度理解这家公司才能做出的估值洞见"。

| 行业 | 常见的估值创新方向 |
|------|----------------|
| SaaS | NRR隐含的有机增速 vs 报告增速差距→真实增长率 |
| 金融基础设施 | Core PE(剥离非核心收入)→揭示真实估值水平 |
| 消费品 | 收入纯度还原→真实OPM→真实PE |
| 半导体 | 周期位置调整PE(峰值PE不可比) |
| 高增长 | 信念翻转测试(单假设失败→股价影响) |
| 强周期 | 零收入事件保险定价(ZREIP) |
| 多身份 | 双重/多重身份SOTP(不同部分用不同倍数) |

## 估值章节结构模板

```markdown
## Chapter X: Reverse DCF回顾与估值方法论选择
- Phase 1 Reverse DCF结论回顾
- 正向估值vs隐含假设的校准
- 方法论选择依据(为什么选这3+种)

## Chapter X+1: 情景构建与Pro-Forma P&L
- 3-5情景定义(假设绑定表)
- 每情景5年P&L + FCF预测
- 每情景200-500字叙事

## Chapter X+2: DCF + Python验证
- DCF模型参数(WACC/终端/CapEx)
- Python计算结果
- 残差校验(计算值 vs 手算≤2%)

## Chapter X+3: SOTP / 可比 / 行业特有方法
- 交叉验证方法
- 行业特有估值创新
- 方法独立性审计

## Chapter X+4: 综合判定
- 概率加权公允价值
- 离散度量化+诚实性声明
- 敏感性矩阵(≥2维)
- 不对称比(上行/下行赔率)
- "犯错窗口"(何时入场最合理——CME标杆)
```

**目标字符**: ≥40K(占报告15-20%)。PTC教训: 估值<15K=走过场。
