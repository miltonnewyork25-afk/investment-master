# First-Principles Interrogation Protocol v1.0

## 触发时机
Generator在Phase 1-2的每个核心业务变量分析时调用。不是Phase 4的后置提纯——是Phase 1-2的主动深挖。

## 核心理念

大多数投资分析停在第1-2层（"公司做什么""增速多少"）。
真正值钱的视角在第3-5层（"什么结构性力量会改变这个行业的存在前提"）。

```
第1层: 公司做什么（描述）→ 不值钱，所有人都知道
第2层: 做得好不好（评估）→ 有价值但不稀缺
第3层: 为什么能做好（机制）→ 有价值，开始稀缺
第4层: 什么会改变这个机制（变量）→ 非常有价值
第5层: 这个改变是否已被定价（预期差）→ 这就是alpha
```

**目标**: 每份报告至少有3个变量被逼问到第4-5层。

---

## 逼问方法论：五条追溯链

对每个核心业务变量，执行以下五条追溯链。不是每条都会产出洞见，但系统性执行确保不遗漏。

### Chain 1: 上游因果追溯（Supply Chain of Demand）

**问**: 这个变量的终极来源是什么？

```
CPRT示例:
  收入 ← 拍卖量 ← 事故车供给 ← 事故发生率 ← 驾驶行为+车辆安全技术
  → 终极变量: 自动驾驶渗透率
  → 逼问: L3+自动驾驶渗透到30%时，事故率下降多少？CPRT的TAM收缩多少？

SpaceX示例:
  收入 ← 发射次数 ← 卫星需求 ← 通信/遥感/导航需求 ← 地面替代方案的成本
  → 终极变量: 卫星vs地面方案的经济交叉点
  → 逼问: 每公斤发射成本降到$X时，哪些地面业务被卫星替代？TAM从$Y扩展到$Z？
```

**模板**:
```
收入/利润 ← [直接驱动] ← [二阶驱动] ← [三阶驱动] ← [终极变量]
逼问: [终极变量]变化X%时，[收入/利润]变化多少？
逼问: [终极变量]目前的趋势方向是什么？速度是什么？
逼问: 当前股价是否反映了[终极变量]的趋势？
```

### Chain 2: 结构性颠覆扫描（What Kills the Business?）

**问**: 什么技术/制度/行为变化会让这个业务的存在前提消失？

```
CPRT示例:
  存在前提: 车辆发生事故 → 保险公司需要处置 → CPRT拍卖
  颠覆: 自动驾驶消灭事故 → 保险行业萎缩 → 事故车供给枯竭
  时间框架: L4自动驾驶大规模部署 = 2030-2035?
  逼问: 在事故率下降30%的情景下，CPRT的EBITDA下降多少？

低空经济示例:
  存在前提(中国): 政策推动+空域改革+城市密度高
  存在前提(美国): FAA认证+保险体系+诉讼风险+郊区化
  差异: 中国=政府主导快速试点 vs 美国=市场主导缓慢认证
  逼问: 差异是暂时的(中国先走但美国会追上)还是结构性的(制度决定路径)?
```

**模板**:
```
存在前提: [这个业务为什么存在？]
颠覆场景: [什么变化会让这个前提不成立？]
时间框架: [颠覆在5年/10年/20年内发生的概率？]
逼问: 颠覆发生30%时，核心指标变化多少？
逼问: 当前股价隐含的颠覆概率是多少？（Reverse DCF反推）
```

### Chain 3: 跨行业传导扫描（Adjacent Industry Impact）

**问**: 哪个看似无关的行业变化会深刻影响这个公司？

```
CPRT示例:
  看似无关: 电动车渗透率
  实际传导: 电动车事故后维修成本更高(电池) → 更高比例判定全损 → 事故车供给反而增加
  逼问: 电动车渗透率提升是利好(更多全损车)还是利空(更少事故)?
  → 两个方向都有道理 → 这就是值得深挖的矛盾

SpaceX示例:
  看似无关: AI训练数据需求
  实际传导: AI需要全球遥感数据 → 卫星数据需求激增 → 发射需求增加
  逼问: AI数据需求对卫星发射频次的边际贡献是多少？
```

**模板**:
```
目标行业: [公司所在行业]
扫描范围: 上游供应商行业 / 下游客户行业 / 替代品行业 / 互补品行业 / 监管机构
对每个相邻行业问: 该行业正在发生什么结构性变化？
传导路径: [变化] → [传导机制] → [对目标公司的影响]
逼问: 这个传导是正面/负面/不确定？市场是否已知？
```

### Chain 4: 制度/法规差异追溯（Why Different Here vs There?）

**问**: 同一个业务在不同市场为什么表现不同？差异是制度性的还是暂时性的？

```
低空经济示例:
  中国: 空域管制由军方→民航局渐进放开 / 无人机监管框架2024已出
  美国: FAA Part 107→BVLOS豁免→Type Certification / 诉讼风险极高
  差异根源:
    ① 空域管理体制（军管vs民管）
    ② 认证速度（中国特事特办 vs FAA风险厌恶）
    ③ 保险/诉讼环境（中国低 vs 美国极高）
    ④ 城市形态（高密度适合 vs 郊区化不适合）
  逼问: 哪些差异是永久的（制度决定）？哪些是暂时的（时间问题）？
  → 永久差异 = 中国low-altitude经济可能是独立赛道，不能用美国类比定价

SpaceX示例:
  美国: ITAR出口管制 / 商业发射市场开放 / NASA采购支持
  中国: 商业航天2015才起步 / 国企主导 / 军民融合
  逼问: SpaceX的成本优势有多少来自制度（NASA合同+FAA快速认证）vs 技术（Raptor引擎+复用）？
  → 如果主要是制度 → 竞争对手在不同制度环境下可能更快追赶
```

**模板**:
```
市场A vs 市场B: 同一业务的表现差异
差异维度: 法规/认证/保险/诉讼/城市形态/政府角色/消费习惯
对每个维度: 差异是结构性(制度决定)还是暂时性(时间问题)?
逼问: 如果用A市场的估值框架看B市场，会犯什么错？
逼问: 差异中哪个维度解释力最强？（不要平铺，找主因）
```

### Chain 5: TAM框架构建（How Big Can This Really Be?）

**问**: 这个市场的终极规模是多少？用什么方法估算最诚实？

```
SpaceX示例:
  方法1（自上而下）: 全球航天市场$4000亿 × SpaceX可获份额
    问题: 航天市场定义模糊，包含大量政府支出
  方法2（自下而上）:
    发射服务: 年发射次数×每次$X → $Yb
    星链: 可覆盖人口×渗透率×ARPU → $Zb
    星舰应用: 点对点运输/太空旅游/月球基地 → $Wb（高度投机）
  方法3（替代成本）:
    星链替代的是: 光纤到户($X/户) + 海底电缆($Y) + 5G基站($Z)
    替代成本 = 地面方案总投资 × 卫星能替代的比例
  逼问: 三种方法的交叉验证结果是什么？
  逼问: 哪种方法最不依赖假设？（最诚实的那个）
  逼问: 市场当前用的是哪种方法？如果用错了方法→估值偏差多大？
```

**模板**:
```
方法1（自上而下）: 总市场 × 份额 → $X
方法2（自下而上）: 单位量 × 单价 × 渗透率 → $Y
方法3（替代成本/意愿支付）: 替代方案成本 × 替代比例 → $Z
交叉验证: X vs Y vs Z 的离散度
逼问: 三种方法的共同假设是什么？（共同假设=最脆弱的点）
逼问: 最保守的方法给出多大TAM？最乐观呢？离散度多少？
逼问: 市场当前隐含的TAM假设是多少？（Reverse DCF反推）
```

## 执行规范

### 何时执行
- Phase 1-2中，对每个**核心业务变量**（不是所有变量）执行
- "核心业务变量"= Sprint Contract中标记的Top 3-5驱动因素
- 每个变量选择最相关的2-3条Chain执行（不必全部5条）

### 逼问深度标准
```
第1轮逼问: "这个变量由什么驱动？" → 大多数分析师到这里
第2轮逼问: "那个驱动因素又由什么决定？" → 少数分析师到这里
第3轮逼问: "什么结构性力量会改变那个决定因素？" → 这里开始有alpha
第4轮逼问: "这个结构性变化是否已被定价？" → 这就是投资视角

最少到第3轮。如果第3轮的答案是"不知道/数据不可得"——诚实标注，
这本身就是一个认知边界发现。
```

### 产出格式
每次逼问完成后，产出一个First-Principles Lens Seed：

```yaml
# 写入lens_seed_registry.yaml
- id: "FP-SEED-001"
  type: "first_principles"  # 区别于普通seed
  title: "自动驾驶渗透率是CPRT的TAM终极变量"
  chain_used: "chain_1_upstream + chain_2_disruption"
  interrogation_depth: 4  # 逼问到第几轮

  causal_chain: |
    收入 ← 拍卖量 ← 事故车供给 ← 事故发生率 ← 自动驾驶渗透率

  first_principles_question: |
    L3+自动驾驶渗透到30%时，事故率下降多少？
    CPRT的TAM从$X缩到$Y？
    当前股价隐含的自动驾驶折价是多少？

  market_awareness: "部分已知但未量化定价"
  affects_valuation: true
  affects_load_bearing: true
  maturity: "developing"

  unknown_admitted: |
    自动驾驶渗透时间表高度不确定（±5年）
    电动车全损率提升可能部分抵消事故率下降
```

### 与Evaluator的衔接
Evaluator在Phase 1-2审查时新增检查项：

```
E11: First-Principles Depth
- 是否对Top 3-5核心变量执行了逼问？
- 逼问深度是否≥3轮？
- 是否产出了first_principles类型的Lens Seeds？
- 是否诚实标注了认知边界（"不知道"的部分）？
threshold: 7/10
fatal_if_below: 4  # 完全没做逼问 → FAIL
```

### 与Sprint Contract的衔接
Planner在Sprint Contract中标记哪些变量需要逼问：

```yaml
mandatory_analysis:
  - item: "First-Principles Interrogation on top 3 variables"
    trigger: "universal"
    variables_to_interrogate:
      - "核心收入驱动（上游追溯）"
      - "最大风险变量（颠覆扫描）"
      - "TAM假设（框架构建）"
    verification: "检查lens_seed_registry中type=first_principles的seeds≥3"
```

---

## 成本纪律

- 每个变量的逼问: ≤1000字产出（逼问本身要简洁）
- 每份报告: 3-5个变量 × 2-3条Chain = 6-15次逼问
- 不是所有逼问都产出洞见——没有洞见的逼问简短记录"已探索，未发现非共识视角"
- **不为逼问而逼问**: 如果第2轮就到了"这是常识"，停止。逼问到常识层就够了。
