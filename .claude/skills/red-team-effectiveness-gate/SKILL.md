# 红队有效性门控 v1.0

> **核心价值**: 红队的价值不在字数，在于是否改变了你的判断。41K字符说"你基本对"是失败；5K字符翻转一个CQ是成功。
> **来源验证**: MSFT v1.0 (41K红队产出, 净CQ变动0.6pp, RT-2恰好发现"报告偏悲观") | AMAT v1.0 (8/8全下调, 触发red-team-calibration)

## 触发条件

Phase 4完成后、Phase 5开始前**自动执行**。

与`red-team-calibration`(确保双向性)互补：calibration确保方向合理，effectiveness-gate确保幅度有效。

## 为什么需要这个Skill

`red-team-calibration`解决了AMAT的问题(全部下调→要求至少1个上调)。但MSFT暴露了一个新问题：红队完美满足了双向性要求(CQ2+5, CQ5-5, CQ-B-5)，但**净效果为零**。

| 指标 | AMAT P4 (触发calibration) | MSFT P4 (通过calibration但无效) |
|------|--------------------------|-------------------------------|
| CQ变动方向 | 8↓ 0→ 0↑ | 1↑ 5→ 2↓ |
| 净CQ变动 | -40pp (过度) | +0.6pp (无效) |
| 新发现 | 3个(温水煮青蛙等) | ~0个(全部已知论点重述) |
| 双向性 | ❌ FAIL → 修复 | ✅ PASS → 但仍然无效 |

**核心诊断**: MSFT的红队是"表演性"的——它产出了7个RT章节、82个DM锚点、3张Mermaid图，看起来很专业，但没有改变任何实质判断。

## 执行流程

### Step 1: 三指标计算

Phase 4完成后，计算以下指标:

```markdown
## 红队有效性审计

### 指标1: 净CQ变动强度

| CQ | Phase 3值 | Phase 4值 | 变动 |
|----|:---------:|:---------:|:----:|
| CQ1 | 60% | 60% | 0 |
| CQ2 | 45% | 50% | +5 |
| CQ3 | 55% | 55% | 0 |
| CQ4 | 45% | 45% | 0 |
| CQ5 | 80% | 75% | -5 |
| CQ6 | 65% | 65% | 0 |
| CQ7 | 50% | 50% | 0 |
| CQ-B | 60% | 55% | -5 |

**绝对变动总和**: |+5| + |-5| + |-5| = 15pp
**CQ数量**: 8
**平均绝对变动**: 15/8 = 1.9pp
**净变动**: +5-5-5 = -5pp → 除以8 = -0.6pp

⚠️ 平均绝对变动 < 2pp → 标记为"低效红队"
```

**阈值**:
- 平均绝对变动 ≥ 3pp: 有效红队 ✅
- 2-3pp: 边界有效 ⚠️
- < 2pp: 低效红队 ❌ → 触发Step 4强制补救

### 指标2: 新发现计数

逐一检查RT-1~RT-7的核心论点，判断是否在Phase 1-3中**完全未触及**:

```markdown
### 新发现清单

| RT | 核心论点 | Phase 1-3已有? | 新发现? |
|----|---------|:------------:|:------:|
| RT-1 | W3(CapEx/FCF)最脆弱 | Ch12已识别 | ❌ |
| RT-2 | 锚定偏差+IBM叙事 | 新维度 | ✅ |
| RT-3 | AI资本毁灭4/5威胁 | Ch6已覆盖 | ❌ |
| RT-5 | BS-6 OpenAI IPO $40-70B | 新定量 | ✅ |
| RT-7 | GPU预囤积20-25% | 新解释 | ✅ |

**新发现数**: 3/7
```

**阈值**:
- ≥ 3个新发现: 有效红队 ✅
- 1-2个: 边界 ⚠️
- 0个: 无新信息 ❌ → 触发Step 4

### 指标3: RT-2偏差审计方向检测

RT-2(认知偏差审计)应该客观识别偏差方向。但如果RT-2恰好发现报告偏向有利于当前评级的方向，需要警惕**确认偏差的确认偏差**:

```markdown
### RT-2方向检测

当前评级倾向: 中性关注(轻微偏乐观, +4.4%)
RT-2发现的偏差方向: "报告整体偏悲观2-4pp" → 建议上调Bull概率

⚠️ RT-2发现报告"偏悲观" → 支持更乐观的方向
   当前评级已经是轻微乐观(+4.4%)
   RT-2的"偏悲观"发现恰好强化了当前评级方向

**诊断**: 确认偏差嫌疑 — RT-2的结论支持了现有立场而非挑战它
```

**判断逻辑**:
- 如果当前评级偏乐观(期望回报>0)，且RT-2发现"报告偏悲观" → ⚠️ 确认偏差嫌疑
- 如果当前评级偏悲观(期望回报<0)，且RT-2发现"报告偏乐观" → ⚠️ 确认偏差嫌疑
- 如果RT-2发现的方向与当前评级**相反** → ✅ 红队在真正挑战

### Step 2: 综合诊断

```markdown
## 有效性综合诊断

| 指标 | 结果 | 状态 |
|------|------|:----:|
| 平均绝对CQ变动 | 1.9pp | ❌ 低效 |
| 新发现数 | 3/7 | ✅ 有效 |
| RT-2方向 | 确认偏差嫌疑 | ⚠️ |

**综合判断**: 2/3指标异常 → 触发强制补救
```

**触发规则**: 三项中≥2项被标记(❌或⚠️)→ 进入Step 4强制补救。

### Step 3: 记录与标注 (无需补救时)

如果≤1项异常，记录审计结果到checkpoint.yaml并继续Phase 5:

```yaml
phase_4_effectiveness:
  avg_absolute_cq_change: 3.2pp
  new_findings: 4/7
  rt2_direction: challenging  # or confirming
  verdict: effective
```

### Step 4: 强制补救 (≥2项异常时)

**补救措施(选择一项)**:

#### 选项A: 重做一条CQ深挖
选择红队中变动最小的CQ(例如CQ1 0pp变动)，重新执行专项审查:
- 搜索该CQ的最新外部证据(WebSearch)
- 寻找Phase 1-3未考虑的反面论点
- 强制产出≥5pp的调整(上调或下调)，并给出完整推导

#### 选项B: 引入外部锚点
对RT-2的偏差审计结论进行外部验证:
- 搜索3篇卖方研报的评级分布
- 搜索Polymarket相关事件概率
- 如果外部证据支持RT-2的方向，确认；如果不支持，逆转RT-2的调整

#### 选项C: 承认红队局限
在Phase 5的AI能力边界声明中增加:
```markdown
6. **红队局限**: Phase 4红队审查未能产出对现有判断的显著修正
   (平均CQ变动<2pp)。这可能意味着Phase 1-3的分析已经足够均衡，
   也可能意味着红队未能突破初始分析的框架。读者应注意本报告
   可能存在未被识别的系统性偏差。
```

**禁止**: 仅靠增加红队文字量来"修复"有效性问题。5K字符的有效红队 > 50K字符的表演性红队。

## 质量门控

| 检查项 | 要求 | 严重度 |
|--------|------|:------:|
| 三指标计算完成 | 必须有数值 | BLOCK |
| 综合诊断给出 | effective/marginal/ineffective | BLOCK |
| ≥2项异常时执行补救 | 选项A/B/C之一 | BLOCK |
| 补救结果记入checkpoint | yaml更新 | WARN |
