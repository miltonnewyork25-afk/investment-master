# 产业链全景分析器 v1.0 (Industry Chain Mapper)

> **定位**: 把一条产业链做成"谁在哪个周期、谁拿到利润、谁先被去杠杆、谁被市场重新定价"的完整分析。跨行业可迁移,不只服务 AI 产业链。
> **产出**: `reports/{CHAIN_NAME}/Chain_Framework_{DATE}.md`(目标 70-100K 字符)+ `reports/{CHAIN_NAME}/data/chain_skeleton.yaml`(结构化骨架)
> **v1.0 首次验证**: AI 产业链报告(2026-04-20)——20+ 公司、74K 字符、通过四层结构 + 四把尺子完成"地图 / 尺子 / 时间 / 结构 / 情景 / 行动"六部分收敛。

---

## 一、这个 skill 解决什么问题

普通产业链报告最常见的三个问题:

1. **只列"谁在链上",不回答"谁拿到钱"**——读完还是不知道哪家值得买。
2. **把节点相近的公司混成一组**——例如把所有"AI 电力"放一篮子、把所有"AI 测试"放一篮子,忽略它们在信用 / 商誉 / FCFE / 客户集中度上的巨大差异。
3. **风险章节用"宏观不确定性"等通用词搪塞**——不写清楚"下一轮回调时谁先被重定价"。

这个 skill 强制用 21 个分析角度 + 6 部分收敛结构,确保上述三个问题都被具体回答。

## 二、触发条件

| 场景 | 触发 |
|------|------|
| **手动** | `/chain-map {CHAIN_NAME}`(例 `/chain-map AI` / `/chain-map EV` / `/chain-map Obesity`) |
| **跨报告复盘** | 完成 ≥5 家同行业独立公司报告后,自动建议触发,把个股视角升级到链条视角 |
| **行业切换期** | 当一个行业出现"主题转折 / 资金轮动 / 信用弱点暴露"三者任一时,触发链条层面重绘 |

**不触发场景**:
- 单一公司分析(用 Tier 1-3 公司分析 skill)
- 子链分析(用各自专用 skill,例 `moat-evaluator`、`valuation-builder`)

## 三、六部分收敛结构(全报告骨架)

这是任何产业链报告的**强制骨架**。21 个分析角度分配到 6 个部分,不允许重排:

| 部分 | 名字 | 核心任务 | 对应章节 |
|------|------|---------|---------|
| **A. 地图** | 谁在哪 | 确定四层结构 + 玩家数 + 市值分档 | Ch 1-3 |
| **B. 尺子** | 怎么判 | 四把尺子 + 分层估值 + 离散度 + SBC 幻觉 | Ch 4-7 |
| **C. 时间** | 什么时候 | 订单瀑布 + 利润归属 + CapEx 分配 | Ch 8-10 |
| **D. 结构** | 谁会先破 | 信用传导 + 象限模型 + 三种贵 + 拥挤度 | Ch 11-14 |
| **E. 情景** | 会怎样 | 三情景 + 压力测试 + 混读组 | Ch 15-17 |
| **F. 行动** | 做什么 | 三池 + 回调应对 + 跟踪 + 投资者分型 + 钉子 | Ch 18-22 |

## 四、21 个分析角度(必须全部包含)

### Part A: 地图层(3 角度)

#### 角度 1:四层结构 + 信用弱点第四层

把产业链画成三层**物理/商业/经济**结构,再叠加第四层**信用弱点**(横跨前三层)。

| 层级 | 含义 | AI 链示例 | 通用模板 |
|------|------|----------|---------|
| L1 物理瓶颈层 | 决定"够不够"的核心环节 | GPU / HBM / 先进制程 / EUV | 行业核心不可替代环节 |
| L2 扩散层 | 决定"能不能交付"的执行环节 | 光模块 / PCB / 配电 / 服务器 | 围绕核心的关键配套 |
| L3 外围商业化层 | 决定"变成钱"的最终通路 | SaaS / 公用事业 / REIT | 终端收入承接者 |
| L4 信用弱点层 | 横跨前三层,下轮去杠杆时先被重定价 | ORCL / LITE / HPE | 满足 ≥2 条:净债/EBITDA>5x、FCFE 转负、CapEx/Rev>40%、Current Ratio<1、Goodwill/Assets>50%、单一客户>30% |

**强制要求**: L4 必须单独显式化,不能隐性埋藏在风险章里。

#### 角度 2:每层玩家数量 + 定价权趋势

对每个节点列:
- 玩家数量(1 家垄断 / 2-3 家寡头 / 4-6 家分化 / >6 家充分竞争)
- 定价权趋势(过去 2 年增强 ↑ / 稳定 → / 削弱 ↓)

**为什么必填**: 玩家数 + 定价权趋势的乘积,决定了这个节点的利润是会变多还是变少——纯粹的静态玩家数无法区分"稳定垄断"和"被蚕食的垄断"。

#### 角度 3:按市值分档扫描

所有标的按市值分四档:
- 大盘(>$500B):信用弹性强,回调是避险
- 中大盘($100-500B):估值分化最明显
- 中盘($10-100B):基本面 vs 估值差异最大
- 小盘(<$10B):质量异类 vs 高流动性风险

**产出**:每档一张表(公司 / 市值 / 链上位置 / 核心风险 / 建议)。

### Part B: 尺子层(4 角度)

#### 角度 4:四把尺子(核心判断框架)

任何公司都必须同时通过四把尺子才能进入"核心池":

1. **节点不可替代性**(护城河):3 级分类——最不可替代 / 高但非垄断 / 易被补
2. **利润留存能力**(定价权):毛利率稳定性 < 5pp 波动;ROIC > WACC + 5pp;SBC/Rev < 10%
3. **资本开支回报可测性**:ROI 是否被 guidance 过 / CapEx 和收入的先后顺序 / 是否分开披露"增长性"与"维持性"
4. **衰退/回调中的信用弹性**:净债/EBITDA<3x、Current Ratio>1.5、FCFE>0

**强制**: 报告必须列出"四把尺子同时通过的名单"(通常只有 5-10 家),这就是真正的核心池。

#### 角度 5:分层估值尺子

每个子链有自己的"正确尺子",用错尺子会产生系统性误判:

| 子链类型 | 不该只看什么 | 应该同时看 |
|---------|-------------|-----------|
| 核心垄断节点 | PE | PE + 毛利稳定性 + FCF + ROIC |
| 周期内存/原料 | Forward PE | 跨周期利润 + EV/EBITDA + 供给曲线 |
| 重资产代工/生产 | PE | PE + EV/EBIT + CapEx intensity + FCF |
| 关键设备 | 收入增速 | PE + ROIC + 订单质量(backlog + book-to-bill) |
| 高客户集中度零部件 | 收入和 PE | EV/EBITDA + 净债 + 客户集中 + ASP 趋势 |
| 组装/集成 | PE | EV/EBITDA + 营运资本 + 净债 + 现金转换 |
| 重并购成长 | PE | PE + backlog + book-to-bill + FCF + 商誉占比 |
| 软件订阅 | PE | FCF + usage(非 seat) + workflow 迁移证据 |

**强制**: 报告必须列出"哪个子链用哪把尺子"的对照表。

#### 角度 6:估值离散度诚实性测试

对核心公司同时用 4 种方法(DCF / EV/EBITDA / P/FCF / 相对估值),计算离散度 = (最高 - 最低) / 均值。

| 离散度 | 判定 |
|-------|------|
| <15% | 质量可信 |
| 15-30% | 合理 |
| 30-50% | 警告,单一方法不足以锚定公允 |
| >50% | 极高,"这家公司的估值取决于你相信哪个故事" |

**强制**: 报告必须对至少 8 家核心公司跑这个测试。离散度最低的公司 = 质量硬证据。

#### 角度 7:SBC 稀释量化(Owner PE 幻觉倍数)

对 SBC/Rev > 5% 的公司,计算:

```
Owner PE = 市值 / (GAAP 净利润 - SBC)
幻觉倍数 = Owner PE / Non-GAAP PE
```

- 幻觉倍数 < 1.3x:Non-GAAP 可用
- 1.3-2.0x:需要同时看两套
- >2.0x:Non-GAAP 是永久性光学折扣(典型:AVGO 2.7x)
- Owner 利润为负:意味着"剥离 SBC 后公司实际在亏钱"(典型:LITE / DDOG)

**强制**: 所有 SBC/Rev > 5% 的标的,不允许只用 Non-GAAP PE 讨论估值。

### Part C: 时间层(3 角度)

#### 角度 8:订单瀑布 + 时滞

把"预算决定 → 订单 → 收入 → 利润 → 现金"拆成 8 个时点(T+0、T+60d、T+90d、T+180d、T+270d、T+360d、T+540d、T+720d),每个时点标出受益公司。

**强制规则**:
- 下行传导是反的:平台先减 CapEx,最后才传导到末端配套
- 每个主题会产生 3-5 个先后股价高点,不只一个
- 当上游见顶时,下游可能还有 6-12 个月的惯性

#### 角度 9:利润最终归属五层

区分"谁拿收入"和"谁拿利润",明确五层:

1. 预算决定层:谁决定花出去
2. 收入承接层:谁先拿订单
3. 毛利承接层:谁定价权强
4. 现金流承接层:谁转 FCF
5. 股东回报承接层:谁把利润留下(回购 / 股息 / 复利)

**强制**:每家公司必须定位在这五层之一。列"收入层 → 利润层 → 股东回报层"的漏斗图。

#### 角度 10:CapEx / 总需求分配到供应链的映射

把本轮行业总资本开支(或总 TAM)按百分比分配到各子链。例如 AI 链 2026 $830B:
- GPU 30% / HBM 8% / 代工 12% / 设备 10% / 网络 7% / 光模块 4% / 服务器 10% / 配电 6% / 电力 4% / 软件 3% / DC 建设 3% / 其他 3%

**强制**: 这个分配决定了"市场给谁溢价"的合理锚——如果一家公司市值隐含份额 > 实际份额 2 倍,就是身份溢价型贵。

### Part D: 结构层(4 角度)

#### 角度 11:信用传导五层瀑布

```
Layer 1: 总需求决定者(平台/终端/政府)
  ↓ 90 天 DPO + 18 月 lead time
Layer 2: 核心硬件/核心材料
  ↓ 60 天 DPO + 12 月 lead time
Layer 3: 扩散层
  ↓ 45 天 DPO + 6 月 lead time
Layer 4: 配套与执行层
  ↓ 30 天 DPO + 3 月 lead time
Layer 5: 二级材料与组件
```

**监测点(5 个,任一触发 → 整个链需要重定价)**:
1. 需求层 Top 3 CapEx guidance 下修 >10-15%
2. 首次披露的 utilization 低于经济阈值(因行业而异)
3. 执行层的 DPO(应付账款)延长 >70 天
4. 扩散层任一 Current Ratio < 1.0
5. 信用弱点层任一新发债增加净债/EBITDA >1x

#### 角度 12:二维象限模型(周期位置 × 信用强弱)

```
             信用强(A/A+)
                    |
         [第一象限]    |   [第四象限]
       前中段 × 信用强 | 中后段 × 信用强
                    |
周期早 —————————————+————————————— 周期晚
                    |
         [第二象限]    |   [第三象限]
       前中段 × 信用弱 | 中后段 × 信用弱
                    |
             信用弱(B-/C)
```

- **第一象限** = 核心重点研究
- **第四象限** = 核心但贵(回调时值得再进)
- **第二象限** = 交易型,不适合长期
- **第三象限** = 回避

**强制**: 每家 Top 20 公司必须被定位到四象限之一。

#### 角度 13:三种"贵"

区分:

| 类型 | 贵的理由 | 回调跌幅 | 代表 |
|------|---------|---------|------|
| **质量型贵** | 基本面真实,估值前置 | -25%~-40% | 核心垄断节点 |
| **题材型贵** | 情绪 + 仓位拥挤,基本面跟不上 | -50%~-80% | 高 PE + ROIC<WACC + 客户集中 |
| **身份溢价型贵** | 被市场贴上更高身份,但真实业务占比不符 | -25%~-40%(温水) | 身份缺口 >30pp 的混合业务公司 |

**强制**: 每家高 PE 公司必须被归到三种贵的一种,并给出判断依据。

#### 角度 14:拥挤度 + 持有人脆弱性

三个子指标:
- 主题 ETF 持仓占比(>20% = 高拥挤)
- 对冲基金多空净仓位(Net Length 相对过去 3 年分布)
- 长期价值型 vs 高 beta 主题资金占比

**强制**: 每家 PE > 100x 或者过去 12 月涨幅 > +300% 的公司,必须标注拥挤度。

---

### Part E: 情景层(3 角度)

#### 角度 15:三种宏观情景 + 概率加权

Bull / Base / Bear 三情景,明确:
- 每种情景的触发条件(具体数据,不是概念)
- 每种情景的概率(当前观察)
- 每家公司在每种情景下的涨跌幅
- 按概率加权后的期望收益排序

**强制**: 不允许只给"正面/中性/负面"的定性描述,必须有具体触发条件 + 具体涨跌百分比。

#### 角度 16:压力测试七场景

最少 7 个具体压力测试:
1. 龙头下游单季度增速首次跌破关键阈值
2. 终端需求决定者下调 CapEx guidance >10-15%
3. 利率环境突变(例 10 年期美债 +100bps)
4. 主题 ETF 单月跌幅 >15%
5. 外生事件(地缘 / 监管 / 审计)冲击
6. 关键原料价格单月跌幅 >20%
7. 货币政策超预期转向

每个场景下列出:触发公司(跌幅)+ 相对抗跌。

#### 角度 17:混读组分析(≥5 组)

找出"节点相近但投资逻辑不同"的公司组合,至少 5 组。每组必须展示:
- 为什么容易被混在一起
- 哪个维度上它们其实完全不同
- 数据表对比
- 投资含义

**强制**: 混读组是检验分析深度的关键——如果写不出 5 组,说明链条还没拆清楚。

---

### Part F: 行动层(5 角度)

#### 角度 18:三池分配(核心/研究/交易/回避)

- **核心池**:四把尺子同时过 + 第一或第四象限
- **研究池**:三把尺子过 + 等特定触发条件
- **交易池**:高 beta / 高拥挤 / 短期窗口
- **回避池**:信用弱点层 + 基本面 + 信用都弱

**强制**: 每家覆盖公司必须定位到这四池之一,不允许留白。

#### 角度 19:回调应对(四层操作)

- 第一层:回调优先重看(越跌越值得)
- 第二层:需要确认节奏(等 -35~-45% 再入场)
- 第三层:只做反弹交易(1% 仓位 + 严格止损)
- 第四层:回调时先回避(便宜 ≠ 安全)

**强制**: 给出 Bear 情景下的组合模拟,量化"质量版组合" vs "题材版组合"跌幅差距。

#### 角度 20:跟踪清单(按频率分层)

- **每日**(10 分钟):股价 / 利率 / 情绪 ETF / VIX
- **每周**:关键产能利用率 / 龙头供应链价格
- **每月**:原料价格 / 客户应付账款 / 出口数据
- **每季度**(财报季):Top 20 全覆盖的"必答问题清单"
- **每年**(结构性变量):竞争格局演变 / 代际切换 / 政策路径

**强制**: 每个指标必须标注数据源 + 触发重排序的具体阈值。

#### 角度 21:九个钉子固化(读者带走什么)

报告最后列 **正好 9 个**"如果读者只记住 9 件事"的锚点。

格式要求:
- 每个钉子 ≤ 40 字
- 必须包含具体公司名或数字
- 九个钉子加起来覆盖 Part A-E 每一部分至少一次
- 写作节奏:第 1-3 个最意外、4-6 个最可操作、7-9 个最系统性

## 五、执行流程(9 步)

### Step 1: 链条范围确认
```
输入:
- CHAIN_NAME(例:AI / EV / Obesity / Data Center Power)
- 覆盖公司数(建议 20-60 家)
- 时间锚点(必须精确到日,例 2026-04-20)
```

### Step 2: 读取已有独立公司报告
```bash
ls reports/ | grep -iE "{CHAIN_KEYWORDS}"
```
如果 ≥ 5 家有 Tier 3 深度报告,优先用它们的概率加权公允价值作为评级锚。

### Step 3: 拉取 FMP FY25 Q4 / 最新季度数据
每家公司必须有以下 12 项最新季度数据:
- PE / EV/EBITDA / EV/Sales
- ROE / ROIC
- 净债/EBITDA / Current Ratio / Quick Ratio
- FCFE(季度) / CapEx/Revenue / SBC/Revenue
- Goodwill/Total Assets

**禁止使用年化代理**(会系统性低估并购 + CapEx 周期期间的真实杠杆)。

### Step 4: 构建 chain_skeleton.yaml

产出 `reports/{CHAIN_NAME}/data/chain_skeleton.yaml`:

```yaml
chain_name: {CHAIN_NAME}
date: {YYYY-MM-DD}

layers:
  L1_physical_bottleneck:
    nodes: [...]
    companies: [...]
  L2_diffusion:
    nodes: [...]
    companies: [...]
  L3_commercialization:
    nodes: [...]
    companies: [...]
  L4_credit_weakness:  # 必填, 跨层
    companies: [...]  # 必须给出 ≥2 条入选依据

four_rulers:
  pass_all_4:  # 四把尺子同时过的公司
    - ticker: xxx
      replaceability: 高/中/低
      pricing_power: 高/中/低
      capex_roi_measurable: 高/中/低
      credit_elasticity: 高/中/低

quadrants:
  Q1_early_strong: [...]
  Q2_early_weak: [...]
  Q3_late_weak: [...]
  Q4_late_strong: [...]

three_types_of_expensive:
  quality: [...]
  theme: [...]
  identity_premium: [...]

three_scenarios:
  bull: {probability: 0.25, triggers: [...]}
  base: {probability: 0.50, triggers: [...]}
  bear: {probability: 0.25, triggers: [...]}

pools:
  core: [...]
  research: [...]
  trading: [...]
  avoid: [...]

nine_nails: []  # 倒数第二章填,每个 ≤40 字
```

### Step 5: 按六部分收敛结构撰写章节

严格按 Part A→B→C→D→E→F 顺序,不允许重排。每章至少 1500 字,核心章节 3000+ 字。

### Step 6: 压力测试 + 混读组(最强的"拆分")

Part E 是这个 skill 最容易被偷懒的部分。强制检查:
- 三情景每家公司涨跌幅具体数字 ✓
- 7 个压力测试场景齐全 ✓
- 至少 5 组混读组,每组对比表齐全 ✓

### Step 7: 跟踪清单 + 投资者分型

Part F 是"给不同读者的行动指南"。至少 4 种投资者类型:
- 长线价值(3-5 年)
- 成长/GARP
- 主题交易
- 风险厌恶

### Step 8: 九个钉子写作(最后一章)

倒数第二章必须是"九个钉子"。不是总结,是"如果读者只带走 9 件事"。

**严格规则**:
- 每个钉子 ≤ 40 字
- 不允许类似"AI 行业很重要"这种无信息句
- 必须包含具体数字或公司名
- 九个里至少 3 个是"反直觉的发现"(读者本来不这么想)

### Step 9: 无痕化检查(提交前)

```bash
# 验证脚本
grep -cE "v[0-9]+|原报告|修订说明|重写|Phase|Agent|staging|skill" {REPORT}
# 期望输出: 0

grep -cE "回流|校准|深度研报|本次|Tier [0-9]" {REPORT}
# 期望输出: 0 或仅限于"后续可做的独立深度研究"正当用法
```

读者是"没有背景的终端投资者",不是"研究同行"。任何过程暴露都违反第零律。

## 七、泛化指引(迁移到其他行业)

这套框架已在 AI 产业链上完成 v1.0 验证(2026-04-20)。迁移到其他行业时,只需替换每层的含义:

| 行业 | L1 物理瓶颈 | L2 扩散 | L3 商业化 | L4 信用弱点候选 |
|------|------------|---------|----------|-----------------|
| AI | GPU / HBM / 先进制程 | 网络 / 光模块 / 配电 | SaaS / DC REIT | 高 CapEx 云厂 / 高杠杆光模块 |
| EV | 电池材料 / 碳化硅 / 电驱 | 充电桩 / 电池管理 / 轻量化 | 整车 OEM | 高负债新势力 / 商誉重的并购 OEM |
| 肥胖药 (GLP-1) | API 原料药 / 肽合成 | Pen 装置 / 包装 / 冷链 | CRO / 支付 / 保险 | 单一产品依赖 + 专利悬崖 |
| 数据中心电力 | 核电 / 燃气轮机 | 变压器 / UPS / 配电柜 | IPP / 电网 / REIT | 重补贴 / 重并购 / 长周期 PPA |
| 太空 | 火箭 / 卫星载荷 / 芯片抗辐射 | 地面站 / 发射场 / 保险 | 卫星电信 / 遥感服务 | 未盈利 SPAC / 政府合同依赖 |
| 半导体设备 | EUV / 缺陷检测 | 刻蚀沉积 / ALD / CMP | OSAT / 测试服务 | 高中国敞口 / 高客户集中 |
| 生物药 CDMO | 细胞培养 / 抗体纯化 | 填装 / 冷链 / QC | 临床阶段药企 / 大药企 | 单客户 >40% |

**判断 L4 的通用标准(不分行业)**:
同时满足 ≥2 条 = L4 候选
- 净债/EBITDA > 5x
- FCFE 转负
- CapEx/Revenue > 40%
- Current Ratio < 1.0
- Goodwill/Total Assets > 50%
- 单一客户 > 30%

## 八、反向约束(NEVER)

1. **NEVER 只列玩家不问"谁拿利润"** — 所有覆盖公司必须走完五层利润归属
2. **NEVER 把节点相近的公司写成"差不多"** — 混读组分析 ≥5 组是强制
3. **NEVER 用年化代理替代季度口径** — 并购 / CapEx 周期会让年化严重低估真实杠杆
4. **NEVER 跳过 L4 信用弱点层** — 风险章里埋藏不算,必须独立小节显式化
5. **NEVER 用单一估值方法** — 核心公司必须跑 4 种方法的离散度测试
6. **NEVER 只用 Non-GAAP PE 讨论 SBC/Rev > 5% 的公司** — Owner PE 必须同时出现
7. **NEVER 把"宏观不确定性"当风险主段** — 风险必须按子链写,不按情绪写
8. **NEVER 给情景只打"正/中/负"** — 必须有具体触发条件 + 具体涨跌幅
9. **NEVER 写 >9 个钉子或 <9 个钉子** — 正好 9 个,每个 ≤40 字
10. **NEVER 在最终报告暴露过程** — 不允许"本报告修订 / Phase / Agent / staging / 独立深度研报"等工程化词汇

## 十一、v1.0 已知限制

- 首次验证只跑过 AI 产业链一条,其他行业需要第二轮验证来打磨 L1-L4 分层标准
- 混读组的"≥5 组"是硬下限,但有些小链条可能找不到 5 组——此时允许降到 3 组,但要在报告中说明"本链条节点差异已经很清晰,不需要更多混读对比"
- 九个钉子的"反直觉比例 ≥ 3/9"是经验法则,不是硬规则
- 跟踪清单的"每日/每周/每月/每季/每年"五层是对高关注度链条的设置;冷门链条可以压到"每月/每季/每年"三层

---

**一句话定位**: 把一条产业链从"谁在链上"升级到"谁在哪个周期、谁拿利润、谁先被去杠杆、谁被市场重新定价"——用 6 部分 × 21 角度的固化骨架,保证跨行业可迁移、不偷懒、不遗漏。
