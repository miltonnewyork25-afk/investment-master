# 产业链全景分析器 v2.0 (Industry Chain Mapper)

> **定位**: 把一条产业链做成"谁在哪个周期、谁拿到利润、谁先被去杠杆、谁被市场重新定价"的完整分析。跨行业可迁移,不只服务 AI 产业链。
> **产出**: (1) `reports/{CHAIN_NAME}/Chain_Framework_{DATE}.md`(目标 70-100K 字符)(2) `reports/{CHAIN_NAME}/data/chain_skeleton.yaml`(结构化骨架)(3) **`reports/{CHAIN_NAME}/data/module_master_table_{DATE}.md`(12 列母表,v2.0 新增硬产出)**
> **v1.0 → v2.0 升级核心**: 把"21 个分析角度"重新装进"四层系统图 + 12 列母表"的**更稳定、更可迁移、更可复用**的架构里。21 角度不砍,变成每层的分析深度;母表是跨板块迁移的共用底板。
> **v1.0 首次验证**: AI 产业链报告(2026-04-20)——20+ 公司、74K 字符。
> **v2.0 验证**: AI 产业链 v6(2026-04-20)——四层系统图 + 12 列母表 + 四个核心修正 + 8 问工作法。

---

## 一、这个 skill 解决什么问题

普通产业链报告最常见的三个问题:

1. **只列"谁在链上",不回答"谁拿到钱"**——读完还是不知道哪家值得买。
2. **把节点相近的公司混成一组**——例如把所有"AI 电力"放一篮子、把所有"AI 测试"放一篮子,忽略它们在信用 / 商誉 / FCFE / 客户集中度上的巨大差异。
3. **风险章节用"宏观不确定性"等通用词搪塞**——不写清楚"下一轮回调时谁先被重定价"。

v2.0 在这三条之上再加一条:

4. **写成"静态观点表",而不是"可更新工作底板"**——每次都要重写散文,无法跨板块迁移。v2.0 用 **12 列母表**解决这一条。

## 二、触发条件

| 场景 | 触发 |
|------|------|
| **手动** | `/chain-map {CHAIN_NAME}`(例 `/chain-map AI` / `/chain-map EV` / `/chain-map Obesity`) |
| **跨报告复盘** | 完成 ≥5 家同行业独立公司报告后,自动建议触发,把个股视角升级到链条视角 |
| **行业切换期** | 当一个行业出现"主题转折 / 资金轮动 / 信用弱点暴露"三者任一时,触发链条层面重绘 |

**不触发场景**:
- 单一公司分析(用 Tier 1-3 公司分析 skill)
- 子链分析(用各自专用 skill,例 `moat-evaluator`、`valuation-builder`)

## 三、v2.0 顶层架构:四层系统图(取代 v1.0 的"三层结构")

v2.0 的核心升级是**不再把产业链画成"谁在链上"的横向清单**,而是分成四层系统:

| 层 | 回答什么问题 | 内容 |
|---|---|---|
| **结构层** | 系统里到底有什么 | 预算源 / 物理主链 / 部署扩散链 / 回流商业化层 的**稀缺事物**(不是板块名) |
| **约束层** | 什么在控制这张图 | 预算约束 / 物理供给约束 / 部署约束 / 利润留存约束 / 区域角色约束 |
| **时钟层** | 谁先兑现谁后兑现 | 预算 / 设计与资格导入 / 制造扩产 / 交付 / 上电与热管理 / 商业化回流 / 现金兑现 / 市场认知 八个时钟 |
| **定价层** | 现在该拿哪一块 | 结构性溢价 vs 主题溢价 / 利润中心 vs 放大量 / 供给弹性 / 财务弹性 / 核心或交易 / 四分法 |

**串联关系(不是并列标签)**:

```
结构层("里面有什么") → 约束层("什么卡住它") → 时钟层("什么时候兑现") → 定价层("现在该拿哪一块")
```

**丢一层就退化**:
- 只有结构层 = 名单
- 结构 + 约束 = 静态评分
- 结构 + 约束 + 时钟 = 缺价格纪律
- 四层齐全 = 真正能指导研究、排序和仓位的运行地图

## 四、v2.0 的四个核心修正(指针,贯穿全报告)

写每一章之前,必须先用这四条校准方向,否则会悄悄退回旧的清单式产业链:

### 修正 1:从"模块图"改成"事物图"

不再只写板块名(GPU / HBM / 封装 / 设备 / 服务器 / 光模块),而是写它们代表的**真正稀缺事物**:预算 / 算力 / 内存带宽能力 / 先进制造与封装整合能力 / 上电能力 / 配电与保护能力 / 热管理能力 / 板级高速互连能力 / 已知良品筛选能力。

### 修正 2:从"受益关系"改成"作用关系"

不再只问"谁受益于 X",而是追问:谁**转化**预算、谁**组织供给**、谁**负责部署**、谁**形成约束**、谁**形成回流**。

### 修正 3:从"静态层级"改成"动态多钟"

不再把所有受益股当同一轮行情同时兑现,而是用八个时钟分别定位。**经营兑现时钟**和**市场定价时钟**必须分开看——"基本面没错,但价格已经走太远"只有两个时钟分开才能看见。

### 修正 4:从"谁重要"改成"谁值得研究 / 值得拿 / 只适合交易"

最接近投资动作的一步。**重要 ≠ 最适合买**。四个动作层:
- 结构核心 + 高质量利润池 → 核心跟踪 / 回调优先看
- 长周期基础设施承接层 → 中期研究 / 优先深挖
- 重要但利润浅的配套层 → 选择性跟踪 / 研究观察
- 高 beta 高拥挤交易层 → 交易观察 / 不做默认核心池

## 五、v2.0 硬产出:12 列母表

**这是 v2.0 最重要的落地物**。母表不是静态观点表,而是可反复更新的工作底板。跨板块切换时,只需换数据,不换结构。

### 5.1 母表字段定义(8 核心 + 3 辅助 = 12 列,固定不再改)

#### A. 8 个核心字段(判断结构)

| 字段 | 定义 | 填写要求 | 最常见误填 |
|---|---|---|---|
| **事物节点** | 模块提供的"稀缺事物" | 写能力 / 容量 / 接口 / 供给,不写板块名 | 把"光模块""PCB""服务器"当最终答案 |
| **约束节点** | 当前决定能否扩、能否赚、能否兑现的主约束 | 只写 1-2 个最硬约束 | 把所有利空都堆上去 |
| **时钟位置** | 处在早段 / 前中段 / 中段 / 中后段 / 后段 | **必须同时写"经营兑现位置"和"市场定价位置"** | 只写景气不写预期位置 |
| **利润池深度** | 最终能留在公司与股东手里的利润深浅 | "很深 / 深 / 中深 / 中 / 中浅 / 浅" | 把收入弹性当利润深度 |
| **供给弹性** | 需求上来时供给多久能补上 | "低 / 中低 / 中 / 中高 / 高" | 把重要性误当成低供给弹性 |
| **财务弹性** | 代表公司整体是高现金/高 FCF/低杠杆还是相反 | "强 / 中强 / 中 / 中弱 / 弱" | 只看 PE,不看现金转换和杠杆 |
| **当前估值状态** | 低估 / 合理 / 拥挤 / 过热 / 重要性高于热度 | **必须写成完整判断句**,不写"贵/便宜" | 单字评级 |
| **适合动作** | 核心跟踪 / 优先深挖 / 选择性跟踪 / 交易观察 / 回避 | **用仓位动作语言,不用研究态度语言** | 写成"看好/不看好" |

#### B. 3 个辅助字段(强制保留,否则母表会退回"静态观点表")

| 字段 | 作用 |
|---|---|
| **代表公司** | 让模块落到股票池 |
| **关键跟踪变量** | 让母表和现实世界保持联动 |
| **失效触发** | 让排序能被及时重排 |

### 5.2 母表填写纪律(5 条,强制)

1. **先填"事物节点",再填其他列** — 后七列都依赖第一列。"光模块"不是事物节点,"高速光连接能力"才是。
2. **"约束节点"只写最硬的 1-2 个** — 写真正会改变排序的约束,不是风险清单。
3. **"时钟位置"必须写两个时钟** — 经营兑现时钟 + 市场定价时钟分开写。
4. **"利润池深度"要和"重要性"分开** — 服务器、ODM、PCB、测试链都可能很重要,但利润池未必深。
5. **"适合动作"写仓位动作,不写研究态度** — 核心跟踪 / 优先深挖 / 选择性跟踪 / 交易观察 / 回调优先看 / 回调先回避。

### 5.3 母表使用手册

**A. 它首先不是股票池,而是"模块排序器"** — 把"真核心 / 扩散层 / 重要但利润浅 / 高 beta 交易层 / 最怕信用收缩"的判断**固定下来**。

**B. 每次更新只检查 3 列**:约束节点 / 时钟位置 / 当前估值状态。其他列通常会跟着变。

**C. 触发整表重排的是结构变量变化,不是股价** — 每份报告必须给出 ≥5 条"失效触发信号"映射表(哪个信号触发哪一列重写)。

**D. 8 问工作法**(打开母表时按这个顺序问):

1. 真正提供的稀缺事物是什么
2. 当前最硬的约束是什么
3. 处在哪个兑现时钟上(经营 vs 定价)
4. 利润最终能不能留在股东手里
5. 供给会不会很快补上
6. 资产负债表能不能穿过错配
7. 市场是低估、合理、拥挤还是过热
8. 现阶段最适合的动作是什么

8 问答完,模块排序基本不跑偏。

### 5.4 母表规模要求

- 行数 = **每个独立"事物节点"一行**(AI 链典型 13-15 行,EV / 航空等 8-12 行)
- 每行 12 列必须全部填写,不允许留白
- 附一张空白模板(供以后板块切换)

## 六、六部分收敛结构(v1.0 骨架,v2.0 保留并映射到四层)

这是产业链报告的**叙事骨架**。21 个分析角度分配到 6 个部分,**每个部分对应四层系统图的某一层(或多层)**:

| 部分 | 名字 | 核心任务 | 对应四层 | 对应章节 |
|------|------|---------|--------|---------|
| **A. 地图** | 谁在哪 | 四层结构 + 玩家数 + 市值分档 | **结构层** | Ch 1-3 |
| **B. 尺子** | 怎么判 | 四把尺子 + 分层估值 + 离散度 + SBC 幻觉 | **约束层 + 定价层** | Ch 4-7 |
| **C. 时间** | 什么时候 | 订单瀑布 + 利润归属 + CapEx 分配 | **时钟层** | Ch 8-10 |

## 七、21 个分析角度(v1.0 保留,映射到四层)

### Part A: 结构层(3 角度)

#### 角度 1:四层结构 + 信用弱点第四层

把产业链画成三层**物理/商业/经济**结构,再叠加第四层**信用弱点**(横跨前三层)。

| 层级 | 含义 | AI 链示例 | 通用模板 |
|------|------|----------|---------|
| L1 物理瓶颈层 | 决定"够不够"的核心环节 | GPU / HBM / 先进制程 / EUV | 行业核心不可替代环节 |
| L2 扩散层 | 决定"能不能交付"的执行环节 | 光模块 / PCB / 配电 / 服务器 | 围绕核心的关键配套 |
| L3 外围商业化层 | 决定"变成钱"的最终通路 | SaaS / 公用事业 / REIT | 终端收入承接者 |
| L4 信用弱点层 | 横跨前三层,下轮去杠杆时先被重定价 | ORCL / LITE / HPE | 满足 ≥2 条:净债/EBITDA>5x、FCFE 转负、CapEx/Rev>40%、Current Ratio<1、Goodwill/Assets>50%、单一客户>30% |

**强制**: L4 必须单独显式化,不能隐性埋藏在风险章里。

#### 角度 2:每层玩家数量 + 定价权趋势

对每个节点列:玩家数量(1 家垄断 / 2-3 家寡头 / 4-6 家分化 / >6 家充分竞争)+ 定价权趋势(过去 2 年增强 ↑ / 稳定 → / 削弱 ↓)。

#### 角度 3:按市值分档扫描

大盘>$500B(信用强,回调是避险)/ 中大盘$100-500B(估值分化最明显)/ 中盘$10-100B(基本面 vs 估值差异最大)/ 小盘<$10B(质量异类 vs 高流动性风险)。

---

### Part B: 约束层 + 定价层(4 角度)

#### 角度 4:四把尺子(核心判断框架)

任何公司都必须同时通过四把尺子才能进入"核心池":

1. **节点不可替代性**(护城河):3 级——最不可替代 / 高但非垄断 / 易被补
2. **利润留存能力**(定价权):毛利率稳定性 < 5pp 波动;ROIC > WACC + 5pp;SBC/Rev < 10%
3. **资本开支回报可测性**:ROI 是否被 guidance 过 / CapEx 和收入的先后顺序 / 是否分开披露"增长性"与"维持性"
4. **衰退/回调中的信用弹性**:净债/EBITDA<3x、Current Ratio>1.5、FCFE>0

**强制**: 报告必须列出"四把尺子同时通过的名单"(通常只有 5-10 家)。

#### 角度 5:分层估值尺子

| 子链类型 | 不该只看什么 | 应该同时看 |
|---------|-------------|-----------|
| 核心垄断节点 | PE | PE + 毛利稳定性 + FCF + ROIC |
| 周期内存/原料 | Forward PE | 跨周期利润 + EV/EBITDA + 供给曲线 |
| 重资产代工/生产 | PE | PE + EV/EBIT + CapEx intensity + FCF |
| 关键设备 | 收入增速 | PE + ROIC + 订单质量(backlog + book-to-bill) |
| 高客户集中度零部件 | 收入和 PE | EV/EBITDA + 净债 + 客户集中 + ASP 趋势 |
| 组装/集成 | PE | EV/EBITDA + 营运资本 + 净债 + 现金转换 |
| 重并购成长 | PE | PE + backlog + book-to-bill + FCF + 商誉占比 |
| 软件订阅 | PE | FCF + usage(非 seat) + workflow 迁移证据 |

#### 角度 6:估值离散度诚实性测试

对核心公司同时用 4 种方法(DCF / EV/EBITDA / P/FCF / 相对估值),计算离散度 = (最高 - 最低) / 均值。<15% 质量可信 / 15-30% 合理 / 30-50% 警告 / >50% 极高。

#### 角度 7:SBC 稀释量化(Owner PE 幻觉倍数)

对 SBC/Rev > 5% 的公司,Owner PE = 市值 / (GAAP 净利润 - SBC);幻觉倍数 = Owner PE / Non-GAAP PE。>2.0x 时 Non-GAAP 是永久性光学折扣。

---

### Part C: 时钟层(3 角度)

#### 角度 8:订单瀑布 + 时滞

把"预算决定 → 订单 → 收入 → 利润 → 现金"拆成 8 个时点(T+0、T+60d、T+90d、T+180d、T+270d、T+360d、T+540d、T+720d),每个时点标出受益公司。

#### 角度 9:利润最终归属五层

区分"谁拿收入"和"谁拿利润":预算决定层 → 收入承接层 → 毛利承接层 → 现金流承接层 → 股东回报承接层。

#### 角度 10:CapEx / 总需求分配到供应链的映射

把本轮行业总资本开支(或总 TAM)按百分比分配到各子链。市值隐含份额 > 实际份额 2 倍 = 身份溢价型贵。

**v2.0 补充:八个时钟全景表**

必须在 Part C 显式呈现 8 个时钟的全景表:预算 / 设计与资格导入 / 制造扩产 / 交付 / 上电与热管理 / 商业化回流 / 现金兑现 / 市场认知。每个时钟给出:当前位置 + 最先信号 + 典型错配案例。

---

### Part D: 约束层 + 定价层(4 角度)

#### 角度 11:信用传导五层瀑布(带监测点)

```
Layer 1(需求决定者)→ Layer 2(核心硬件/材料)→ Layer 3(扩散层)→ Layer 4(配套与执行)→ Layer 5(二级组件)
DPO / lead time 随层数递减
```

5 个监测点任一触发 → 整链重定价:Top 3 CapEx guidance 下修 >10-15% / utilization 低于经济阈值 / DPO 延长 >70 天 / 扩散层 Current Ratio < 1.0 / 信用弱点层净债/EBITDA 新增 >1x。

#### 角度 12:二维象限模型(周期位置 × 信用强弱)

Q1 前中段 × 信用强 = 核心重点研究 / Q2 前中段 × 信用弱 = 交易型 / Q3 中后段 × 信用弱 = 回避 / Q4 中后段 × 信用强 = 核心但贵(回调再进)。

#### 角度 13:三种"贵"

质量型贵(回调 -25%~-40%)/ 题材型贵(-50%~-80%)/ 身份溢价型贵(温水 -25%~-40%)。

#### 角度 14:拥挤度 + 持有人脆弱性

主题 ETF 持仓占比(>20% = 高拥挤)+ 对冲基金多空净仓位 + 长期价值型 vs 高 beta 资金占比。PE > 100x 或涨幅 > +300% 必须标注。

---

### Part E: 时钟层 + 定价层(3 角度)

#### 角度 15:三种宏观情景 + 概率加权

Bull / Base / Bear 三情景:具体触发条件(不是概念)+ 当前概率 + 每家公司涨跌幅 + 按概率加权的期望收益排序。

#### 角度 16:压力测试七场景

最少 7 个:龙头下游增速跌破阈值 / 终端 CapEx guidance 下修 / 利率突变 / 主题 ETF 单月 -15% / 外生事件 / 关键原料单月 -20% / 货币政策转向。

#### 角度 17:混读组分析(≥5 组)

"节点相近但投资逻辑不同"的公司组合,≥5 组。每组展示:为什么容易被混 / 哪个维度完全不同 / 数据表对比 / 投资含义。

---

### Part F: 定价层(5 角度)

#### 角度 18:三池分配(核心 / 研究 / 交易 / 回避)

核心池 = 四把尺子同时过 + Q1 或 Q4;研究池 = 三把尺子过 + 等触发;交易池 = 高 beta / 高拥挤 / 短期窗口;回避池 = L4 信用弱点 + 基本面弱。每家覆盖公司必须定位,不许留白。

#### 角度 19:回调应对(四层操作)

A. 回调优先重看(越跌越值得)B. 需要确认节奏(等 -35~-45% 再入场)C. 只做反弹交易(1% 仓位 + 严格止损)D. 回调时先回避(便宜 ≠ 安全)。

#### 角度 20:跟踪清单(按频率分层)

每日(10 分钟)/ 每周 / 每月 / 每季度(财报季)/ 每年(结构性变量)。每个指标必须标注数据源 + 触发重排序的具体阈值。

#### 角度 21:九个钉子固化(读者带走什么)

正好 9 个,每个 ≤40 字,必含具体公司名或数字,加起来覆盖 Part A-E 每一部分至少一次。1-3 个最意外 / 4-6 个最可操作 / 7-9 个最系统性。

**v2.0 补充:倒数第二章必须并列呈现"九个钉子 + 12 列母表"**。钉子是叙事压缩,母表是结构压缩,两者互补不可替代。

### Step 4.5(v2.0 新增): 构建 12 列母表

产出 `reports/{CHAIN_NAME}/data/module_master_table_{DATE}.md`,含:

1. **12 列定义表**(8 核心 + 3 辅助 + 每列"最常见误填")
2. **5 条填写纪律**
3. **主母表**(每个事物节点一行,12 列全填)
4. **失效触发映射表**(≥5 条信号 → 哪一列重写)
5. **8 问工作法**
6. **空白模板**(供以后板块切换)

母表必须先于 Step 5 开始填——**母表填不完,主报告禁止写**。这是防止 Step 5 退回散文式观点表的硬控制。

### Step 5: 按六部分收敛结构撰写章节

严格按 Part A→B→C→D→E→F,不允许重排。Part A 第一章必须是"总定义:四层系统图"。

### Step 6: 压力测试 + 混读组

三情景每家公司涨跌幅具体数字 ✓ / 7 个压力测试齐全 ✓ / ≥5 组混读组 ✓。

### Step 7: 跟踪清单 + 投资者分型

至少 4 种投资者:长线价值 / 成长 GARP / 主题交易 / 风险厌恶。

### Step 8: 九个钉子写作

倒数第二章。≤40 字 / 必含数字或公司名 / ≥3 个反直觉。

### Step 8.5(v2.0 新增): 四个核心修正 + 8 问回头验证

最终报告完成后,用四个核心修正 + 8 问工作法**逐一反查**:

- 是否写成了模块图而不是事物图?
- 是否只谈受益不谈作用?
- 是否只有一个静态时钟没有拆成多钟?
- 是否只评"重要"没评"值得拿 / 只适合交易"?
- 8 问每一问是否都能从母表某一列直接读出答案?

任一反查失败 → 回到对应章节重写。

### Step 9: 无痕化检查

```bash
grep -cE "v[0-9]+|原报告|修订说明|重写|Phase|Agent|staging|skill" {REPORT}
# 期望: 0
grep -cE "回流|校准|深度研报|本次|Tier [0-9]" {REPORT}
# 期望: 0 或仅限正当用法
```

### Step 10: 交叉一致性检查

母表的"适合动作"列必须和三池分配(角度 18)完全一致;母表的"时钟位置"必须和订单瀑布(角度 8)完全一致;母表的"失效触发"必须覆盖信用传导监测点(角度 11)。

## 十一、反向约束(NEVER,v1.0 10 条 + v2.0 新增 4 条)

1. **NEVER 只列玩家不问"谁拿利润"** — 五层利润归属必跑
2. **NEVER 把节点相近的公司写成"差不多"** — 混读组 ≥5 组
3. **NEVER 用年化代理替代季度口径**
4. **NEVER 跳过 L4 信用弱点层** — 必须独立显式化
5. **NEVER 用单一估值方法** — 核心公司跑 4 种离散度
6. **NEVER 只用 Non-GAAP PE 讨论 SBC/Rev > 5% 的公司**
7. **NEVER 把"宏观不确定性"当风险主段** — 风险按子链写
8. **NEVER 给情景只打"正/中/负"** — 必须具体触发 + 涨跌幅
9. **NEVER 写 >9 或 <9 个钉子** — 正好 9 个,每个 ≤40 字
10. **NEVER 在最终报告暴露过程** — 无痕化硬门控

**v2.0 新增:**

11. **NEVER 跳过 12 列母表** — 母表缺任一列或任一行 = 报告不合格。这是 v2.0 防止退回"散文式观点表"的硬控制。
12. **NEVER 把"重要"写成"最适合买"** — 修正 4 的反向约束。母表"适合动作"列必须使用仓位语言(核心跟踪/研究/交易/回避),不用研究态度语言(看好/不看好)。
13. **NEVER 只写一个时钟** — 修正 3 的反向约束。每个模块的"时钟位置"列必须同时写经营兑现时钟和市场定价时钟。
14. **NEVER 把"事物节点"写成板块名** — 修正 1 的反向约束。"光模块""服务器""PCB"不是事物节点,"高速光连接能力""AI 系统交付与集成能力""板级高速互连能力"才是。

## 十五、v2.0 已知限制 + 下一步

### 已知限制

- 12 列母表在 AI 链上验证,其他行业需二轮验证标定"经营兑现时钟"和"市场定价时钟"的具体阈值
- 八个时钟对快周期(电子 / 半导体)合适,对慢周期(电力 / 航空)可能只需 5-6 个时钟
- 失效触发映射表的"≥5 条"是硬下限,小链条可降到 3 条,需说明原因

### 下一步(v2.1 或 v3.0 方向)

1. **模块打分版**:给 12 列每列一套 1-5 分量化规则,让模块排序可以直接按分数跑。
2. **跨板块对比**:用同一张 12 列母表对比 AI / EV / 数据中心电力三条链,找出结构位置最相似但时钟错位的组合。
3. **历史回放**:把过去 3 年的母表历史版本对齐,观察哪一列变化最早预示了行情拐点。

---

**一句话定位**: v2.0 把产业链从"谁在链上"(v1.0)升级到"四层系统 × 12 列母表 × 8 问工作法"——结构层回答里面有什么,约束层回答什么卡住它,时钟层回答什么时候兑现,定价层回答现在该拿哪一块。母表是跨板块迁移的共用底板,让每一次产业链分析都累积成长期可复用的研究资产,而不是一次性散文。
