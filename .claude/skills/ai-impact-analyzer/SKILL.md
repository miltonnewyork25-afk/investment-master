# AI冲击分析器 v1.0 (AI Impact Analyzer)

> **定位**: 系统化评估AI对目标公司的正面/负面影响，产出可直接融入报告。
> **适用**: 所有Tier 2+公司(不只是科技公司——AI可能影响任何行业)
> **核心理念**: AI对每家公司的影响不是"有/无"的二元判断，而是一个**净效应向量**——方向(利好/利空)+幅度(小/大)+时间(近/远)+确定性(高/低)
> **源自**: CRM/ADBE/INTU/PTC/NVDA/MSFT/GOOGL/DDOG 8份报告实战提炼的6种AI影响模式

---

## 触发条件

| 场景 | 触发 |
|------|------|
| **自动(Tier 3)** | Phase 1写AI/技术相关章节时 |
| **手动** | `/ai-impact {TICKER}` |
| **跳过条件** | C7=5(永续型)且C1来自制度/合同/物理 → AI大概率无关 → 快速标注"AI无关"即可 |

## Step 1: AI影响模式分类

先判断目标公司属于哪种AI影响模式(可能多种叠加):

### 6种模式 (从40+份报告提炼)

| 模式 | 核心机制 | 方向 | 典型公司 | 识别信号 |
|------|---------|:----:|---------|---------|
| **M1: AI蚕食核心** | AI让客户自助→减少per-seat/per-query需求 | 🔴利空 | CRM, ADBE, INTU | "AI可能替代我们的核心产品" |
| **M2: AI加深护城河** | 独占数据+AI=护城河自增强 | 🟢利好 | DDOG, GOOGL, META, FICO | "我们的数据是AI训练的独占燃料" |
| **M3: AI军备赛** | AI投入吃利润，回报待验证 | 🟡中性偏空 | MSFT, GOOGL, AMZN | CapEx激增+AI收入占比<10% |
| **M4: AI卖铲人** | 提供AI基础设施，直接受益 | 🟢利好 | NVDA, AVGO, ANET, VRT | 收入>30%来自AI相关 |
| **M5: AI渐进增强** | AI是提价理由/效率工具，非独立收入 | 🟡中性偏好 | PTC, INTU(GenOS), SaaS | "AI功能嵌入现有产品" |
| **M6: AI无关** | 护城河来自制度/物理/合同，AI绕不过 | ⚪无影响 | CPRT, VRSN, CME, IHG | C7=5且C1=制度/独占/物理 |

**多模式叠加**: 多数公司不是纯粹的单一模式。例如:
- INTU = M1(AI替代报税) + M5(GenOS增强QB) → 净效应取决于哪个更快
- MSFT = M2(Azure数据) + M3(CapEx军备赛) → 短期利空长期利好
- GOOGL = M2(搜索数据) + M3(Gemini投入) + M1(AI搜索可能蚕食广告点击) → 三力交汇

### 判定方法

对目标公司逐一检查6个模式的适用性(Yes/No/部分):

```markdown
| 模式 | 适用? | 证据 | 影响方向 | 影响幅度(1-5) |
|------|:----:|------|:-------:|:-----------:|
| M1蚕食核心 | | | | |
| M2加深护城河 | | | | |
| M3军备赛 | | | | |
| M4卖铲人 | | | | |
| M5渐进增强 | | | | |
| M6无关 | | | | |
```

## Step 2: AI影响四维量化

对每个适用的模式，量化4个维度:

### 维度1: 方向 — AI对这家公司是利好还是利空?

```
净方向 = Σ(模式i × 幅度i × 概率i)

正面因素: 效率提升/新收入/提价理由/护城河加深/TAM扩展
负面因素: 核心产品被替代/利润被投入吃掉/竞争者AI更强/定价权被削弱

净方向 > 0 → AI利好
净方向 < 0 → AI利空
|净方向| < 0.5 → 影响不大
```

### 维度2: 幅度 — 影响有多大?

| 等级 | 对收入的影响 | 对估值的影响 | 代表 |
|:----:|-----------|-----------|------|
| 5(革命性) | 收入±50%+ | PE±50%+ | NVDA(从$27B→$216B) |
| 4(重大) | 收入±20-50% | PE±20-40% | CRM(Agent→seat蚕食) |
| 3(显著) | 收入±10-20% | PE±10-20% | ADBE(Canva/AI生成) |
| 2(温和) | 收入±5-10% | PE±5-10% | PTC(AI提价$50-100M) |
| 1(边际) | 收入±<5% | PE±<5% | CPRT(AI优化拍卖算法) |

### 维度3: 时间 — 影响什么时候到?

| 时间窗口 | 定义 | 估值影响方式 |
|---------|------|-----------|
| 近期(1-2年) | 已有产品/已见收入 | 直接进入DCF近期预测 |
| 中期(3-5年) | 产品开发中/客户试用 | 进入DCF中期+情景概率 |
| 远期(5-10年) | 技术趋势推演 | 仅影响终端价值假设 |
| 不确定 | 无法判断时间 | 作为期权/风险标注，不进基础估值 |

### 维度4: 确定性 — 我们有多确信?

| 确定性 | 依据 | 处理方式 |
|:------:|------|---------|
| 高(>70%) | 已有财务数据验证 | 直接进入估值 |
| 中(40-70%) | 有产品但缺收入验证 | 进入概率加权情景 |
| 低(<40%) | 纯逻辑推演 | 仅标注为风险/期权，不进基础估值 |

## Step 3: AI影响→估值映射

将Step 1-2的结论转化为对估值的具体调整:

### 3a. AI对增长的影响

```
收入增速调整 = Σ(AI收入增量 - AI蚕食损失) / 当前收入
```

| 影响路径 | 加减 | 量化方法 |
|---------|:----:|---------|
| AI新产品收入 | + | 产品定价×目标客户数×渗透率 |
| AI提价增量 | + | 提价幅度×受影响ARR |
| AI效率节省 | + | 减员×人均成本 或 自动化率×流程成本 |
| 核心产品蚕食 | - | 蚕食率×核心ARR×迁移速度 |
| AI竞品份额损失 | - | 竞品渗透率×目标市场×你的份额 |

### 3b. AI对利润率的影响

```
OPM调整 = AI收入利润率贡献 - AI投入成本 - AI人才成本
```

### 3c. AI对护城河的影响(→CQI调整)

| AI影响 | CQI因子调整 |
|--------|-----------|
| AI加深数据壁垒 | C4数据飞轮↑ + C7自维持性↑ |
| AI替代人力锁定 | C3锁定载体从"人力"→"系统" = 更持久 |
| AI降低进入壁垒 | C1/C5↓(新进入者也能用AI) |
| AI创造新网络效应 | C2↑(用户越多AI越准→更多用户) |

### 3d. AI对风险的影响(→Kill Switch)

必须为每个AI影响路径定义KS:

```
KS-AI-1: [AI蚕食] 核心产品ARR同比增速 < X% 连续2Q
KS-AI-2: [AI军备赛] AI CapEx/Rev > X% 且AI收入占比 < Y%
KS-AI-3: [AI竞争] 竞品AI产品NPS > 本公司AI产品NPS
```

### 产出格式(直接可融入报告)

```markdown
### AI影响评估

**AI影响模式**: M2(数据加深)+M5(渐进增强) — 净效应中等利好
**净方向**: +0.7(利好为主, M2贡献+1.2, M5贡献+0.5, 无M1蚕食风险)
**幅度**: 2(温和) — AI增量约$X/年, 占收入Y%
**时间**: 中期(3-5年) — 产品已上线但收入验证需2-3年
**确定性**: 中(55%) — 有产品数据但缺规模化验证

**对估值的影响**:
- 收入增速: +1-2pp(AI提价+新客户场景)
- OPM: +50-100bps(AI自动化降低运营成本)
- 护城河: C4+0.5(数据飞轮加深), C7不变
- 风险: KS-AI-1/AI-2/AI-3定义 [DM-AI-xxx]

**简言之**: AI是顺风不是飓风——增强现有护城河但不改变估值量级。
```

## 飞轮悖论专项检测(M1模式深化)

> M1是最危险的模式——因为它看起来像M5(好事)但实际是蚕食

**检测触发**: 公司宣称"AI增强产品"或"AI agent"时，必须检查:

```
问题: 如果AI功能100%成功(客户100%采用)，核心产品的收入会增加还是减少?

CRM: Agent 100%成功→企业不再需要那么多Salesforce seat→收入减少
ADBE: AI生成100%成功→用户不需要Photoshop技能→Creative Cloud降级
INTU: GenOS 100%自动→用户不需要TurboTax Live→高端收入消失

如果答案是"减少" → M1确认 → 必须量化蚕食率
```

**蚕食率公式**(继承moat-evaluator):
```
蚕食率 = AI成功后核心产品收入流失 / AI功能带来的增量收入
< 0.3 → 安全(AI净增量)
0.3-0.7 → 警告(部分蚕食)
> 0.7 → 危险(AI主要是替代不是增量)
```

## 行业模板

| 行业 | 默认模式 | 优先检查 | 典型AI影响路径 |
|------|---------|---------|-------------|
| **SaaS** | M1+M5 | 飞轮悖论(Agent蚕食seat?) | per-seat→per-outcome转型 |
| **科技平台** | M2+M3 | 军备赛ROI(CapEx vs AI收入) | 数据加深+投入吃利润 |
| **半导体** | M4 | 每代洗牌风险(CUDA→TPU?) | 卖铲人但铲子可能换代 |
| **消费品** | M6(多数) | AI营销效率(DTC提升?) | 边际效率改善,非革命 |
| **金融** | M5+M2 | AI风控增强 vs 监管限制 | 数据优势但应用受监管 |
| **工业** | M5 | AI是提价理由 vs 真实价值 | 渐进增强,5-10年窗口 |
| **医疗** | M2+M1 | 诊断AI增强 vs 医生被替代 | 数据独占但监管审批慢 |
