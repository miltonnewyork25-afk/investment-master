# 演绎动态推理 v1.0

> **核心命题**: 历史类比在渐变趋势中有效，但在结构性非线性面前系统性失效。AI生态和半导体行业正经历至少3个没有历史先例的非线性变量——Agent经济的token乘数、推理/训练比反转、自定义芯片对通用GPU的替代。本Skill为这些"无法类比"的变量提供第一性原理的演绎推理框架。
> **与类比的关系**: 互补，不替代。类比回答"过去怎样"，演绎回答"如果前提成立则未来怎样"。两条链在报告中并行呈现，由读者判断哪条更可信。

## 触发条件

1. **行业触发**: 分析对象属于AI生态(AMZN/MSFT/GOOG/META)或半导体(NVDA/AMD/TSM/ASML)
2. **变量触发**: 分析中涉及以下任一主题:
   - CapEx/算力需求预测
   - 云计算增速/份额预测
   - AI变现时间表/商业化路径
   - 芯片需求/TAM预测
   - 推理vs训练计算比
3. **手动触发**: 用户说"演绎分析"/"第一性原理"/"deductive"

## Part A: 演绎链构建方法论

### A.1 什么是演绎链

```
类比: "过去5年AWS增速CAGR 25% → 未来5年可能15-20%"
      ↑ 锚定于历史数据，外推趋势

演绎: "前提1: Agent任务消耗100x tokens
       前提2: Agent渗透率未来3年从1%→20%
       前提3: 每用户日均Agent调用从0.1→3次
       → 推论: 推理token需求将增长 100×20×30 = 60,000x(理论上限)
       → 约束: 基础设施建设速度、成本下降曲线、替代方案
       → 修正后推论: 实际推理需求增长10-50x(3年)"
      ↑ 锚定于因果逻辑，构建可证伪的推理链
```

### A.2 演绎链的四要素

每条演绎链必须包含:

1. **前提集(Premises)** — 明确列出所有假设前提，标注确定性等级
2. **推导步骤(Deduction)** — 每一步的逻辑推导，显式标注
3. **约束条件(Constraints)** — 限制推论的现实因素
4. **证伪条件(Falsifiable)** — 什么数据能否定这条链

### A.3 演绎链的DM锚点标注

```markdown
### DM-DED-001
- **类型**: D (演绎推理, 区别于H/R/S)
- **链**: [前提1] + [前提2] + [前提3] → [推论]
- **前提确定性**: P1(高) / P2(中) / P3(低)
- **链强度**: 强(每步逻辑必然) / 中(每步逻辑合理) / 弱(含跳跃)
- **证伪条件**: "若2026Q4推理token增速<5x YoY,则此链失效"
- **与类比链的关系**: 补充/替代/矛盾
```

**D型锚点**是本Skill新增的第四种锚点类型，专用于演绎推理。与H(硬数据)/R(合理推断)/S(主观判断)并列。

## Part B: AI生态/半导体的核心演绎链库

> 以下是经过初步推导的演绎链模板。分析具体公司时，需要用该公司的实际数据填充前提。

### 演绎链 #1: Agent经济的Token乘数效应

**适用**: AMZN(AWS)/MSFT(Azure)/GOOG(GCP)/半导体全部

```markdown
前提P1 [高确定性]: 单次传统API调用消耗 ~0.5-2K tokens
前提P2 [高确定性]: 单次Agent任务消耗 ~50K-2M tokens (100-1000x)
前提P3 [中确定性]: Agent-calls-Agent架构产生 N×M 乘数 (如3个并行Agent各调用2个子Agent = 6x)
前提P4 [低确定性]: Enterprise Agent渗透率 FY2026 ~5% → FY2028 ~25-40%
前提P5 [低确定性]: Consumer Agent渗透率 FY2026 ~1% → FY2028 ~10-20%

推导:
  Step 1: 人均日token消耗 = 基础chat + Agent任务
         FY2025: ~5K (几乎全是chat)
         FY2028E: ~5K(chat) + 200K(Agent) = ~205K/天 (41x增长)
  Step 2: 总推理token需求 = 人均消耗 × 活跃用户 × Agent渗透率
         FY2025: 5K × 100M = 500T tokens/天
         FY2028E: 205K × 300M × 30% = 18,450T tokens/天 (37x)
  Step 3: 推理算力需求(FLOPS) ≈ tokens × model_size × overhead
         随模型效率提升(量化/蒸馏), 每token FLOPS下降~50%/年
         净推理算力需求增速: 37x × 0.5^3 ≈ 4.6x (3年)

约束:
  C1: 基础设施建设周期 (数据中心18-24个月)→供给跟不上需求=价格上升
  C2: 成本曲线 — 推理成本下降使更多场景经济可行(正反馈)
  C3: 替代架构 — 本地推理(端侧AI)分流云推理需求
  C4: 监管 — AI使用政策可能限制Agent自动化

修正后推论:
  云推理收入增速: FY2025-2028 CAGR 35-50% (vs 类比锚点 ~20-25%)
  不确定性区间: 极宽 (20%-80% CAGR均可能)

证伪条件:
  - FY2026Q4 推理API调用量增速 <3x YoY → 链失效
  - Agent DAU/MAU比 <5% → 渗透率前提P4/P5过高
  - 推理成本未下降 → C2正反馈未触发

与类比链的关系: 矛盾
  类比: AWS增速从25%→15% (减速趋势)
  演绎: Agent经济可能使增速从25%→35%+ (再加速)
  → 两条链指向相反方向, 这是分析的最大不确定性来源
```

### 演绎链 #2: 推理/训练比反转

**适用**: NVDA/AMD/TSM/ASML/自定义芯片(Trainium/TPU)

```markdown
前提P1 [高确定性]: FY2024-2025 AI CapEx主导用途 = 训练大模型 (~70%训练/30%推理)
前提P2 [中确定性]: 训练需求增速将减速 (模型规模scaling law边际递减, 训练效率提升)
前提P3 [中确定性]: Agent经济使推理需求增速远超训练需求 (演绎链#1)
前提P4 [低确定性]: 推理最优硬件 ≠ 训练最优硬件 (推理重吞吐/延迟, 训练重内存/互联)

推导:
  Step 1: 训练/推理比将从70:30翻转至30:70 (FY2027-2028)
  Step 2: 推理硬件需求特性: 高吞吐、低延迟、能效比优先
         → 有利于: 推理专用芯片(Groq/Cerebras/Trainium2)、定制ASIC
         → 不利于: 通用GPU(NVDA H100/B100在推理效率上并非最优)
  Step 3: NVDA的护城河从"训练无替代"变为"推理可替代"
         → NVDA份额可能从90%+降至60-70% (推理市场)
  Step 4: 自定义芯片(AWS Trainium/Google TPU/Meta MTIA)份额上升
         → AWS CapEx中自定义芯片占比可能从~10%→30-40%

约束:
  C1: CUDA生态锁定 — 迁移成本高, 软件惯性大
  C2: NVDA迭代速度 — 可能推出推理优化产品线(Blackwell推理版)
  C3: 自定义芯片的可靠性/成熟度 — 企业客户保守

证伪条件:
  - NVDA FY2027推理收入占比仍<40% → 比反转未发生
  - 自定义芯片在MLPerf推理基准上未超越NVDA → P4前提不成立
  - Agent经济增速低于预期 → 推理需求驱动力不足

投资含义:
  - 对NVDA: 类比(历史份额稳定)→乐观 vs 演绎(推理可替代)→审慎
  - 对TSM: 无论谁赢推理芯片战争, TSM都是制造商→中性偏积极
  - 对AWS: 自定义芯片成功→CapEx ROIC改善(自有芯片成本更低)
```

### 演绎链 #3: CapEx回收路径突变

**适用**: AMZN/MSFT/GOOG(巨头CapEx评估)

```markdown
前提P1 [高确定性]: 当前市场共识的CapEx回收模型 = "卖云计算订阅"
前提P2 [中确定性]: Agent经济创造新的变现模式 = "按任务/按结果收费"
前提P3 [低确定性]: 按任务收费的单价远高于按token收费 (价值捕获上移)

推导:
  Step 1: 传统模型: CapEx → GPU小时 → 按token/按小时收费 → ROIC ~8-12%
  Step 2: Agent模型: CapEx → Agent基础设施 → 按任务完成收费 → ROIC ~15-25%?
  Step 3: 差异来源: Agent完成的"任务"价值($50-500/任务) >> 原始算力成本($0.5-5/任务)
         → 平台抽取的价值比 = 任务价值 / 算力成本 = 10-100x markup
  Step 4: 但前提是平台能capture这个markup(竞争可能压缩)

约束:
  C1: 竞争压缩 — 多家云厂商+开源Agent框架→margin pressure
  C2: 客户自建 — 大企业可能自建Agent infra而非购买云服务
  C3: 定价模型不确定 — 按任务vs按token vs包月, 市场尚未收敛

证伪条件:
  - FY2027 Agent相关收入占云收入<10% → 变现模式未成立
  - Agent定价持续按token而非按任务 → P3前提不成立, markup不存在

与CQ的关系:
  - 直接影响CQ1(CapEx ROIC): 如果演绎链成立, ROIC可能高于类比预期
  - 但不确定性也更大: 演绎链的前提P3确定性低
```

### 演绎链 #4: 推理成本下降的二阶效应

**适用**: 全部AI生态/半导体

```markdown
前提P1 [高确定性]: 推理成本正以 ~70%/年 速度下降 (Jevons悖论前提)
前提P2 [中确定性]: 成本下降使原本不经济的AI应用变得可行
前提P3 [中确定性]: 新应用创造新需求, 总消耗反而增加 (Jevons悖论)

推导:
  Step 1: 当前推理成本: ~$10/M tokens (GPT-4级)
  Step 2: FY2028E推理成本: ~$0.1/M tokens (100x下降)
  Step 3: 在$0.1/M tokens下, 可经济运行的场景:
         - 每封邮件AI审阅 ($0.001/封)
         - 每次搜索Agent增强 ($0.01/次)
         - 每行代码实时审查 ($0.0001/行)
         - 实时对话翻译 ($0.01/分钟)
  Step 4: 这些场景的总token消耗: 当前的1000-10000x
  Step 5: 净效应: 成本下降100x × 需求增长1000x = 总支出增长10x

约束:
  C1: Jevons悖论不总是成立 — 需要需求弹性>1
  C2: 并非所有潜在场景都会实现
  C3: 非AI替代方案可能更经济(简单规则引擎 vs LLM)

证伪条件:
  - 推理成本下降但总推理支出不增反降 → Jevons不成立
  - 企业AI预算增速<15% YoY → 需求弹性不足

投资含义:
  - 推理成本下降对GPU厂商(NVDA)是双刃剑: 每GPU收入下降但需求量上升
  - 对云厂商(AWS/Azure)是净正面: 更多workload迁移到云
  - 对TSM是纯利好: 无论成本如何变化, 芯片数量需求只增不减
```

## Part C: 在报告中的呈现方式

### C.1 章节集成

演绎链不单独成章，而是嵌入现有章节作为**对比视角**:

```markdown
### 7.3.2 CapEx回收: 类比 vs 演绎

**类比视角** (基于历史CapEx周期):
科技巨头CapEx周期的历史成功率>60%...
→ 隐含ROIC: 8-12% (与WACC接近)

**演绎视角** (基于Agent经济第一性原理) [DM-DED-003]:
前提: Agent任务消耗100x tokens + 渗透率5%→25% + 按任务收费markup 10-100x
→ 推论: 如果Agent变现模式成立, ROIC可能达15-25%
→ 但前提P3(按任务收费)确定性低, 且竞争可能压缩markup

**两条链的张力**:
类比→ROIC勉强覆盖WACC(CQ1置信度42%)
演绎→ROIC可能显著高于WACC, 但前提不确定性极大
→ 这一张力本身就是CQ1低置信度的根本原因:
   我们既不能用历史证明$200B会成功, 也不能用逻辑排除它成功的可能性。
```

### C.2 演绎链汇总表

在Phase 5综合章节中增加:

```markdown
### 演绎动态分析汇总

| # | 演绎链 | 核心推论 | 前提最弱环 | vs类比 | CQ影响 |
|---|--------|---------|-----------|--------|--------|
| DED-1 | Token乘数 | 推理需求3年4.6-37x | Agent渗透率(P4/P5) | 矛盾(类比减速vs演绎加速) | CQ1↑ CQ2↓ |
| DED-2 | 推理/训练反转 | NVDA份额→60-70% | 推理硬件差异化(P4) | 矛盾(类比份额稳vs演绎可替代) | CQ7↑ |
| DED-3 | CapEx回收突变 | Agent变现ROIC 15-25% | 按任务收费markup(P3) | 补充(新回收路径) | CQ1↑↑ |
| DED-4 | Jevons效应 | 总推理支出增10x | 需求弹性>1(P2) | 补充(成本降≠支出降) | CQ6↓ |

**诚实声明**: 以上演绎链的前提确定性均为"中"或"低"。
它们的价值不在于预测精度,而在于:
(1) 揭示类比框架的盲区
(2) 映射"如果...则..."的条件空间
(3) 提供未来数据的证伪检验点
```

### C.3 确定性标注

演绎链的不确定性必须显式标注:

```
确定性层级:
  H (硬数据)     → 90%+   → "FY2025推理成本$10/M tokens"
  R (合理推断)   → 60-80% → "推理成本下降~70%/年"
  S (主观判断)   → 30-50% → "护城河强度评估"
  D (演绎推理)   → 20-60% → "Agent渗透率25%→推理需求37x"
                             ↑ 链越长,确定性越低
                             ↑ 但逻辑结构比S型更可审查
```

**D型的独特价值**: 虽然确定性可能低于R型，但D型是**可逻辑审查的**——你可以逐步检验每个前提和每步推导，而S型(主观判断)是不可拆解的黑箱。

## Part D: 递归升级机制

### D.1 演绎链的迭代升级

每份报告完成后，演绎链库会根据新数据更新:

```yaml
# knowledge/deductive_chains.yaml
chain_DED_1:
  name: "Agent Token乘数"
  version: 1.0
  created: "2026-02-19 (AMZN)"
  premise_updates:
    # 下次报告时检查:
    - premise: "P4: Agent渗透率"
      check: "搜索 'enterprise AI agent adoption rate 2026'"
      last_checked: "2026-02-19"
      next_check: "下次AI生态/半导体报告"
    - premise: "P2: Agent任务token消耗"
      check: "检查Claude/GPT API pricing变化"
      last_checked: "2026-02-19"
  status: "active"  # active/weakened/falsified
  falsification_log: []
```

### D.2 与递归质量闭环的集成

在`recursive-quality-loop`的第2圈(语义审计)中增加:

```
Agent审计检查项(新增):
- 报告是否包含至少1条演绎链(AI生态/半导体公司)?
- 演绎链是否与类比分析并行呈现(而非替代)?
- 演绎链是否有证伪条件?
- D型DM锚点是否标注了前提确定性?
```

### D.3 跨报告累积

```
AMZN报告 → 演绎链#1(Token乘数), #3(CapEx回收)
  ↓ 下一份NVDA报告
NVDA报告 → 引用AMZN的#1, 新增#2(推理/训练反转)
  ↓ 下一份TSM报告
TSM报告 → 引用NVDA的#2, 新增#4(Jevons), 更新#1(新数据)
  ↓ 交叉验证
→ 4条链构成"AI算力需求演绎网络"
→ 任何一条链的前提被证伪, 影响所有引用它的报告
```

## Part E: 局限性声明(内建于Skill)

### E.1 演绎推理的已知局限

1. **前提脆弱性**: 演绎链的结论只在前提成立时有效。前提越多,链越脆弱。4个"中确定性"前提的联合概率 = 0.7^4 = 24%。
2. **线性推导偏差**: 人(和LLM)倾向于构建线性因果链,忽略非线性交互和意外反馈环。
3. **过度精确化风险**: "37x增长"看起来精确,但实际上是多个模糊前提相乘的结果,精度是虚假的。
4. **确认偏差**: 构建演绎链时,分析师可能无意识地选择支持预设结论的前提。

### E.2 应对措施

| 局限 | 措施 |
|------|------|
| 前提脆弱 | 每个前提独立标注确定性; 计算联合概率 |
| 线性偏差 | 强制要求≥1个"如果反向呢"的替代链 |
| 伪精度 | 数量级思维(10x, 100x)优先于精确数字 |
| 确认偏差 | 演绎链必须与类比链对比; 矛盾时标注张力 |
